# 1.1 `import` / `export`（模块系统）

## 痛点

一个项目有 500 个文件，每个文件都需要用别人的代码。
**怎么"借用"？** Java 用 `import`，前端早期用 `<script>` 标签一个个引入（顺序还会出错）。

ES6 给了正式的模块系统：**谁导出，谁才能被导入。**

## 类比

```java
// Java
package com.ruoyi.utils;
public class AuthUtil { ... }

// 别处
import com.ruoyi.utils.AuthUtil;
```

```javascript
// 前端
export function getToken() { ... }        // 导出

// 别处
import { getToken } from '@/utils/auth'   // 导入
```

## 两种导出方式（必须分清）

### ① 具名导出（named export）

```javascript
// src/utils/auth.js
export function getToken() {
  return Cookies.get('Admin-Token')
}

export function setToken(token) {
  return Cookies.set('Admin-Token', token)
}
```

```javascript
// 别处导入 —— 必须加花括号，名字要对上
import { getToken, setToken } from '@/utils/auth'
```

**类比**：从一个工具箱里**按名字取工具**。

### ② 默认导出（default export）

```javascript
// src/utils/request.js
const service = axios.create({ ... })
export default service        // 一个文件只能有一个默认导出
```

```javascript
// 别处导入 —— 不加花括号，名字随便起
import request from '@/utils/request'      // 叫 request 也行
import http from '@/utils/request'         // 叫 http 也行
```

**类比**：一个文件"主打"的那一个东西，你可以给它起任何名字。

## ⭐ 记法

| 导出写法 | 导入写法 |
|---|---|
| `export function xxx() {}` | `import { xxx } from '...'` ← **有花括号** |
| `export default xxx` | `import 任意名 from '...'` ← **无花括号** |

## 项目里的真实例子

```javascript
// src/store/modules/user.js 第 1 行
import { login, logout, getInfo } from '@/api/login'
//      ↑ 有花括号：因为 api/login.js 里是 export function login(...)

// src/store/modules/user.js 第 2 行
import { getToken, setToken, removeToken } from '@/utils/auth'
```

```javascript
// src/api/login.js 第 1 行
import request from '@/utils/request'
//      ↑ 无花括号：因为 request.js 里是 export default service
```

## ⚠️ 坑 1：花括号漏了会怎样

```javascript
// ❌ 错误
import getToken from '@/utils/auth'
// 结果：getToken 是 undefined，调用时报 "getToken is not a function"

// ✅ 正确
import { getToken } from '@/utils/auth'
```

**原因**：`auth.js` 里没有 `export default`，只有具名导出。

## ⚠️ 坑 2：只有 `import` 没有 `from`

```javascript
// src/main.js 第 23-24 行
import "./assets/icons"      // 没有 from！
import "./permission"        // 没有 from！
```

**这叫「副作用导入」**：只是为了让它**执行一遍**，不取任何东西。

| 写的是什么 | 执行了什么 |
|---|---|
| `import "./permission"` | 执行 `permission.js`，里面有 `router.beforeEach(...)` → **注册了路由守卫** |
| `import "./assets/icons"` | 执行 `icons/index.js`，里面批量注册 svg 图标 |

**⭐ 这是理解项目骨架的关键**：`main.js` 靠这一行"隐式地"把路由守卫接进了应用。

## `@/` 是什么

```javascript
import request from '@/utils/request'
//                 ↑ 这里的 @ 是路径别名
```

**配置在 `vue.config.js`**：

```javascript
configureWebpack: {
  resolve: {
    alias: {
      '@': resolve('src')       // '@' = src 目录的绝对路径
    }
  }
}
```

所以：

| 你写的 | 实际路径 |
|---|---|
| `@/utils/request` | `src/utils/request.js` |
| `@/views/index` | `src/views/index.vue` |
| `./apply.vue` | **同目录下的** `apply.vue`（`./` 是相对路径） |

**类比**：`@` ≈ Java 里的 `classpath:`，都是从"根"开始找。

## 练习 1.1

打开 `src/store/modules/permission.js`，找出它的 import 语句，判断每条**有没有花括号**、**为什么**。

<details>
<summary>点开看答案</summary>

```javascript
import auth from '@/plugins/auth'                                    // 无花括号 → plugins/auth.js 是 export default
import router, { constantRoutes, dynamicRoutes } from '@/router'      // 混合！default + 两个具名
import { getRouters } from '@/api/menu'                              // 有花括号 → 具名导出
import Layout from '@/layout/index'                                  // 无花括号 → layout/index.vue 是 export default
import ParentView from '@/components/ParentView'                     // 无花括号
import InnerLink from '@/layout/components/InnerLink'                // 无花括号
```

**混合写法解释**：`router/index.js` 里既有 `export default new Router(...)`，又有 `export const constantRoutes = [...]`。

所以可以一行同时拿默认导出和具名导出：

```javascript
import router, { constantRoutes, dynamicRoutes } from '@/router'
//     ↑默认        ↑具名1          ↑具名2
```
</details>

# 1.2 `const` / `let`（变量声明）

## 痛点

老 JS 只有一个 `var`，它有两个反直觉的行为：

```javascript
var x = 1
if (true) {
  var x = 2        // ← 会覆盖外面的 x！
}
console.log(x)     // 2（而不是 1）
```

这叫**变量提升**和**函数级作用域**，极易出 bug。

## 解决

ES6 引入两个新关键字，**不要再使用 `var`**：

| 关键字 | 能否重新赋值 | 类比 Java |
|---|---|---|
| `const` | ❌ 不能 | `final` |
| `let` | ✅ 能 | 普通变量 |

```javascript
const token = 'abc'
token = 'def'        // ❌ 报错：Assignment to constant variable

let count = 0
count = 1            // ✅ 可以
```

## ⚠️ 重要细节：`const` 只锁"引用"，不锁"内容"

```javascript
const arr = [1, 2, 3]
arr.push(4)              // ✅ 允许！数组内容变了，但 arr 还是指向同一个数组
arr = [1, 2]             // ❌ 报错：不能重新赋值

const obj = { a: 1 }
obj.a = 2                // ✅ 允许
obj = { a: 3 }           // ❌ 报错
```

**类比 Java**：`final List<String> list = new ArrayList<>();`
→ `list.add("x")` 可以，`list = new ArrayList<>()` 不行。**完全一样。**

## 项目里的实际选择

```javascript
// src/utils/request.js
const service = axios.create({...})     // 不会再变 → const
let downloadLoadingInstance;            // 后面会变 → let

// src/store/modules/user.js
const username = userInfo.username.trim()    // 一次定值 → const
```

**规律：优先用 `const`，需要重新赋值才用 `let`。** 项目里 90% 都是 `const`。

## 练习 1.2

判断下面代码哪里会报错：

```javascript
const config = { timeout: 10000 }
config.timeout = 20000
config = { timeout: 30000 }
```

<details>
<summary>答案</summary>

- 第 2 行 ✅ 允许（改的是对象**内容**）
- 第 3 行 ❌ 报错（试图重新**赋值**这个常量）

**记忆口诀**：`const` 管的是"这个名字不能换指向"，不是"内容不能改"。
</details>

# 1.3 箭头函数 `=>`（Lambda）

## 痛点

以前写回调要写一长串：

```javascript
// 老写法
const users = list.filter(function(user) {
  return user.age > 18
})
```

`function` 太啰嗦，而且 `this` 指向会变（后面讲）。

## 解决：箭头函数

```javascript
// 新写法
const users = list.filter((user) => {
  return user.age > 18
})

// 还能更简（单行 + 直接返回 → 省略 {} 和 return）
const users = list.filter(user => user.age > 18)
```

## 类比 Java

```java
// Java Lambda
list.stream().filter(user -> user.getAge() > 18).collect(...)
```

**几乎一模一样**：

| | Java | JS |
|---|---|---|
| 全写 | `(user) -> { return user.getAge() > 18; }` | `(user) => { return user.age > 18 }` |
| 简写 | `user -> user.getAge() > 18` | `user => user.age > 18` |

## 四种形态（都要认识）

```javascript
// ① 无参数
() => console.log('hi')

// ② 一个参数（括号可省）
x => x * 2

// ③ 多个参数（括号必须有）
(a, b) => a + b

// ④ 函数体多行（花括号 + return 必须有）
(a, b) => {
  const sum = a + b
  return sum * 2
}
```

## ⚠️ 最容易搞错的一点：单行 vs 多行

```javascript
// ✅ 单行：自动 return
x => x * 2                    // 返回 x*2

// ❌ 加了大括号但没写 return → 返回 undefined！
x => { x * 2 }

// ✅ 加了大括号就要写 return
x => { return x * 2 }
```

**这是新手最容易犯的错**：加了 `{}` 忘记 `return`，函数就静默返回 `undefined`。

## ⭐ 第二个关键区别：`this` 的指向

```javascript
// 普通 function：this 由"谁调用"决定
const obj = {
  name: 'Tom',
  say: function() {
    setTimeout(function() {
      console.log(this.name)      // ❌ undefined（this 指向 window）
    }, 100)
  }
}

// 箭头函数：this 继承自外层，**不会被改变**
const obj = {
  name: 'Tom',
  say: function() {
    setTimeout(() => {
      console.log(this.name)      // ✅ 'Tom'（this 还是 obj）
    }, 100)
  }
}
```

**⭐ 一句话记忆**：**箭头函数没有自己的 `this`，它用外层的 `this`。**

这就是为什么项目里到处都用箭头函数——**不会踩 `this` 丢失的坑**。

## 项目里的真实例子

```javascript
// src/store/modules/user.js:18
SET_TOKEN: (state, token) => {
  state.token = token
}
// 多行，有花括号，但不需要 return（因为是赋值，没有返回值要交出去）

// src/store/getters.js:7
token: state => state.token
// 单行，自动返回 state.token

// src/plugins/auth.js:7
return permissions.some(v => {
  return all_permission === v || v === permission
})
// 多行，有 return
```

## 练习 1.3

下面两行有什么区别？

```javascript
const f1 = x => x + 1
const f2 = x => { x + 1 }
```

<details>
<summary>答案</summary>

- `f1(1)` → **2** ✅（单行自动 return）
- `f2(1)` → **undefined** ❌（有 `{}` 但没 `return`）

**这是同一个错误的两种表现**，务必记住：**有 `{}` 就要有 `return`。**
</details>

# 1.4 解构赋值（Destructuring）

## 痛点

从对象/数组里取值，老写法很啰嗦：

```javascript
const user = { name: 'Tom', age: 20, city: '北京' }
const name = user.name
const age = user.age
const city = user.city
```

## 解决：解构

```javascript
const user = { name: 'Tom', age: 20, city: '北京' }
const { name, age, city } = user            // 一行搞定

// 等价于
const name = user.name
const age = user.age
const city = user.city
```

**语义是"按名字取值"** —— 名字必须和对象的属性名一致。

## 类比

Java 没有直接对应。最接近的是：

```java
// Java 只能一个一个 get
String name = user.getName();
int age = user.getAge();
```

**JS 的解构是语法糖，编译后还是一条条取。**

## 三种常见用法

### ① 对象解构

```javascript
const { token, roles, permissions } = store.getters

// 可以起别名
const { token: myToken } = store.getters     // 把 token 的值赋给 myToken
```

### ② 数组解构

```javascript
const arr = [1, 2, 3]
const [a, b, c] = arr         // a=1, b=2, c=3

// 跳过某个
const [first, , third] = arr  // first=1, third=3
```

### ③ 函数参数解构（⭐ 项目里最常见）

```javascript
// src/directive/permission/hasPermi.js:10
inserted(el, binding, vnode) {
  const { value } = binding           // 从 binding 里取 value
}

// 更简的写法：直接在参数位置解构
inserted(el, { value }, vnode) {
  // 现在 value 就是 binding.value
}
```

## ⭐ 项目里的关键例子：Vuex action 的参数解构

```javascript
// src/store/modules/user.js:49
Login({ commit }, userInfo) {
//     ↑ 这里就是解构！
```

**完整含义**：

```javascript
Login(context, userInfo) {
  const commit = context.commit       // ← 解构等价于这行
}
```

**为什么要解构？**

Vuex 传给 action 的第一个参数是一个"上下文对象"，包含很多东西：

```javascript
{
  commit:   function,     // 触发 mutation
  dispatch: function,     // 触发别的 action
  state:    object,       // 当前模块的 state
  getters:  object,
  rootState: object
}
```

**大多数时候只需要 `commit`**，所以直接解构出来，不用写 `context.commit`。

| 写法 | 含义 |
|---|---|
| `Login({ commit })` | 只要 commit |
| `Login({ commit, state })` | 要 commit 和 state |
| `Login(context)` | 全都要（然后写 `context.commit`） |

## 练习 1.4

下面代码里 `res` 是什么？`res.data` 又是什么？

```javascript
getInfo().then(res => {
  const user = res.data.user
  const roles = res.data.roles
})
```

<details>
<summary>答案</summary>

- `res` = 响应拦截器返回的值（已经剥掉了 axios 包裹层）
- `res.data` = 后端返回的 `data` 字段
- `res.data.user` = 用户对象
- `res.data.roles` = 角色数组

**注意**：这里**不是**解构，是普通属性访问。如果改成解构：

```javascript
getInfo().then(({ data }) => {
  const user = data.user
  const roles = data.roles
})
```
</details>

# 1.5 展开运算符 `...`（Spread）

## 痛点

```javascript
const obj1 = { a: 1, b: 2 }
const obj2 = { c: 3 }

// 想把两个对象合并？
// 老方法：Object.assign({}, obj1, obj2)  ← 啰嗦
```

## 解决

```javascript
const merged = { ...obj1, ...obj2 }        // { a:1, b:2, c:3 }
```

**`...` 的意思是"把这个对象/数组的所有字段摊开在这里"。**

## 三种用法

### ① 合并对象

```javascript
const base = { timeout: 10000, method: 'get' }
const custom = { timeout: 30000 }

const config = { ...base, ...custom }
// 结果：{ timeout: 30000, method: 'get' }   ← 后面的覆盖前面的
```

### ② 合并数组

```javascript
const a = [1, 2]
const b = [3, 4]
const c = [...a, ...b]        // [1,2,3,4]
```

### ③ 浅拷贝（⭐ 项目里常用）

```javascript
const original = { a: 1 }
const copy = { ...original }        // 新对象，改 copy 不影响 original
```

## ⚠️ 重要：只做"浅"拷贝

```javascript
const original = {
  name: 'Tom',
  address: { city: '北京' }        // 嵌套对象
}

const copy = { ...original }
copy.name = 'Jerry'                // ✅ 不影响 original
copy.address.city = '上海'         // ⚠️ **会影响 original！**
```

**原因**：`...` 只复制第一层，嵌套对象复制的是**引用**。

**类比 Java**：`new ArrayList<>(originalList)` —— 也是浅拷贝。

**深拷贝怎么写**（项目里的土办法）：

```javascript
const deepCopy = JSON.parse(JSON.stringify(original))
```

## ⭐ 项目里的关键用法

```javascript
// src/permission.js:51
next({ ...to, replace: true })
```

**含义**：

1. `{ ...to }` = 把 `to` 这个路由对象的所有字段复制到新对象里
2. 再加上 `replace: true`
3. 结果是一个"和 to 一样，但多了 replace 标记"的新对象

**为什么要复制而不是直接改 `to`？** 因为 `to` 是 Vue Router 传进来的只读对象，直接改可能出问题。

```javascript
// src/main.js 常见写法
import { mapGetters } from 'vuex'
computed: {
  ...mapGetters(['roles', 'permissions'])
  // ↑ 把 mapGetters 返回的多个函数"摊开"到 computed 里
}
```

**这里的 `...` 是把一个对象的方法展开，成为 `computed` 的属性**（详见 1.15）。

## 练习 1.5

```javascript
const a = { x: 1, nested: { y: 2 } }
const b = { ...a }
b.x = 99
b.nested.y = 99
console.log(a.x, a.nested.y)
```

<details>
<summary>答案</summary>

输出：`1 99`

- `a.x` 还是 1 ✅（第一层是复制）
- `a.nested.y` 变成 99 ⚠️（嵌套对象复制的是引用，**共享**）

**这就是"浅拷贝"的坑。**
</details>

# 1.6 模板字符串（反引号）

## 痛点

```javascript
const name = 'Tom'
const msg = '你好，' + name + '，你有 ' + count + ' 条消息'    // 加号地狱
```

## 解决

```javascript
const msg = `你好，${name}，你有 ${count} 条消息`
```

**用反引号 `` ` `` 包裹，用 `${变量}` 插值。**

## 类比 Java

```java
// Java
String msg = String.format("你好，%s，你有 %d 条消息", name, count);
// 或
String msg = "你好，" + name + "，你有 " + count + " 条消息";
```

**JS 的 `` ` `` 比这两个都方便**：
- 不用 `String.format` 的位置对应
- 不用一堆 `+`

## 三个能力

### ① 插值

```javascript
`${a} + ${b} = ${a + b}`      // 里面可以写表达式
```

### ② 多行（不用写 `\n`）

```javascript
const html = `
  <div>
    <span>${name}</span>
  </div>
`
```

### ③ 嵌套函数调用

```javascript
`用户：${user.getName()}，年龄：${user.age}`
```

## 项目里的真实例子

```javascript
// src/utils/request.js:58（防重复提交时打印日志）
console.warn(`[${s_url}]: ` + message)
// 输出：[接口地址]: 数据正在处理，请勿重复提交

// src/main.js:89（这是普通字符串，不是模板）
formValidate: require("./utils/formValidate").default

// src/utils/request.js:126（错误处理里截取状态码）
message = "系统接口" + message.substr(message.length - 3) + "异常"
// 这里用 + 拼接，因为只有一处，没必要用模板字符串
```

## ⚠️ 坑：反引号 vs 单引号

```javascript
const a = 'hello ${name}'        // ❌ 单引号不解析 ${}，原样输出
const b = `hello ${name}`        // ✅ 反引号才解析
```

**这是新手常犯的错**：写了 `${}` 但用的是单引号，结果字面量输出了 `${name}`。

## 练习 1.6

改写这段代码，用模板字符串：


# 1.7 `||` 和 `&&` 当"默认值"用（⭐ 极常用）

## 痛点

```javascript
function getUser(user) {
  // 如果 user 是 null，怎么给个默认值？
  let name
  if (user && user.name) {
    name = user.name
  } else {
    name = '匿名'
  }
}
```

## 解决：短路求值

```javascript
const name = (user && user.name) || '匿名'
```

## 原理：`||` 和 `&&` 返回的是"值"，不是布尔值

这一点和 Java **完全不同**！Java 的 `||` 返回 `boolean`，JS 的 `||` 返回**其中一个操作数**。

### `||`（或）：返回第一个"真值"

```javascript
a || b
// 规则：如果 a 是"假值"（false/0/''/null/undefined/NaN），返回 b；否则返回 a

'Tom' || '默认'      // 'Tom'
''    || '默认'      // '默认'
null  || '默认'      // '默认'
undefined || '默认'  // '默认'
0     || '默认'      // '默认'（⚠️ 0 是假值）
```

### `&&`（与）：返回第一个"假值"

```javascript
a && b
// 规则：如果 a 是假值，返回 a；否则返回 b

user && user.name         // user 存在 → 返回 user.name；不存在 → 返回 user（假值）
```

## ⭐ 项目里的 3 个关键用法

### 用法 1：给默认值

```javascript
// src/utils/request.js:73
const code = res.data.code || 200
// 后端没返回 code（undefined）→ 用 200
```

```javascript
// src/utils/request.js:75
const msg = normalizeUserMessage(errorCode[code] || res.data.msg || errorCode['default'])
// 三级优先级：错误码映射表 → 后端 msg → 通用默认文案
// "依次尝试，取第一个有值的"
```

### 用法 2：安全访问（防 undefined 报错）

```javascript
// src/utils/request.js:29
const isToken = (config.headers || {}).isToken === false
//                          ↑ 如果 headers 是 undefined，就用空对象
```

**为什么必须写 `|| {}`？**

```javascript
config.headers.isToken
// 如果 config.headers 是 undefined
// → 报错：Cannot read property 'isToken' of undefined
```

**类比 Java**：`Optional.ofNullable(config.getHeaders()).map(...).orElse(false)`

### 用法 3：安全调用（连接两个操作）

```javascript
// src/directive/permission/hasPermi.js:22
el.parentNode && el.parentNode.removeChild(el)
// 如果 parentNode 是 null，后面的 removeChild 就不执行（避免报错）
```

**这叫"短路"**：`&&` 左边是假值，右边**根本不执行**。

## ⚠️ 坑：`||` 会把 `0` 和 `''` 当成"没有"

```javascript
const count = 0
const result = count || 10      // ❌ 得到 10（但 0 是有效值！）

// 正确做法：用 ??（见 1.9）
const result = count ?? 10       // ✅ 得到 0
```

**这是真实 bug 来源**：分页时 `pageNum: 0 || 1` 会变成 1。

## 练习 1.7

```javascript
const user = { name: '', age: 0 }
const a = user.name || '匿名'
const b = user.age || 18
console.log(a, b)
```

<details>
<summary>答案</summary>

输出：`匿名 18`

- `user.name` 是空字符串 `''`（假值）→ 取 `'匿名'`
- `user.age` 是 `0`（假值）→ 取 `18`

**如果业务上 0 是有效年龄**，这行就有 bug。应该用 `??`。
</details>

# 1.8 `===` vs `==`

## 区别

| 运算符 | 行为 |
|---|---|
| `==` | **松散相等**：会先做类型转换，再比较 |
| `===` | **严格相等**：类型和值都必须相同 |

```javascript
1 == '1'        // true   ⚠️ 字符串被转成数字
1 === '1'       // false  ✅ 类型不同
0 == false      // true   ⚠️
0 === false     // false  ✅

null == undefined     // true   ⚠️
null === undefined    // false  ✅
```

## 规则：**永远用 `===`**

项目代码里几乎全是 `===`。

```javascript
// src/utils/request.js:29
const isToken = (config.headers || {}).isToken === false
//                                                  ↑ 严格等于
```

## ⚠️⚠️ 一个致命的小坑（项目里真实存在）

```javascript
const isToken = (config.headers || {}).isToken === false
```

**为什么必须是 `=== false`，不能写成 `!isToken`？**

| 情况 | `.isToken` 的值 | `=== false` 结果 | `!isToken` 结果 |
|---|---|---|---|
| 请求**没写** `isToken` | `undefined` | **`false`** ✅ 正常 | **`true`** ❌ 灾难 |
| 请求写了 `isToken: true` | `true` | `false` ✅ | `false` ✅ |
| 请求写了 `isToken: false` | `false` | `true` ✅ | `true` ✅ |

**用 `!isToken` 的后果**：所有**没写** `isToken` 的请求（也就是 99% 的请求）都被判定为"不要 token" → **全站 401**。

**⭐ 这就是"反向开关"必须用 `=== false` 的原因。**

## 例外：项目里有两处用了 `==`

```javascript
// src/utils/request.js:115
if (message == "Network Error") { ... }
//          ↑ 松散相等（能工作但不严谨）
```

**为什么？** 可能是历史遗留写法。**你自己写代码时请一律用 `===`。**

## 练习 1.8

下面哪个判断是安全的？

```javascript
// A
if (value) { ... }

// B
if (value === undefined || value === null) { ... }
```

<details>
<summary>答案</summary>

**取决于意图**：

- A：`value` 是 `0`、`''`、`false` 时也会进 `else` —— **可能不是你要的**
- B：只判断"没有值" —— **更精确**

**项目里的正确示范**：

```javascript
// src/utils/request.js:49
if (sessionObj === undefined || sessionObj === null || sessionObj === '') {
```

这里把 `''` 也算"没有"，因为 `sessionStorage` 读空时返回 `null`，序列化后可能是空串。
</details>

# 1.9 `?.` 和 `??`（可选链、空值合并）

## 痛点

```javascript
// 想取 user 的 address 的 city，但 user 或 address 可能是 null
const city = user.address.city          // ❌ 报错：Cannot read property 'city' of undefined
```

老写法：

```javascript
const city = user && user.address && user.address.city     // 啰嗦
```

## 解决：可选链 `?.`

```javascript
const city = user?.address?.city
// 任何一环是 null/undefined → 整个表达式返回 undefined（不报错）
```

**类比 Java**：`Optional.ofNullable(user).map(User::getAddress).map(Address::getCity).orElse(null)`

## 空值合并 `??`

```javascript
a ?? b
// 规则：如果 a 是 null 或 undefined，返回 b；否则返回 a
```

**和 `||` 的区别**：

| 表达式 | `a = 0` 的结果 |
|---|---|
| `a \|\| b` | `b`（0 是假值，被跳过）❌ |
| `a ?? b` | **`0`**（0 不是 null/undefined）✅ |

**所以：想给"默认值"且 0/''/false 是有效值时，必须用 `??`。**

## ⚠️ 浏览器兼容性

`?.` 和 `??` 是 ES2020 的语法，**老浏览器（IE、旧版安卓 WebView）不支持**。

**本项目是 Vue 2 + babel 编译**，所以能用（babel 会转译）。

但如果你看到项目里用的是：

```javascript
const isToken = (config.headers || {}).isToken === false
```

**而不是**

```javascript
const isToken = config.headers?.isToken === false
```

那是因为这份代码写于 2021 年，当时团队习惯用 `|| {}`。

**两种写法效果一样**，`?.` 更现代。

## 项目里的现状

我搜过：项目里**大量使用 `|| {}` / `&&` 的安全写法，几乎没有 `?.`**。

**你写新代码时，用 `?.` 更简洁。**

## 练习 1.9

```javascript
const config = { timeout: 0 }
const a = config.timeout || 10000
const b = config.timeout ?? 10000
console.log(a, b)
```

<details>
<summary>答案</summary>

输出：`10000 0`

- `a`：`0` 是假值 → 取 `10000`（**如果 0 是有效值，这是 bug**）
- `b`：`0` 不是 null/undefined → 保留 `0` ✅

**这就是 `??` 存在的意义。**
</details>

# 1.10 数组方法（`.some()` `.every()` `.filter()` `.map()`）

> 这一组是**项目里出现频率最高的**，权限判断、列表过滤全靠它们。

## 类比 Java Stream

| JS | Java Stream | 作用 |
|---|---|---|
| `.filter(f)` | `.filter(f)` | 过滤 |
| `.map(f)` | `.map(f)` | 转换 |
| `.some(f)` | `.anyMatch(f)` | 有一个满足就 true |
| `.every(f)` | `.allMatch(f)` | 全部满足才 true |
| `.find(f)` | `.filter(f).findFirst()` | 找第一个 |
| `.forEach(f)` | `.forEach(f)` | 遍历 |
| `.includes(x)` | `.contains(x)` | 是否包含 |

## 逐个看（含项目真实用法）

### `.some()` —— 有一个满足就 true（⭐ 权限判断的核心）

```javascript
// src/plugins/auth.js:7
return permissions.some(v => {
  return all_permission === v || v === permission
})
```

**读法**：遍历用户拥有的所有权限码（`permissions`），
**只要有一个**是 `*:*:*` 或者等于要求的权限码 → 返回 `true`。

**为什么用 `some` 而不是 `filter`？** 因为 `some` 找到第一个就停，**性能更好**（不用遍历完）。

### `.every()` —— 全部满足才 true

```javascript
// src/plugins/auth.js:40
hasPermiAnd(permissions) {
  return permissions.every(item => {
    return authPermission(item)
  })
}
```

**读法**：要求的所有权限码，用户必须**全部**拥有。

### `.filter()` —— 过滤

```javascript
// src/store/modules/permission.js:57
return asyncRouterMap.filter(route => {
  // ... 处理逻辑
  return true        // ⚠️ 永远返回 true = 不过滤，只是借用遍历
})
```

**⚠️ 这个用法很特别**：回调永远返回 `true`，所以**没有真正过滤**，
只是"借用 `filter` 的遍历能力"（因为 `filter` 会返回新数组，而 `forEach` 不会）。

**更清晰的写法**应该是 `.map()` 或 `forEach`，但这段是 RuoYi 原版代码。

### `.map()` —— 转换

```javascript
// src/views/contract/contractDraft/index.vue:380
this.ids = selection.map((item) => item.id)
// 把 [{id:1,name:'a'}, {id:2,name:'b'}] 变成 [1, 2]
```

**这就是"提取字段"**，等价 Java：

```java
List<Long> ids = selection.stream().map(Item::getId).collect(Collectors.toList());
```

### `.includes()` —— 是否包含

```javascript
// src/directive/permission/hasPermi.js:18
return all_permission === permission || permissionFlag.includes(permission)
```

**注意方向**：`permissionFlag` 是**页面要求的权限码数组**，
`permission` 是**用户拥有的某个权限码**。

所以是"页面要求的数组里，包含用户这个权限吗"。

## ⭐ 一个必须理解的差异：会不会"提前终止"

| 方法 | 何时停止 |
|---|---|
| `.some()` | 找到第一个满足的**就停** |
| `.every()` | 找到第一个不满足的**就停** |
| `.filter()` / `.map()` | **遍历完全部** |

**所以权限判断用 `some` 比 `filter().length > 0` 快。**

## 练习 1.10

下面代码做什么？

```javascript
const hasPermission = permissions.some(p => p === '*:*:*' || p === 'contract:add')
```

<details>
<summary>答案</summary>

判断当前用户是否：
1. 拥有超级权限 `*:*:*`，**或**
2. 拥有 `contract:add` 这个具体权限

**只要满足一个就返回 `true`。**

这正是 `src/plugins/auth.js` 里 `authPermission` 的核心逻辑。

---

**延伸思考**：如果改成 `.every()`，含义就变成"必须同时拥有这两个"，完全不同。
</details>

# 1.11 Promise（`.then()` 链）

## 痛点

JS 是**单线程**的。网络请求要等几百毫秒，**不能阻塞界面**。

所以所有网络请求都是**异步**的——发起后立刻返回，结果稍后才来。

```javascript
const data = getData()       // ❌ 不能这样写（拿不到结果）
console.log(data)            // 此时请求还没回来
```

## 解决：Promise

Promise 表示"**一个未来才会有结果的操作**"。

```javascript
getData()
  .then(data => {
    console.log(data)        // ✅ 请求成功后才执行
  })
  .catch(err => {
    console.error(err)       // 失败时执行
  })
```

## 三个状态

| 状态 | 含义 |
|---|---|
| `pending` | 进行中 |
| `fulfilled` | 成功（会调 `.then`） |
| `rejected` | 失败（会调 `.catch`） |

**状态一旦确定就不能改**（`fulfilled` 不会再变 `rejected`）。

## 类比 Java

```java
// Java
CompletableFuture<String> future = getDataAsync();
future.thenAccept(data -> System.out.println(data));
```

**几乎一一对应**：

| JS | Java |
|---|---|
| `.then(f)` | `.thenAccept(f)` / `.thenApply(f)` |
| `.catch(f)` | `.exceptionally(f)` |
| `Promise.all([...])` | `CompletableFuture.allOf(...)` |
| `new Promise((resolve, reject) => {})` | `new CompletableFuture<>()` |

## ⭐ 项目里的关键用法

### 用法 1：链式调用（多个异步串起来）

```javascript
// src/views/contract/contractDraft/index.vue:401（删除操作）
this.$modal.confirm('是否确认删除...')      // ① 弹确认框（返回 Promise）
  .then(() => {
    this.loading = true
    return delContractDraft(ids)             // ② 调删除接口（返回 Promise）
  })
  .then(() => {
    this.loading = false
    this.getList()                           // ③ 刷新列表
    this.$modal.msgSuccess('删除成功')
  })
  .finally(() => {
    this.loading = false                     // ④ 无论如何都执行
  })
```

**`.finally()` = 不管成功失败都执行**（适合收尾，比如关 loading）。

**类比 Java**：`whenComplete((r, e) -> loading = false)`

### 用法 2：手动创建 Promise

```javascript
// src/store/modules/user.js:55
return new Promise((resolve, reject) => {
  login(...).then(res => {
    setToken(res.data.token)
    resolve()                 // ← 告诉调用方"成功了"
  }).catch(error => {
    reject(error)             // ← 告诉调用方"失败了"
  })
})
```

**`resolve()` = 成功，`reject(err)` = 失败。**

### 用法 3：返回 Promise 的函数能被 `.then`

```javascript
// src/store/modules/user.js:49
Login({ commit }, userInfo) {
  return new Promise(...)     // ★ 返回 Promise
}

// 调用方（login.vue）
this.$store.dispatch('Login', this.loginForm).then(() => {
  this.$router.push({ path: this.redirect || "/" })      // 登录成功后才跳转
})
```

## ⚠️ 坑：忘了 return

```javascript
// ❌ 错误：没 return
.then(() => {
  delContractDraft(ids)        // 这个 Promise 没人等
})
.then(() => {
  this.getList()               // 可能在删除完成前就执行了！
})

// ✅ 正确
.then(() => {
  return delContractDraft(ids)
})
```

**规则：在 `.then` 里返回 Promise，下一个 `.then` 才会等它。**

## 练习 1.11

```javascript
Promise.resolve(1)
  .then(v => { console.log('A', v); return v + 1 })
  .then(v => { console.log('B', v) })
  .finally(() => console.log('C'))
```

输出顺序？

<details>
<summary>答案</summary>

```
A 1
B 2
C
```

- 第 1 个 `.then` 收到 `1`，打印 `A 1`，返回 `2`
- 第 2 个 `.then` 收到 `2`，打印 `B 2`
- `.finally` 最后执行，打印 `C`

**关键：`.then` 的返回值会传给下一个 `.then`。**
</details>

# 1.12 `async` / `await`

## 痛点

`.then` 链写多了会"嵌套地狱"：

```javascript
getUser().then(user => {
  getRoles(user.id).then(roles => {
    getPermissions(roles[0]).then(perms => {
      console.log(perms)      // 缩进太深
    })
  })
})
```

## 解决：`async` / `await`

```javascript
async function load() {
  const user = await getUser()              // ← 看起来像同步代码
  const roles = await getRoles(user.id)
  const perms = await getPermissions(roles[0])
  console.log(perms)
}
```

**`await` 的作用**：等后面的 Promise 完成再继续，**把结果直接赋给变量**。

**⚠️ 关键：`await` 只能用在 `async` 函数里。**

## 类比 Java

```java
// Java
public void load() {
  User user = getUser().get();                    // 阻塞等待
  List<Role> roles = getRoles(user.getId()).get();
}
```

**但 JS 的 `await` 不会阻塞整个浏览器**——只暂停这个函数，其他代码照常跑。

## 项目里的用法

```javascript
// src/utils/request.js:142（下载文件）
}).then(async (data) => {
  const isLogin = await blobValidate(data)        // 等验证完成
  if (isLogin) {
    const blob = new Blob([data])
    saveAs(blob, filename)
  } else {
    const resText = await data.text()             // 等读取完成
    const rspObj = JSON.parse(resText)
    Message.error(errMsg)
  }
  downloadLoadingInstance.close()
})
```

**注意 `then(async (data) => {...})`**：
`.then` 的回调是 `async` 函数，里面才能用 `await`。

## ⚠️ 坑：`async` 函数返回的一定是 Promise

```javascript
async function f() {
  return 1
}
f()                        // 返回 Promise<1>，不是 1

// 要用结果必须 await 或 .then
const x = await f()        // 1
```

## 练习 1.12

把这段 `.then` 链改成 `async/await`：

```javascript
getUser().then(user => {
  getRoles(user.id).then(roles => {
    console.log(roles)
  })
})
```

<details>
<summary>答案</summary>

```javascript
async function load() {
  const user = await getUser()
  const roles = await getRoles(user.id)
  console.log(roles)
}
load()
```

**注意需要包在一个 `async` 函数里**（顶层 `await` 在旧环境不支持）。
</details>

# 1.13 对象字面量简写

## 痛点

```javascript
const name = 'Tom'
const age = 20

const user = {
  name: name,        // ← 名字重复了
  age: age
}
```

## 解决

```javascript
const user = { name, age }      // 等价于 { name: name, age: age }
```

**规则：如果"变量名"和"属性名"一样，可以省略 `: 值`。**

## 项目里的真实例子

```javascript
// src/api/login.js:6
const data = {
  username,        // = username: username
  password,        // = password: password
  code,
  uuid,
  tenantId
}
```

```javascript
// src/main.js 的 plugins 注册
Vue.use(Element, { size: Cookies.get("size") || "medium" })
//                ↑ 这是普通对象，没有简写
```

## ⚠️ 一个容易混的写法：`data: data`

```javascript
// src/api/login.js:19
return request({
  url: '/login',
  method: 'post',
  data: data            // ← 这里不能简写成 data！
})
```

**为什么？** 因为 `request()` 的参数对象的属性名叫 `data`，
如果写成 `{ data }`，JS 会去找一个叫 `data` 的**变量**。

这里恰好有那个变量（第 6 行定义的 `data`），所以 `{ data }` **也能工作**。

但项目里写的是 `data: data`（显式），**更清晰**。

## 练习 1.13

```javascript
const token = 'abc'
const roles = ['admin']
const state = { token, roles, permissions: [] }
```

`state` 是什么？

<details>
<summary>答案</summary>

```javascript
{
  token: 'abc',
  roles: ['admin'],
  permissions: []
}
```

**前两个用了简写，第三个是完整写法。**

# 1.15 `...mapGetters()` —— 这种"函数调用在对象里"是什么

## 先看代码

```javascript
// src/layout/components/Sidebar/index.vue
computed: {
  ...mapState(["settings"]),
  ...mapGetters(["userInfo"]),
  ...mapGetters(["sidebarRouters", "sidebar"]),
}
```

**这一坨 `...mapGetters(...)` 在干什么？**

## 拆解

### ① `mapGetters` 是一个函数，返回一个**对象**

```javascript
mapGetters(['roles', 'permissions'])
// 返回：
{
  roles: function() { return this.$store.getters.roles },
  permissions: function() { return this.$store.getters.permissions }
}
```

**它帮你批量生成 computed 属性的访问器。**

### ② `...` 把这个对象"摊开"

```javascript
computed: {
  ...mapGetters(['roles', 'permissions'])
}

// 等价于
computed: {
  roles: function() { return this.$store.getters.roles },
  permissions: function() { return this.$store.getters.permissions }
}
```

### ③ 效果：页面里可以直接用

```javascript
this.roles           // 等价于 this.$store.getters.roles
this.permissions     // 等价于 this.$store.getters.permissions
```

## 类比

```java
// 如果你有个类，要暴露 10 个 getter
public String getA() { return store.getA(); }
public String getB() { return store.getB(); }
// ... 10 个重复方法

// Java 没有语法糖能省掉这些
```

**JS 的 `mapGetters` 就是"批量生成这些 getter 方法"的工具。**

## 三个类似的工具

| 工具 | 映射的是什么 |
|---|---|
| `mapGetters([...])` | `this.$store.getters.xxx` |
| `mapState([...])` | `this.$store.state.xxx` |
| `mapActions([...])` | `this.$store.dispatch('xxx')` |
| `mapMutations([...])` | `this.$store.commit('xxx')` |

## 练习 1.15

下面代码等价于什么？

```javascript
computed: {
  ...mapGetters(['token', 'nickname'])
}
```

<details>
<summary>答案</summary>

```javascript
computed: {
  token: function() { return this.$store.getters.token },
  nickname: function() { return this.$store.getters.nickname }
}
```

**之后在模板里就能写 `{{ token }}` 或 `{{ nickname }}`。**
</details>

# 本章自测（15 题）

答对 12 题以上再进第 2 章。

1. `import { a } from 'x'` 和 `import a from 'x'` 有什么区别？
2. `const` 声明的对象，能不能改它的属性？
3. 为什么 `x => { x + 1 }` 返回 `undefined`？
4. 箭头函数的 `this` 指向什么？
5. `const { commit } = context` 等价于什么？
6. `{ ...obj1, ...obj2 }` 中同名字段取谁的？
7. `${}` 必须用什么符号包裹字符串？
8. `'' || 'default'` 的结果是什么？
9. `0 ?? 10` 和 `0 || 10` 分别是什么？
10. 为什么判断"不要 token"必须写 `=== false` 而不是 `!isToken`？
11. `.some()` 和 `.filter()` 最关键的区别？
12. `.then()` 里不写 `return` 会怎样？
13. `await` 只能用在什么函数里？
14. `mapGetters` 返回的是什么？
15. `import "./permission"` 这种没有 `from` 的导入有什么用？

<details>
<summary>答案</summary>

1. 前者取**具名导出**（名字必须对上），后者取**默认导出**（名字随便起）
2. **能**。`const` 只锁"不能重新赋值"，不锁"内容不能改"（≈ `final` 对象引用）
3. 因为有 `{}` 但没写 `return`，函数体执行完返回 `undefined`
4. **外层的 `this`**（不自己创建 `this`）
5. `const commit = context.commit`
6. **后面的覆盖前面的**（`...obj2` 优先）
7. **反引号** `` ` ``（不是单引号！）
8. `'default'`（空串是假值）
9. `0` 和 `10`（`??` 只认 null/undefined）
10. 因为 `undefined` 取反是 `true`，会让**所有没写 `isToken` 的请求都不带 token** → 全站 401
11. `.some()` **找到第一个满足的就停**；`.filter()` 遍历完全部
12. 下一个 `.then` **不会等**它，可能提前执行
13. **`async` 函数**里
14. 一个**对象**，里面是一批"访问 store 的函数"（再用 `...` 摊开）
15. **只执行一遍**，不取任何东西。用来触发副作用（如 `permission.js` 里的 `router.beforeEach`）
</details>
