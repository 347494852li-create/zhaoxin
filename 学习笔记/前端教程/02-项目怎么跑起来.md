# 2.1 环境要求

## 必须的版本

| 组件 | 要求 | 检查命令 | 为什么 |
|---|---|---|---|
| **Node.js** | **16.x 或 18.x** | `node -v` | ⚠️ **不能用 20+，更不能用 24**（见下面） |
| **npm** | 8.x+ | `npm -v` | 装依赖 |
| **后端** | Java 11 + MySQL 8 + Redis | — | 见项目根 `docs/开发运行文档.md` |

## ⚠️⚠️ 坑：Node 版本太高会失败

这个项目的技术栈是**2020~2021 年**的：

```json
"vue": "2.6.12",
"@vue/cli-service": "4.4.6"
```

`package.json` 里的 dev 脚本已经带了一个补丁：

```json
"dev": "set NODE_OPTIONS=--openssl-legacy-provider && vue-cli-service serve"
//                          ↑ 这行说明作者已经踩过 OpenSSL 的坑了
```

**但仍然不建议用 Node 20+**，因为：

| Node 版本 | 结果 |
|---|---|
| 14 / 16 | ✅ 最稳（项目当年的版本） |
| 18 | ✅ 基本能跑 |
| 20 | ⚠️ 可能报 `ERR_OSSL_EVP_UNSUPPORTED` |
| **22 / 24** | ❌ **大概率失败**（webpack 4 的很多 API 被移除） |

### 怎么切换 Node 版本

**如果你装过 nvm-windows**：

```powershell
nvm install 16.20.2
nvm use 16.20.2
node -v              # 应该显示 v16.20.2
```

**⭐ 关键：切完必须重开终端！** `nvm use` 改的是环境变量，当前已经打开的终端不会生效。

**如果没装 nvm**：

1. 去 https://github.com/coreybutler/nvm-windows/releases
2. 下载 `nvm-setup.exe`
3. 一路下一步
4. **重开终端**，`nvm -v` 能显示版本就成功

### 为什么不用最新的 Node？

**类比 Java**：你的项目用 Java 8 写的，非要用 Java 21 跑，会遇到：
- 模块系统变化（JAXB 被移除）
- 反射限制
- 依赖不兼容

**Node 也一样**：webpack 4（Vue CLI 4 用的）在 Node 17+ 上因为 OpenSSL 3 会报错，
在 Node 22+ 上因为更多 API 移除会彻底挂。

## 检查你的环境

```powershell
node -v
npm -v
```

**期望输出**（示例）：
```
v16.20.2
8.19.4
```

**如果 node 是 v20 以上，先别往下走，先切版本。**

# 2.2 安装依赖

## 命令

```powershell
cd E:\Develop\project\zxcm-learn\zxcm-ui
npm install
```

## 会发生什么

1. 读 `package.json` 里的依赖列表
2. 下载到 `node_modules/` 目录
3. 首次安装大约 **3~10 分钟**（取决于网速）

**这个项目有 1011 个包**，装完 `node_modules` 大约 300~500 MB。

## ⭐ 用国内镜像（强烈推荐）

```powershell
npm install --registry=https://registry.npmmirror.com
```

**或者永久设置**：

```powershell
npm config set registry https://registry.npmmirror.com
```

**为什么？** `npm install` 默认从 `registry.npmjs.org` 下载，国内会非常慢甚至失败。

## ⚠️ 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `ECONNRESET` / `ETIMEDOUT` | 网络 | 用国内镜像（见上） |
| `Unexpected end of JSON input` | 缓存损坏 | `npm cache clean --force` 后重装 |
| `gyp ERR!` | 需要编译原生模块 | 装 Python 2.7 + Visual Studio Build Tools（这个项目一般不需要） |
| `EACCES` / `EPERM` | 权限 | 别用管理员运行，或者改用 `--no-optional` |

## 确认装好了

```powershell
Test-Path node_modules
# 期望：True

(Get-ChildItem node_modules -Directory).Count
# 期望：1000 左右
```

# 2.3 改后端地址（3 处）

> **⭐ 这一节是关键**：如果后端地址不对，前端跑起来也登录不了。

## 3 处要改的地方

### ① 后端要连的数据库（改后端，不是前端）

**文件**：`ruoyi-admin/src/main/resources/application-dev.yml`

```yaml
spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:mysql://localhost:3306/opensource?...
          username: root
          password: root        # ← 改成你的
```

**⚠️ 注意库名**：配置里默认是 `opensource`，但项目文档推荐建 `zxcm`。
**两者必须一致**，否则报"表不存在"。

**建议**：建库时叫 `zxcm`，然后把配置里的 `opensource` 改成 `zxcm`。

### ② 前端要连的后端（改前端，本教程重点）

**文件**：`zxcm-ui/vue.config.js`

```javascript
devServer: {
  port: 80,                                    // 前端端口
  proxy: {
    [process.env.VUE_APP_BASE_API]: {           // '/dev-api'
      target: `http://localhost:8080`,           // ← 后端地址
      changeOrigin: true,
      pathRewrite: {
        ['^' + process.env.VUE_APP_BASE_API]: ''  // 剥掉 /dev-api
      }
    }
  }
}
```

**要改的**：

| 项 | 默认值 | 什么时候改 |
|---|---|---|
| `target` | `http://localhost:8080` | 后端不在本机 / 换了端口 |
| `port` | `80` | 80 被占用（如被 IIS、Skype 占） |

**端口 80 被占用怎么办？**

```powershell
# 查谁占了 80
Get-NetTCPConnection -LocalPort 80 -State Listen | ForEach-Object { Get-Process -Id $_.OwningProcess }
```

**改法**：在 `zxcm-ui` 目录下建一个 `.env.local`（或改 `.env.development`）：

```ini
port = 8081
```

**然后访问 `http://localhost:8081`。**

### ③ 环境变量文件（了解即可，一般不用改）

**文件**：`zxcm-ui/.env.development`

```ini
VUE_APP_TITLE = 合同管理系统
ENV = 'development'
VUE_APP_BASE_API = '/dev-api'           # ← 就是这个前缀
VUE_APP_CONTEXT_PATH = '/'
VUE_APP_MONITRO_ADMIN = 'http://localhost:9090/admin/login'
VUE_APP_XXL_JOB_ADMIN = 'http://localhost:9100/xxl-job-admin'
VUE_CLI_BABEL_TRANSPILE_MODULES = true
```

**⭐ 关键规则**：只有 `VUE_APP_` 开头的变量才会被打包进浏览器。

**为什么？** 这是安全闸门，防止把 `DB_PASSWORD` 这种误打包进 JS 被人 F12 看到。

**改完必须重启**（环境变量是**编译时**注入的，热更新不生效）。

## 三个文件的关系

```
zxcm-ui/.env.development          →  定义 VUE_APP_BASE_API = '/dev-api'
        ↓ 打包时替换
src/utils/request.js              →  baseURL: '/dev-api'
        ↓ 每个请求自动加前缀
浏览器发请求                      →  GET http://localhost/dev-api/xxx
        ↓ vue.config.js 的 proxy 匹配到 '/dev-api'
devServer 转发                    →  GET http://localhost:8080/xxx（剥掉前缀）
```

# 2.4 启动

## 前提：后端要先起来

**顺序很重要**：先后端，后前端。

```powershell
# 后端（在项目根目录）
mvn clean package -DskipTests
java -jar ruoyi-admin/target/zxcm-admin.jar
```

或者在 IDEA 里跑 `com.ruoyi.RuoYiApplication`。

**验证后端起来了**：

```powershell
curl http://localhost:8080/captchaImage
# 期望：{"code":200,...,"img":"iVBORw0KGgo..."}
```

**⭐ `/captchaImage` 返回 200 就同时证明了 3 件事**：
1. Web 服务器（Tomcat）活着
2. MySQL 连上了
3. Redis 连上了

（因为生成验证码需要 Redis 存 uuid 对应的答案）

## 启动前端

```powershell
cd E:\Develop\project\zxcm-learn\zxcm-ui
npm run dev
```

## 成功的样子

```powershell
 DONE  Compiled successfully in 30000ms

  App running at:
  - Local:   http://localhost/
  - Network: http://192.168.1.100/

  Note that the development build is not optimized.
  To create a production build, run npm run build.
```

**浏览器会自动打开**（`vue.config.js` 里配了 `open: true`）。

## ⚠️ 如果启动很慢

**第一次启动要 30 秒 ~ 2 分钟是正常的**，因为 webpack 要：
1. 编译 528 个源文件
2. 处理所有依赖
3. 生成 bundle

**第二次启动会快很多**（有缓存）。

按顺序验证，**全过才算成功**：

## 标志 1：能看到登录页

浏览器打开 `http://localhost/`，应该看到登录页（有验证码图片）。

## 标志 2：F12 能看到请求成功

按 **F12** → 切到 **Network** 面板 → 刷新页面。

应该看到这些请求（状态码 200）：

```
GET /dev-api/captchaImage      → 200  ← 验证码
GET /dev-api/common/config     → 200  ← 系统配置
```

**⭐ `/dev-api` 前缀**说明代理生效了。

## 标志 3：能登录

| 项 | 值 |
|---|---|
| 账号 | `zxcmAdmin` |
| 密码 | `123456` |
| 验证码 | 看图输入 |

## 标志 4：登录请求返回 token

F12 → Network → 找到 `login` 请求（POST）→ 看 **Response**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }

```

**⭐ 看到 `token` 就说明登录链路打通了。**

登录后应该看到：
- 左侧侧边栏有菜单


**这两个请求成功，就说明"权限 + 动态路由"链路也通了。**

# 2.6 15 个常见报错

## 启动类错误

| # | 报错 | 原因 | 解决 |
|---|---|---|---|
| 1 | `ERR_OSSL_EVP_UNSUPPORTED` | Node 17+ 的 OpenSSL 3 | 切到 Node 16/18；或临时：`$env:NODE_OPTIONS="--openssl-legacy-provider"` |
| 2 | `Cannot find module 'webpack'` | 依赖没装全 | 删 `node_modules` 重装 |
| 3 | `EACCES: permission denied` | 权限 / 端口被占 | 换端口（见 2.3）；别用管理员运行 |
| 4 | `Port 80 is already in use` | 80 被占用 | `port = 8081` 写进 `.env.local` |
| 5 | `Module not found: Error: Can't resolve '@/xxx'` | 路径错了 / 文件不存在 | 检查 `@` 后的路径、大小写 |
| 6 | `Syntax Error: Unexpected token` | 语法错误 / Node 版本太低 | 看具体行号；确认 Node ≥ 14 |
| 7 | `digital envelope routines::unsupported` | 同 #1 | 同 #1 |

## 代理 / 请求错误

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 8 | 接口全部 **404** | 后端没起 / `target` 地址错 | 先确认 `http://localhost:8080/doc.html` 能开 |
| 9 | 接口全部 **401** | token 没带上 / 后端 `token-name` 不匹配 | 看第 5 章（token 机制） |
| 10 | 接口 **CORS 跨域报错** | 前端没走代理（直接请求了 8080） | 确认请求 URL 是 `/dev-api/xxx`（不带域名） |
| 11 | `net::ERR_CONNECTION_REFUSED` | 后端没起 | 启动后端 |
| 12 | 登录页验证码**显示不出来** | Redis 没起 / 后端报错 | 看后端控制台 |

## 页面错误

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 13 | 登录后**白屏** | 动态路由没生成 / 有 JS 报错 | F12 → Console 看红色错误 |
| 14 | 左侧**菜单是空的** | `/getRouters` 失败 / 该用户没分配菜单 | F12 看 `/getRouters` 的响应 |
| 15 | 改代码**不生效** | 热更新失效 / 改的是 `.env` | Ctrl+F5 强刷；改 `.env` 必须重启 |

## ⭐ 排查万能三步

```
① F12 → Console：有没有红色报错？
② F12 → Network：请求的 URL、状态码、Response 是什么？
③ 看终端（前后端两个窗口）：有没有报错日志？
```

**80% 的问题用这三步能定位。**

# 2.7 前后端分离是怎么跑起来的（原理）

**这一节是理解整条链路的基础。**

## 三个进程

```
┌─────────────────────┐        ┌─────────────────────┐
│  前端 devServer      │        │      后端            │
│  localhost:80        │ ─────► │  localhost:8080      │
│  （webpack 起的热更新）│  代理    │  （Spring Boot）      │
└─────────────────────┘        └──────────┬──────────┘
                                          │
                              ┌───────────┴───────────┐
                              ▼                       ▼
                        ┌──────────┐            ┌──────────┐
                        │  MySQL   │            │  Redis   │
                        │  :3306   │            │  :6379   │
                        └──────────┘            └──────────┘
```

| 进程 | 端口 | 谁起的 | 作用 |
|---|---|---|---|
| 前端 devServer | 80 | `npm run dev` | 编译前端、热更新、代理 API |
| 后端 | 8080 | `java -jar` / IDEA | 业务逻辑、查数据库 |
| MySQL | 3306 | 服务/Docker | 数据 |
| Redis | 6379 | 服务/Docker | 登录态、缓存、锁 |

## 一次请求的完整路径

```
① 浏览器： GET http://localhost/dev-api/contract/contractDraft/list?pageNum=1
                     ↑ 前端端口 80

② devServer 收到请求，匹配到 proxy 规则 '/dev-api'
   → 剥掉前缀，转发到 target
   
③ devServer → 后端： GET http://localhost:8080/contract/contractDraft/list?pageNum=1

④ 后端查 MySQL，返回 { code:200, rows:[...], total:53 }

⑤ 响应原路返回：后端 → devServer → 浏览器

⑥ 前端代码拿到数据，渲染表格
```

## ⭐ 为什么要代理，不直接请求 8080？

**如果前端直接请求 `http://localhost:8080`，浏览器会报跨域错误。**

跨域规则（同源策略）：

| 前端地址 | 后端地址 | 同源吗 |
|---|---|---|
| `http://localhost` | `http://localhost:8080` | ❌ **端口不同 → 跨域** |
| `http://localhost` | `http://localhost/dev-api/...` | ✅ 同源（都走 80） |

**代理的作用**：让浏览器**以为**在和同源的 80 端口说话，
实际由 devServer 在**服务器端**转发给 8080。

**服务器端转发不受同源策略限制**（同源策略是浏览器的规则）。

## 生产环境怎么办

**生产环境不用 devServer**，用 Nginx：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;          # 前端打包产物 dist/
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # ★ SPA 路由回退
    }

    location /prod-api/ {
        proxy_pass http://backend:8080/;    # ★ 末尾的 / 是剥前缀
    }
}
```

**⭐ `try_files $uri $uri/ /index.html` 必须有**：

因为项目用 **history 路由模式**（URL 没有 `#`）。
用户直接访问 `/contract/contractDraft` 时，Nginx 会去找这个物理文件 → 找不到 → 404。
`try_files` 让它回退到 `index.html`，由前端路由自己处理。

10. 生产环境的 Nginx 为什么必须有 `try_files ... /index.html`？

<details>
<summary>答案</summary>

1. 因为 Vue CLI 4.4.6 / webpack 4 在 Node 17+ 上因为 OpenSSL 3 会报错，Node 22+ 有更多 API 移除
2. 用国内镜像：`npm install --registry=https://registry.npmmirror.com`
3. `vue.config.js` 的 `devServer.proxy` 里的 `target`（默认 `http://localhost:8080`）
4. 开发环境 `/dev-api`，生产环境 `/prod-api`；定义在 `.env.development` / `.env.production`
5. 安全闸门：防止 `DB_PASSWORD` 这类敏感变量误打包进 JS 被 F12 看到
6. **先后端**，后前端（前端起来时会发 `/captchaImage`，后端不在就 404）
7. Web 服务器活着、MySQL 连上了、Redis 连上了
8. `GET /getInfo`（用户信息+权限）和 `GET /getRouters`（菜单树）
9. 会跨域（端口不同）。代理让浏览器以为在同源 80 端口，实际由 devServer 服务端转发
10. 因为用的是 history 路由模式，直接访问深层 URL 会 404，需要回退到 `index.html` 让前端路由处理
</details>
