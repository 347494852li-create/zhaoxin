## ⭐ 记住这张"分层表"

| 层 | 目录 | 职责 | 类比后端 |
|---|---|---|---|

| **页面** | `views/` | UI 和交互 | Controller |

| **插件/指令** | `plugins/` `directive/` | 全局能力扩展 | AOP / 自定义注解 |

# 4.2 启动顺序（从 URL 到页面显示）

**这一节是理解整个骨架的关键。**

```
① 浏览器访问 http://localhost/
        ↓
② Nginx / devServer 返回 public/index.html
   （整个网站只有这一个 HTML）
        ↓
③ index.html 里加载打包后的 JS（webpack 自动插入的 <script>）
        ↓
④ 执行 src/main.js
        ├─ import 一堆东西
        ├─ Vue.component() 注册 13 个全局组件
        ├─ Vue.use() 安装插件
        └─ new Vue({ el:'#app', router, store, render: h => h(App) })
        ↓
⑤ Vue 接管 index.html 里的 <div id="app">
   （"系统加载中"被替换掉）
        ↓
⑥ 渲染 App.vue（根组件，只有 <router-view />）
        ↓
⑦ 首次路由跳转触发 permission.js 的 router.beforeEach
        ├─ 没 token → 踢到 /login
        └─ 有 token → 拉 getInfo + getRouters → 建路由 → next()
        ↓
⑧ 路由匹配成功 → 渲染对应页面
        ↓
⑨ 如果页面配了 component: Layout
   → 先渲染 layout/index.vue（侧边栏+顶栏+标签页）
   → 业务页面渲染在 <app-main> 里的 <router-view />
        ↓
⑩ 页面组件的 created() 触发 → 发请求 → 数据渲染
```

## ⭐ 三个"只执行一次"

| 什么 | 在哪里 | 执行次数 |
|---|---|---|
| `index.html` | 浏览器 | **只有第一次**（之后是 JS 换内容） |
| `main.js`（含 `new Vue()`） | 页面加载时 | **一次**（刷新会重新执行） |
| `router.beforeEach` 注册 | `main.js` 的 `import "./permission"` | 一次（之后每次跳转都**触发**它） |

**⭐ 关键认知**：**切换页面不会重新执行 `main.js`**。
页面切换是 router 在内部替换 `<router-view />` 的内容。

# 4.3 三件套：`index.html` + `main.js` + `App.vue`

## ① `public/index.html`（唯一的 HTML）

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <link rel="icon" href="<%= BASE_URL %>favicon.ico" />
    <title><%= webpackConfig.name %></title>
    <style>
      /* 首屏加载动画（几个转圈的点） */
    </style>
  </head>
  <body>
    <!-- ★★★ 挂载点 ★★★ -->
    <div id="app">
      <div class="first-loading-wrp">
        <div class="loading-wrp">
          <span class="dot dot-spin"><i></i><i></i><i></i><i></i></span>
        </div>
        <div>系统加载中</div>
      </div>
    </div>
  </body>
</html>
```

### ⭐ 三个要点

#### 要点 1：`<%= %>` 是打包时替换的模板语法

```html
<%= BASE_URL %>            →  打包后变成 '/'
<%= webpackConfig.name %>  →  打包后变成 '合同管理系统'
```

**这不是 Vue 的语法，是 webpack 的 html 模板语法**（EJS 风格）。

#### 要点 2：为什么要有"系统加载中"

**因为 Vue 还没加载完时页面是空白的**（只有 `<div id="app"></div>`）。
用户会以为卡死了。

所以先把一段纯 CSS 的加载动画写死在 html 里兜底，
等 JS 加载完、Vue 接管后，整个内容被替换掉。

#### 要点 3：这里**没有** `<script src="main.js">`

**那 JS 怎么加载的？**

**打包时 webpack 会自动插入**（`html-webpack-plugin` 干的）。

所以你在**源码**里看不到，打包后的 `dist/index.html` 里才有：

```html
<script src="/static/js/chunk-vendors.abc123.js"></script>
<script src="/static/js/app.def456.js"></script>
```

**⭐ `Vue.prototype.xxx = yyy` 的作用**：往**所有组件**身上挂方法。

```javascript
// 挂了之后，任何组件都能
this.parseTime(new Date())        // 不需要 import
```

**类比 Java**：相当于给一个基类加了个公共方法，所有子类都能用。

**⚠️ 副作用**：挂得越多，看页面代码时越不知道 `this.xxx` 从哪来。
这是 RuoYi 系列的编码习惯，**不是 Vue 官方推荐做法**（官方更推荐按需 import）。

### 事 3：创建根实例

```javascript
Vue.config.productionTip = false

new Vue({
  el: "#app",                    // ★ 挂到 index.html 的 #app
  router,
  store,
  render: (h) => h(App),         // ★ 渲染 App 组件
})
```

**⭐ 这是全应用唯一一次 `new Vue()`。**

| 参数 | 作用 |
|---|---|
| `el: "#app"` | 挂载到 `index.html` 里那个 `<div id="app">` |
| `router` | 注入路由，之后所有组件能用 `this.$router` / `this.$route` |
| `store` | 注入状态仓库，之后能用 `this.$store` |
| `render: h => h(App)` | 渲染 `App` 组件（`h` 是"创建虚拟节点"的函数） |

**`h` 是什么？**

```javascript
render: (h) => h(App)
// 等价于
render: function(h) {
  return h(App)       // 创建 App 组件的虚拟 DOM
}
```

**`h` = hyperscript**（创建"虚拟 DOM 节点"的函数）。

**⭐ 为什么不写 `template: '<App />'`？** 因为 `render` 函数的性能更好，
而且不需要运行时编译器（Vue 有"完整版"和"运行时版"，运行时版更小）。

## ③ `src/App.vue`（根组件，18 行）

```vue
<template>
  <div id="app">
    <router-view />          <!-- ★ 当前路由对应的页面在这里显示 -->
  </div>
</template>

<script>
export default {
  name: 'App',
  metaInfo() {              // vue-meta 插件：动态设置浏览器标签页标题
    return {
      title: this.$store.state.settings.dynamicTitle && this.$store.state.settings.title,
      titleTemplate: title => {
        return title ? `${title} - ${process.env.VUE_APP_TITLE}` : process.env.VUE_APP_TITLE
      }
    }
  }
}
</script>
```

**`App.vue` 只做两件事**：

1. 提供 `<router-view />` 占位（所有页面的最外层容器）
2. 用 `vue-meta` 动态设置浏览器标题

**⭐ `<router-view />` 是什么？**

它是**路由的"出口"**：当前 URL 匹配到哪个组件，就在这个位置渲染那个组件。

```
访问 /
  → App.vue 渲染 → <router-view /> 发现匹配到 index.vue
    → 在 <router-view /> 位置渲染 index.vue
```

## 三层结构串起来

```
index.html
  └─ <div id="app">
        └─ App.vue（根组件）
              └─ <router-view />
                    └─ layout/index.vue（如果路由配了 component: Layout）
                          ├─ <sidebar />       侧边栏
                          ├─ <navbar />        顶栏
                          ├─ <tags-view />     标签页
                          └─ <app-main>
                                └─ <router-view />   ← 业务页面
                                      └─ views/contract/contractDraft/index.vue
```

**⭐ 这就是"嵌套路由"**：`Layout` 是共用的装修，业务页面是桌面上的具体内容。

# 4.4 路由表（`router/index.js`）

## 两个数组

```javascript
// src/router/index.js

// ① 固定路由（不用权限，启动就注册）
export const constantRoutes = [
  { path: '/redirect', component: Layout, hidden: true, children: [...] },
  { path: '/login', component: () => import('@/views/login'), hidden: true },
  { path: '/register', component: () => import('@/views/register'), hidden: true },
  { path: '/404', component: () => import('@/views/error/404'), hidden: true },
  { path: '/401', component: () => import('@/views/error/401'), hidden: true },

  // ★ 首页
  {
    path: '',
    component: Layout,
    redirect: '/index',
    children: [
      {
        path: 'index',
        component: () => import('@/views/index'),
        name: 'Index',
        meta: { title: '首页', icon: 'dashboard', affix: true }
      }
    ]
  },

  // ★ 个人中心
  { path: '/user', component: Layout, hidden: true, redirect: 'noredirect', children: [...] },
]

// ② 动态路由（需要权限，登录后过滤再注册）
export const dynamicRoutes = [
  {
    path: '/system/role-auth',
    component: Layout,
    hidden: true,
    permissions: ['system:role:edit'],         // ★ 权限码
    children: [
      { path: 'user/:roleId(\\d+)', component: () => import('@/views/system/role/authUser'), ... }
    ]
  },
  {
    path: '/tool/gen-edit',
    component: Layout,
    hidden: true,
    permissions: ['tool:gen:edit'],
    children: [...]
  },
  // ...
]

// ③ 创建 router 实例
export default new Router({
  mode: 'history',                 // ★ URL 没有 #（需要 Nginx try_files）
  scrollBehavior: () => ({ y: 0 }),
  routes: constantRoutes
})
```

## ⭐ 两个数组的区别（重要）

| | `constantRoutes` | `dynamicRoutes` |
|---|---|---|
| 什么时候注册 | **应用启动时** | **登录后**按权限过滤 |
| 需要权限吗 | ❌ 不需要 | ✅ 需要（`permissions` / `roles`） |
| 内容 | 登录页、404、首页、个人中心 | 分配用户、字典数据、代码生成编辑 |
| 谁能访问 | 所有人（未登录走白名单） | 有对应权限码的人 |

## ⭐ 逐字段解释（重点）

```javascript
{
  path: '',                        // 空路径容器
  component: Layout,               // 套后台框架
  redirect: '/index',              // 访问 / 时跳到 /index
  children: [
    {
      path: 'index',               // 相对路径（不带 /）→ 拼成 /index
      component: () => import('@/views/index'),   // 懒加载
      name: 'Index',               // ★ keep-alive 缓存要靠它
      meta: {
        title: '首页',             // 侧边栏/面包屑显示的文字
        icon: 'dashboard',         // 侧边栏图标（对应 src/assets/icons/svg/dashboard.svg）
        affix: true                // ★ 标签页固定，不可关闭
      }
    }
  ]
}
```

### `path: ''` 为什么不是 `/`

```javascript
path: ''          // 空路径容器
redirect: '/index'
```

**效果**：用户访问 `/` 时 → 自动跳到 `/index`。

### ⭐ 子路由 `path` 带不带 `/` 的区别

| 写法 | 含义 | 父 `path` 为 `''` 时的最终 URL |
|---|---|---|
| `path: 'index'` | **相对路径**，拼到父后面 | `/index` |
| `path: '/index'` | **绝对路径**，忽略父级 | `/index` |

**这个项目里首页用的是 `'index'`（相对）**，
好处是如果父级改成 `/home`，子级自动变成 `/home/index`。

### 拼接算法（vue-router 的 `resolvePath`）

```javascript
// 简化版
if (path.charAt(0) === '/') return path          // 以 / 开头 → 绝对路径
if (path === '') return base                     // 空 → 用父路径
return cleanPath(`${base}/${path}`)              // 否则 → 父 + '/' + 子

// 所以：'' + 'index' → '/index' ✅
```

### `meta` 里的字段（自己定义的）

| 字段 | 作用 | 被谁读 |
|---|---|---|
| `title` | 侧边栏/面包屑/标签页文字 | `Sidebar/Item.vue`、`TagsView` |
| `icon` | 侧边栏图标名 | `Sidebar/Item.vue` |
| **`affix`** | **标签页固定，不可关闭** | `TagsView`、`store/tagsView.js` |
| `noCache` | 不缓存（`keep-alive` 排除） | `AppMain.vue` |
| `breadcrumb` | 是否显示在面包屑 | 面包屑组件 |
| `activeMenu` | 高亮哪个菜单（用于隐藏页） | `Sidebar/index.vue` |

#### ⭐ `affix: true` 的效果

```javascript
// src/layout/components/TagsView/index.vue:105
if (route.meta && route.meta.affix) {
  // 这是个 affix 路由，要"钉"在标签页上
}

// src/store/modules/tagsView.js:51-52
const affixTags = state.visitedViews.filter(tag => tag.meta.affix)
state.visitedViews = affixTags        // "关闭其他"时保留它们
```

| 行为 | 没有 `affix` | 有 `affix: true` |
|---|---|---|
| 标签上的 ✕ 关闭按钮 | 有 | **没有** |
| "关闭所有标签" | 被关掉 | **保留** |
| "关闭其他标签" | 被关掉 | **保留** |
| 刚登录时 | 要点菜单才出现 | **自动出现** |

**为什么首页要 `affix`？** 用户点了一堆标签，如果把首页也关了，
标签栏会空，**没有"回家的路"**。

#### `icon: 'dashboard'` 的图标在哪

```
src/assets/icons/svg/dashboard.svg
```

**机制**（`vue.config.js` 配的 `svg-sprite-loader`）：

```javascript
.use('svg-sprite-loader')
.loader('svg-sprite-loader')
.options({ symbolId: 'icon-[name]' })     // 把 svg 变成 <symbol id="icon-dashboard">
```

然后 `main.js` 的 `import "./assets/icons"` 会**自动注册所有 svg**。

**⚠️ 如果 svg 文件不存在**：菜单**不报错**，只是图标位置空白。
这是"看起来没生效"的常见原因。

### `mode: 'history'`

```javascript
export default new Router({
  mode: 'history',           // ★ URL 没有 #
  scrollBehavior: () => ({ y: 0 }),
  routes: constantRoutes
})
```

**两种模式对比**：

| 模式 | URL 样子 | 需要服务端配置吗 |
|---|---|---|
| `hash` | `http://localhost/#/contract/contractDraft` | ❌ 不需要 |
| **`history`** | `http://localhost/contract/contractDraft` | ✅ **需要 Nginx `try_files`** |

**⚠️ history 模式的坑**：用户直接访问 `/contract/contractDraft` 刷新，
Nginx 会去找这个物理文件 → 找不到 → **404**。

**解决**：Nginx 配 `try_files $uri $uri/ /index.html;`

**这个项目用的是 history 模式**（URL 更干净）。

## ⭐ `AppMain.vue`（56 行）—— 业务页面的真正入口

```vue
<template>
  <section class="app-main">
    <transition name="fade-transform" mode="out-in">
      <keep-alive :include="cachedViews">
        <router-view :key="key" />
      </keep-alive>
    </transition>
  </section>
</template>

<script>
export default {
  name: 'AppMain',
  computed: {
    cachedViews() {
      return this.$store.state.tagsView.cachedViews     // 需要缓存的页面名
    },
    key() {
      return this.$route.path                            // 路径变化就重新渲染
    }
  }
}
</script>
```

### 三个关键点

#### ① `<router-view />` 就是"业务页面的出口"

**完整嵌套关系**：

```
App.vue 的 <router-view />
  → 匹配到 /contract/contractDraft
    → 渲染 layout/index.vue（因为路由配了 component: Layout）
      → layout 里的 <app-main />
        → AppMain.vue 里的 <router-view />
          → 渲染 views/contract/contractDraft/index.vue
```

#### ② `<keep-alive>` 缓存

```vue
<keep-alive :include="cachedViews">
  <router-view :key="key" />
</keep-alive>
```

**`keep-alive` 的作用**：把组件**保留在内存里**，切走再切回来时**不重新创建**。

**类比**：像浏览器标签页——切到别的标签，原来的页面状态还在。

**`include` 指定哪些组件要缓存**（存的是**组件名**）。

**`cachedViews` 从哪来？** `store/modules/tagsView.js`：

```javascript
// 添加标签时
if (!v.meta.noCache) {           // meta 里没写 noCache 就缓存
  state.cachedViews.push(v.name)
}
```

**⚠️ 关键**：`cachedViews` 里存的是**组件的 `name`**（不是路由的 `name`）。

**所以路由的 `name` 和组件的 `name` 最好写成一样**，否则缓存不生效。

#### ③ `:key="key"` 为什么要加

```javascript
key() {
  return this.$route.path        // 路径变了 key 就变
}
```

**作用**：强制组件**重新创建**（而不是复用）。

**场景**：从 `/contract/detail/1` 跳到 `/contract/detail/2`，
如果 key 不变，Vue 会**复用**同一个组件实例，`created()` 不会重新执行。

用 `path` 当 key，路径一变就重新创建。

## 侧边栏怎么渲染菜单

```vue
<!-- layout/components/Sidebar/index.vue -->
<template>
  <div :class="{ 'has-logo': showLogo }">
    <logo v-if="showLogo" :collapse="isCollapse" />
    <el-scrollbar :class="settings.sideTheme" wrap-class="scrollbar-wrapper">
      <el-menu
        :default-active="activeMenu"
        :collapse="isCollapse"
        :unique-opened="true"
        mode="vertical"
      >
        <!-- ★ 循环渲染菜单 -->
        <sidebar-item
          v-for="(route, index) in sidebarRouters"
          :key="route.path + index"
          :item="route"
          :base-path="route.path"
        />
      </el-menu>
    </el-scrollbar>
  </div>
</template>

<script>
import { mapGetters, mapState } from "vuex";

export default {
  components: { SidebarItem, Logo },
  computed: {
    ...mapState(["settings"]),
    ...mapGetters(["sidebarRouters", "sidebar"]),    // ★ 菜单数据
    activeMenu() {
      const route = this.$route;
      const { meta, path } = route;
      if (meta.activeMenu) return meta.activeMenu;    // 隐藏页高亮指定菜单
      return path;
    },
    isCollapse() {
      return !this.sidebar.opened;                    // 折叠状态
    }
  }
}
</script>
```

**⭐ `sidebarRouters` 从哪来？**

```
后端 GET /getRouters
  → store/modules/permission.js 的 filterAsyncRouter()
    → commit('SET_SIDEBAR_ROUTERS', constantRoutes.concat(sidebarRoutes))
      → store.getters.sidebarRouters
        → Sidebar/index.vue 的 v-for
```

**所以：后端菜单表 → 侧边栏，一条链。**

### `SidebarItem.vue` 的逻辑（109 行）

```vue
<template>
  <!-- 情况 1：只有一个子菜单 → 直接渲染成菜单项 -->
  <template v-if="hasOneShowingChild(item.children,item) && (!onlyOneChild.children||onlyOneChild.noShowingChildren)&&!item.alwaysShow">
    <app-link v-if="onlyOneChild.meta" :to="resolvePath(onlyOneChild.path, onlyOneChild.query)">
      <el-menu-item :index="resolvePath(onlyOneChild.path)" :class="{'submenu-title-noDropdown':!isNest}">
        <item
          :icon="onlyOneChild.meta.icon||(item.meta&&item.meta.icon)"
          :title="onlyOneChild.meta.title"
          :show-num="onlyOneChild.meta.showNum"
          :is-top="onlyOneChild.meta.isTop"
          :sidebar="sidebar"
        />
      </el-menu-item>
    </app-link>
  </template>

  <!-- 情况 2：有多个子菜单 → 渲染成可展开的父菜单 -->
  <el-submenu v-else ref="subMenu" :index="resolvePath(item.path)" popper-append-to-body>
    <template slot="title">
      <item v-if="item.meta" :icon="item.meta && item.meta.icon" :title="item.meta.title" ... />
    </template>
    <sidebar-item
      v-for="child in item.children"
      :key="child.path"
      :is-nest="true"
      :item="child"
      :base-path="resolvePath(child.path)"
      class="nest-menu"
    />
  </el-submenu>
</template>
```

**⭐ `hasOneShowingChild` 的用意**：

如果一个目录下**只有一个**可见子菜单，就不显示那层目录，**直接把子菜单提上来**（避免"点两层才到页面"）。

**这是 RuoYi 的经典处理**，`alwaysShow: true` 可以强制显示父菜单。

## ⭐ 为什么刷新才生效

因为菜单是**登录时（或首次进入时）**从后端拉一次的。

`roles` 已经有值 → **不会重新拉**。所以要刷新页面（清空 store）。
