# 5.0 先看全局：一次请求经过 7 个"站"

```
① 页面（login.vue）
   this.$store.dispatch('Login', this.loginForm)
        ↓
② 状态仓库（store/modules/user.js 的 Login action）
   login(username, password, code, uuid, tenantId)
        ↓
③ 接口声明（api/login.js 的 login 函数）
   request({ url:'/login', headers:{isToken:false}, method:'post', data })
        ↓
④ 请求拦截器（utils/request.js）
   判断 isToken:false → 不加 token
   POST 请求 → 检查重复提交
        ↓
⑤ 浏览器发出
   POST http://localhost/dev-api/login
        ↓ devServer 代理剥掉 /dev-api
   POST http://localhost:8080/login
        ↓
⑥ 后端（LoginController）
   校验账号密码验证码 → 生成 token → 返回
        ↓
⑦ 响应拦截器（utils/request.js）
   code === 200 → return res.data
        ↓
⑧ 回到 store（user.js）
   setToken(res.data.token)  ← ★ 写进 Cookie
   commit('SET_TOKEN', token)
        ↓
⑨ 回到页面（login.vue）
   this.$router.push({ path: '/' })   ← 跳转
```

**⭐ 记住这个顺序，后面每一节就对应其中一站。**

**关键认知**：**页面不直接发请求**，它只调 store；**store 不拼 URL**，它只调 api；
**api 不处理 token**，它交给拦截器。

**每一层只做一件事**——这就是分层。

# 5.1 第①站：用户点登录按钮（`views/login.vue`）

## 页面上的按钮

```html
<!-- src/views/login.vue ≈ 第 115 行 -->
<el-button
  :loading="loading"
  size="default"
  type="primary"
  style="width: 100%"
  @click.native.prevent="handleLogin"
>
  <span v-if="!loading">登 录</span>
  <span v-else>登 录 中...</span>
</el-button>
```

### 逐行解释

| 代码 | 含义 |
|---|---|
| `:loading="loading"` | 按钮显示转圈（`loading` 为 true 时） |
| `@click.native.prevent="handleLogin"` | 点击时调 `handleLogin()` |
| `v-if="!loading"` / `v-else` | 根据 loading 切换文字 |

**⭐ `@click.native.prevent` 里的 `.native` 和 `.prevent` 是什么？**

| 修饰符 | 作用 |
|---|---|
| `.native` | 绑定到**原生** DOM 事件（因为 `el-button` 是组件，不是原生 button） |
| `.prevent` | 等同于 `event.preventDefault()`，阻止默认行为 |

**类比**：`@click.native.prevent` ≈ 原生 JS 的 `addEventListener('click', e => { e.preventDefault(); ... })`

**为什么需要 `.native`？** 因为 `el-button` 是 Element UI 的组件，
`@click` 默认监听的是组件**内部 emit 的自定义事件**。
加 `.native` 才是监听真正的 DOM click。

## 用户的输入存在哪

```javascript
// src/views/login.vue 的 data()
data() {
  return {
    loginForm: {
      username: "zxcmAdmin",
      password: "123456",        // 或者空
      rememberMe: false,
      code: "",
      uuid: "",
      tenantId: undefined
    },
    loginRules: {
      username: [{ required: true, trigger: "blur", message: "请输入您的账号" }],
      password: [{ required: true, trigger: "blur", message: "请输入您的密码" }],
      code: [{ required: true, trigger: "change", message: "请输入验证码" }]
    },
    loading: false,
    captchaOnOff: true,
    codeUrl: "",
    redirect: undefined,
    tenantList: []
  }
}
```

### 关键字段

| 字段 | 用途 |
|---|---|
| `loginForm` | **表单数据**（`v-model` 绑到输入框上） |
| `loginRules` | **校验规则**（Element UI 自动校验） |
| `loading` | 按钮转圈状态 |
| `codeUrl` | 验证码图片的 base64 |
| `redirect` | 登录成功后跳去哪（从 URL 的 `?redirect=` 读） |
| `tenantList` | 多租户系统：用户名属于多个租户时，让他选 |

### ⭐ `v-model` 双向绑定

```html
<el-input v-model="loginForm.username" placeholder="账号" />
```

**双向**：

- 用户打字 → `loginForm.username` **自动更新**
- 代码里改 `loginForm.username` → **输入框内容自动变**

**这就是为什么不需要 `document.getElementById('xxx').value`** —— 数据驱动。

## 页面加载时做了什么

```javascript
// src/views/login.vue 的 created()
created() {
  this.getCode()                                    // ① 拿验证码
  this.getCookie()                                  // ② 读"记住密码"
  this.$store.dispatch('settings/getCompanyConfig') // ③ 拿公司配置（名称、logo）

```

**⭐ `created()` 是 Vue 的生命周期钩子**：组件创建完成、还没渲染到页面时执行。

## `getCode()` —— 拿验证码

```javascript
getCode() {
  getCodeImg().then((res) => {
    this.captchaOnOff =
      res.data.captchaOnOff === undefined ? true : res.data.captchaOnOff
    if (this.captchaOnOff) {
      this.codeUrl = 'data:image/gif;base64,' + res.data.img
      this.loginForm.uuid = res.data.uuid
    }
  })
}
```

### 逐行解释

```javascript
getCodeImg()
// ↑ 来自 src/api/login.js，发 GET /captchaImage（带 isToken:false）

.then((res) => {
// res = 响应拦截器返回的 res.data，即 { code, data: { captchaOnOff, img, uuid } }

  this.captchaOnOff = res.data.captchaOnOff === undefined ? true : res.data.captchaOnOff
// ↑ 后端可能配置了"关闭验证码"。没配就当 true（开启）
//   ⚠️ 为什么用 === undefined 而不是 || true？
//     因为如果 captchaOnOff 是 false（关闭验证码），|| true 会错变成 true

  if (this.captchaOnOff) {
    this.codeUrl = 'data:image/gif;base64,' + res.data.img
//  ↑ 图片是 base64 字符串，拼成 data URI 直接给 <img src> 用
//    这样不用再发一次请求拿图片

    this.loginForm.uuid = res.data.uuid
//  ↑ ★ 关键：uuid 是这次验证码的唯一标识，登录时必须一起传回后端
//    后端靠它查出"这个 uuid 对应的正确答案"来比对
  }
})
```

### ⭐ 为什么需要 `uuid`

**问题**：后端怎么知道"用户输入的验证码对不对"？

**答案**：后端生成验证码时，把答案存进 Redis，key 就是 `uuid`：

```
Redis:  captcha_codes:{uuid}  →  "3+5=?" 的答案 "8"   （5 分钟过期）
```

登录时前端把 `uuid` + 用户输入的 `code` 一起传回，后端：

```java
// 后端伪代码
String expected = redis.get("captcha_codes:" + uuid);
if (!expected.equalsIgnoreCase(code)) {
    throw new ServiceException("验证码错误");
}
```

**所以 `uuid` 是"这次验证码的身份证"。**

## `getCookie()` —— 读"记住密码"

```javascript
getCookie() {
  const username = Cookies.get('username')
  const password = Cookies.get('password')
  const rememberMe = Cookies.get('rememberMe')
  const tenantId = Cookies.get('tenantId')

  this.loginForm = {
    username: username === undefined ? this.loginForm.username : username,
    password: password === undefined ? this.loginForm.password : decrypt(password),
    rememberMe: rememberMe === undefined ? false : Boolean(rememberMe),
    tenantId: tenantId === undefined ? this.loginForm.tenantId : tenantId
  }
}
```

**用途**：上次勾了"记住密码"，这次打开就自动填上。

**⭐ 注意 `decrypt(password)`**：Cookie 里的密码是**加密存**的（`jsencrypt`），
读出来要**解密**才能用。

**⚠️ 安全提醒**：虽然加密了，但把密码存在 Cookie 里仍然有风险
（加密只是防"明文可见"，防不了"别人拿到你的电脑"）。这是项目的一个设计问题。

## `handleLogin()` —— 点击登录

```javascript
handleLogin() {
  this.$refs.loginForm.validate((valid) => {
    if (valid) {
      this.loading = true

      // ① 处理"记住密码"
      if (this.loginForm.rememberMe) {
        Cookies.set('username', this.loginForm.username, { expires: 30 })
        Cookies.set('password', encrypt(this.loginForm.password), { expires: 30 })
        Cookies.set('rememberMe', this.loginForm.rememberMe, { expires: 30 })
        Cookies.set('tenantId', this.loginForm.tenantId, { expires: 30 })
      } else {
        Cookies.remove('username')
        Cookies.remove('password')
        Cookies.remove('rememberMe')
        Cookies.remove('tenantId')
      }

      // ② 处理"选租户"
      if (!this.loginForm.tenantId) {
        if (this.tenantList.length > 0) {
          this.$modal.msgWarning('请选择账户所属租户')
          return
        }
        getTenantList(this.loginForm.username).then((response) => {
          if (response.data.length == 0) {
            this.$modal.msgError('账户信息不存在，请检查登录名是否正确')
            this.loading = false
            return
          } else if (response.data.length == 1) {
            this.loginForm.tenantId = response.data[0].tenantId     // 只有一个，自动选
          } else {
            this.tenantList = response.data                          // 多个，让用户选
            this.$modal.msgWarning('请选择账户所属租户')
            this.loading = false
            return
          }
          this.login()                                              // ③ 真正登录
        })
      } else {
        this.login()
      }
    }
  })
}
```

### 三段逻辑

#### ① 表单校验（`validate`）

```javascript
this.$refs.loginForm.validate((valid) => {
  if (valid) { /* 校验通过，继续 */ }
})
```

| 部分 | 含义 |
|---|---|
| `this.$refs.loginForm` | 拿到页面上 `ref="loginForm"` 那个 `<el-form>` 组件 |
| `.validate(callback)` | 按 `loginRules` 校验，把结果传给回调 |
| `valid` | `true` = 校验通过 |

**`$refs` 是什么？** 相当于"给组件起个名字，之后能直接拿到它"。

```html
<el-form ref="loginForm" :model="loginForm" :rules="loginRules">
```

**类比 Java**：`@Autowired` 拿到一个 bean 引用。

#### ② 记住密码（Cookie）

```javascript
Cookies.set('username', value, { expires: 30 })    // 30 天后过期
Cookies.remove('username')
```

**⚠️ 这里可以把 `encrypt(password)` 和 `decrypt(password)` 对照看**：

- 存的时候 `encrypt`（加密）
- 读的时候 `decrypt`（解密）

用的是 `jsencrypt`（RSA 加密库），见 `src/utils/jsencrypt.js`。

#### ③ 选租户（多租户系统特有）

**这是什么业务？** 这个项目是**多租户（SaaS）**系统——
一个公司一个租户，同一个用户名可能属于多个公司。

```
用户名 zxcmAdmin
  → 属于租户 A（山西肇新）
  → 属于租户 B（测试公司）
  → 必须让用户选一个，否则后端不知道该登进哪个公司
```

**三种情况**：

| `response.data.length` | 处理 |
|---|---|
| `0` | 报错"账户信息不存在" |
| `1` | **自动选**（不用打扰用户） |
| `> 1` | 显示下拉框让用户选 |

**⭐ `return` 的作用**：提前结束函数（不继续往下执行）。

```javascript
if (response.data.length == 0) {
  this.$modal.msgError('...')
  this.loading = false
  return                    // ← 后面的代码不执行了
}
```

## `login()` —— 真正发起登录

```javascript
login() {
  this.$store
    .dispatch('Login', this.loginForm)      // ★ 把活交给 store
    .then(() => {
      this.$router.push({ path: this.redirect || '/' }).catch(() => { })
    })
    .catch(() => {
      this.loading = false
      if (this.captchaOnOff) {
        this.getCode()                       // 登录失败 → 刷新验证码
      }
    })
}
```

### 三个关键点

#### ① `dispatch('Login', ...)` 把活交给 store

**为什么不在这里直接调 `api/login.js`？**

因为 `Login` 这个动作包含多步：调接口 → 存 token → 存 state。
**这些"业务编排"放在 store 里**，页面只管"调用 + 跳转"。

#### ② `.then()` 里跳转

```javascript
.then(() => {
  this.$router.push({ path: this.redirect || '/' })
})
```

**⭐ `this.redirect` 是从 URL 的 `?redirect=` 读的**：

```javascript
// created() 里
watch: {
  $route: {
    handler: function (route) {
      this.redirect = route.query && route.query.redirect
    },
    immediate: true
  }
}
```

**场景**：用户直接访问 `/contract/contractDraft` → 没登录 → 被踢到 `/login?redirect=/contract/contractDraft`
→ 登录成功后**跳回 `/contract/contractDraft`**（而不是首页）。

#### ③ `.catch()` 里刷新验证码

```javascript
.catch(() => {
  this.loading = false
  if (this.captchaOnOff) {
    this.getCode()          // ← 登录失败，验证码已经失效，要换新的
  }
})
```

**为什么？** 验证码是**一次性**的（后端校验后就从 Redis 删了），
登录失败再用同一个验证码会报"验证码错误"。

# 5.2 第②站：store 接手（`store/modules/user.js`）

```javascript
// src/store/modules/user.js:49
Login({ commit }, userInfo) {
  const username = userInfo.username.trim()
  const password = userInfo.password
  const code = userInfo.code
  const uuid = userInfo.uuid
  const tenantId = userInfo.tenantId

  return new Promise((resolve, reject) => {
    login(username, password, code, uuid, tenantId).then(res => {
      setToken(res.data.token)                 // ★★★ 写 Cookie
      commit('SET_TOKEN', res.data.token)      // ★ 写 state
      resolve()
    }).catch(error => {
      reject(error)
    })
  })
}
```

## 逐段解释

### ① 参数解构

```javascript
Login({ commit }, userInfo) {
//     ↑ 只取 context 里的 commit
```

**Vuex 传给 action 的第一个参数**是一个上下文对象：

```javascript
{
  commit:   function,     // 触发 mutation
  dispatch: function,     // 触发别的 action
  state:    object,       // 当前模块的 state
  getters:  object,
  rootState: object,
  rootGetters: object
}
```

**解构 `{ commit }` = 只取 commit**，后面写 `commit('SET_TOKEN', ...)` 而不是 `context.commit(...)`。

### ② `.trim()` 只对 username

```javascript
const username = userInfo.username.trim()
const password = userInfo.password              // ← 没 trim
```

**为什么密码不 trim？** 因为密码里的空格**可能是用户故意设的**，
去掉了他反而登录失败。这是**正确的做法**。

### ③ 五个参数分别是什么

| 参数 | 来源 | 后端用来做什么 |
|---|---|---|
| `username` | 输入框 | 查用户 |
| `password` | 输入框 | 校验密码 |
| `code` | 输入框 | 验证码（用户输入的） |
| `uuid` | `getCode()` 拿的 | 找出"这次验证码的正确答案" |
| `tenantId` | 下拉框选 / 自动查 | 决定登进哪个公司 |

### ④ `new Promise` 包装

```javascript
return new Promise((resolve, reject) => {
  login(...).then(res => { ...; resolve() }).catch(err => reject(err))
})
```

**⭐ 为什么要包一层？** 因为调用方（`login.vue`）要 `.then()`：

```javascript
this.$store.dispatch('Login', this.loginForm).then(() => { /* 跳转 */ })
```

**如果 action 不返回 Promise**，`.then()` 会报错（`undefined.then is not a function`）。

**💡 其实可以简化**（现代写法）：

```javascript
Login({ commit }, userInfo) {
  return login(...).then(res => {
    setToken(res.data.token)
    commit('SET_TOKEN', res.data.token)
  })
}
```

**因为 `.then()` 本身返回 Promise。** 外面那层 `new Promise` 是多余的（RuoYi 的历史写法）。

**你写新代码时用简化版就行。**

### ⑤ `setToken` 和 `commit` 是两件事

```javascript
setToken(res.data.token)                 // ① 写 Cookie（持久化）
commit('SET_TOKEN', res.data.token)      // ② 写 state（内存，响应式）
```

**为什么要存两份？**

| 存哪 | 用途 | 刷新后 |
|---|---|---|
| **Cookie** | `request.js` 里 `getToken()` 读它加请求头 | ✅ **还在** |
| **state** | 组件里 `this.$store.getters.token` 响应式使用 | ❌ 没了 |

**⭐ 这是关键设计**：Cookie 负责"持久"，state 负责"响应式"。

`setToken` 的实现（`src/utils/auth.js`）：

```javascript
import Cookies from 'js-cookie'

const TokenKey = 'Admin-Token'

export function setToken(token) {
  return Cookies.set(TokenKey, token)
}

export function getToken() {
  return Cookies.get(TokenKey)
}
```

**就这么简单——Cookie 的 key 叫 `Admin-Token`。**

# 5.3 第③站：接口声明（`api/login.js`）

```javascript
// src/api/login.js:5
export function login(username, password, code, uuid, tenantId) {
  const data = {
    username,
    password,
    code,
    uuid,
    tenantId
  }
  return request({
    url: '/login',
    headers: {
      isToken: false                    // ★★★ 关键
    },
    method: 'post',
    data: data
  })
}
```

## 三个要点

### ① `url: '/login'` 是相对路径

**完整 URL 由 `request.js` 的 `baseURL` 拼**：

```
baseURL('/dev-api') + url('/login')  =  '/dev-api/login'
```

**⚠️ 这里不能写完整地址**（如 `http://localhost:8080/login`），
否则会绕过代理，直接触发跨域。

### ② `headers: { isToken: false }` —— 让拦截器不要加 token

**这是登录接口的特殊之处**：此时**还没有 token**，
如果拦截器硬加一个 `token: 'Bearer undefined'`，后端会判为非法。

**拦截器里怎么读这个标记**（`src/utils/request.js:29`）：

```javascript
const isToken = (config.headers || {}).isToken === false
if (getToken() && !isToken) {          // ← isToken 为 true 就跳过
  config.headers['token'] = 'Bearer ' + getToken()
}
```

### ③ `method: 'post'` + `data`

| 字段 | 含义 |
|---|---|
| `method: 'post'` | POST 请求 |
| `data: data` | 参数放**请求体**（JSON） |

**⭐ 如果写成 `params` 会怎样？**

```javascript
// ❌ 错误
return request({
  url: '/login',
  method: 'post',
  params: data          // 参数会被拼到 URL 上！
})
// 实际请求：POST /dev-api/login?username=xxx&password=xxx
// 后端 @RequestBody 收不到（因为它在请求体里找）
```

**规则**：

| method | 用哪个 |
|---|---|
| GET | `params` |
| POST / PUT | `data` |

## 完整调用链

## 这次的执行路径

登录请求是 `POST` + `isToken: false`，所以：

| 步骤 | 会不会执行 | 原因 |
|---|---|---|
| ① 读开关 | ✅ | 总是执行 |
| ② 加 token | ❌ **跳过** | `isToken === false` → `!isToken` = false |
| ③ 拼 GET 参数 | ❌ **跳过** | 这次是 POST |
| ④ 防重复提交 | ✅ **执行** | POST 且没写 `repeatSubmit: false` |
| `return config` | ✅ | 必须 |

## ④ 防重复提交（这次会跑）

```javascript
if (!isRepeatSubmit && (config.method === 'post' || config.method === 'put')) {
  const requestObj = {
    url: config.url,
    data: typeof config.data === 'object' ? JSON.stringify(config.data) : config.data,
    time: new Date().getTime()
  }
  const sessionObj = cache.session.getJSON('sessionObj')

  if (sessionObj === undefined || sessionObj === null || sessionObj === '') {
    cache.session.setJSON('sessionObj', requestObj)
  } else {
    const interval = 1000
    if (s_data === requestObj.data && requestObj.time - s_time < interval && s_url === requestObj.url) {
      const message = '数据正在处理，请勿重复提交'
      console.warn(`[${s_url}]: ` + message)
      return Promise.reject(new Error(message))
    } else {
      cache.session.setJSON('sessionObj', requestObj)
    }
  }
}
```

### 对登录的实际影响

**场景**：用户连点两次"登录"按钮（间隔 < 1 秒）

```
第 1 次点击：
  requestObj = { url:'/login', data:'{"username":"zxcmAdmin",...}', time:1000 }
  sessionStorage 里没有记录 → 存进去 → 放行

第 2 次点击（比如 800ms 后）：
  requestObj = { url:'/login', data:'同一串', time:1800 }
  sessionObj 存在，且：
    数据相同 ✅
    1800 - 1000 = 800 < 1000 ✅
    url 相同 ✅
  → Promise.reject('数据正在处理，请勿重复提交')
```

**用户看到**：弹一条红色提示"数据正在处理，请勿重复提交"（由响应拦截器弹出）。

**⚠️ 但有个副作用**：因为 `loading` 只在 `.catch()` 里设回 false，
而这个 reject 会走 `login()` 的 `.catch()`，所以 `loading` 会正常恢复。

**✅ 这个机制在登录场景是有效的。**

### ⚠️ 首次进入的坑

```javascript
if (sessionObj === undefined || sessionObj === null || sessionObj === '') {
  cache.session.setJSON('sessionObj', requestObj)
}
```

**第一次请求时 `sessionStorage` 是空的**，所以直接存，不拦截。

**但如果用户在 1 秒内换了账号再登录**（数据不同），不会被拦截（因为数据不同）。

**这是合理的**——换了内容就不是"重复"。

## 这次走的是哪条分支

```
code = 200
  ↓
不是 401 / 不是 500 / 等于 200
  ↓
return res.data
```

**返回的是**：

```javascript
{ code: 200, msg: '操作成功', data: { token: 'eyJhbGci...', expireIn: 186400 } }
```

**⭐ 注意：`res.data` 是"后端的整个响应体"，不是"后端的 data 字段"。**

容易混的一点：

| 表达式 | 是什么 |
|---|---|
| `res`（axios 的） | `{ data: {...}, status: 200, headers: {...} }` |
| `res.data`（axios 的） | **后端的整个响应体** `{ code, msg, data }` |
| `res.data.data` | 后端的 `data` 字段 |

**所以响应拦截器 `return res.data` 返回的是 `{ code, msg, data }`。**

**那为什么 store 里写 `res.data.token` 能拿到 token？**

```javascript
// user.js
login(...).then(res => {
  setToken(res.data.token)
```

因为：

- `res` = `{ code, msg, data: { token } }`
- `res.data` = `{ token, expireIn }`
- `res.data.token` = token ✅

**⚠️ 这里有命名歧义**：后端把业务数据放在 `data` 字段里，
而 axios 也把响应体叫 `data`。所以出现了 `res.data.data` 这种写法。

**项目里的证据**：

```javascript
// src/api/login.js 的 getInfo 返回值用法（user.js:70）
getInfo().then(res => {
  const user = res.data.user         // ← 后端返回 { data: { user, roles, permissions } }
  //       ↑ res.data 是后端的 data 字段
})
```

**⭐ 记忆法**：
- 响应拦截器 `return res.data` = 返回**后端响应体**（含 code/msg/data）
- 所以业务代码里要 `.data` 才能拿到**业务数据**

**⭐ 例外：分页接口**

```javascript
// 分页接口返回的是 { code, msg, rows, total }（没有 data）
listContractDraft(query).then(response => {
  this.contractDraftList = response.rows       // ← 直接取 rows，不是 response.data.rows
  this.total = response.total
})
```

**为什么不一样？** 因为后端分页用的是 `TableDataInfo`（`{ rows, total }`），
单条数据用的是 `R<T>`（`{ data }`）。**两种包装格式**。

## `this.$router.push()` 做什么

**切换路由（不刷新页面）**。

| 写法 | 效果 |
|---|---|
| `this.$router.push('/index')` | 跳到 `/index` |
| `this.$router.push({ path: '/index' })` | 同上 |
| `this.$router.push({ name: 'Index' })` | 按路由名跳转 |
| `this.$router.replace('/index')` | 跳转且**不留历史记录** |

## `.catch(() => {})` 为什么是空的

**因为 `$router.push` 返回 Promise，可能会 reject。**

**什么时候 reject？** 如果跳转的目标和当前路由**相同**，
Vue Router 3 会抛一个 `NavigationDuplicated` 错误。

**这是一个已知的"噪音错误"**，所以加个空 `.catch` 忽略掉。

**⭐ 你也可以写成**：

```javascript
this.$router.push({ path: this.redirect || '/' }).catch(err => {
  if (err.name !== 'NavigationDuplicated') throw err
})
```

**但项目里直接忽略了所有错误**（简单粗暴但不严谨）。

## 跳转之后发生什么

**这才是重点**：跳转**会触发路由守卫**（第 9 章）。

```
this.$router.push('/')
    ↓
permission.js 的 router.beforeEach 被触发
    ↓
发现有 token
    ↓
dispatch('GetInfo')        ← 第二个请求：拿用户信息
    ↓
dispatch('GenerateRoutes') ← 第三个请求：拿菜单
    ↓
router.addRoutes()         ← 动态注册路由
    ↓
next({...to, replace:true}) ← 重走一遍
    ↓
页面渲染
```

**⭐ 所以"登录成功后"并不是结束，而是下一阶段的开始。**

### `filterAsyncRouter` 的核心

```javascript
function filterAsyncRouter(asyncRouterMap, lastRouter = false, type = false) {
  return asyncRouterMap.filter(route => {
    if (route.component) {
      if (route.component === 'Layout') {
        route.component = Layout                        // 换成真实组件
      } else if (route.component === 'ParentView') {
        route.component = ParentView
      } else if (route.component === 'InnerLink') {
        route.component = InnerLink
      } else {
        route.component = loadView(route.component)     // ★ 业务页面
      }
    }
    if (route.children && route.children.length) {
      route.children = filterAsyncRouter(route.children, route, type)   // 递归
    }
    return true
  })
}
```

### `loadView` —— 字符串变组件

```javascript
export const loadView = (view) => {
  if (process.env.NODE_ENV === 'development') {
    return (resolve) => require([`@/views/${view}`], resolve)
  } else {
    return () => import(`@/views/${view}`)
  }
}
```

**⭐ 这就是"数据库里的 component 字段怎么变成真实页面"的答案。**

## 最后：`next({ ...to, replace: true })`

```javascript

## 三个阶段、三次请求

```
【阶段 1：登录】
POST /login

  → 跳转

【阶段 2：拿权限 + 建路由】
GET /getInfo     → roles + permissions

  → loadView() 翻译

## ⭐ 五个"为什么"

### 为什么页面不直接发请求？

因为要**复用**（多个页面调同一接口）+ **分层**（页面只管显示）。

### 为什么 store 里不拼 URL？

因为 URL 属于"接口定义"，属于 `api/` 层。改地址只改一处。

### 为什么 token 存两份（Cookie + state）？

Cookie 负责**持久**（刷新不掉登录），state 负责**响应式**（组件能读）。

### 为什么响应拦截器要 `return res.data`？

为了剥掉 axios 的包裹层，让页面代码少一层 `.data`。

### 为什么登录成功后还要发两个请求？

因为**路由是从后端来的**（动态路由）。不拿菜单，前端不知道该有哪些页面。

## 练习 3：改一个地方

**把登录接口的 `isToken: false` 删掉，会发生什么？**

1. 打开 `src/api/login.js`
2. 注释掉 `headers: { isToken: false }`（用 `//`）

4. 尝试登录

**思考**：报什么错？为什么？

<details>
<summary>答案</summary>

**会发生什么**：拦截器仍然会检查 `getToken()`。

- **如果 Cookie 里没有 token**（首次登录）→ `getToken()` 返回 undefined → 不加 token → **登录正常**
- **如果 Cookie 里有旧 token** → 会加上 `token: 'Bearer 旧token'` → 后端可能报"token 无效"

**所以这个 `isToken: false` 主要是为了处理"带着旧 token 重新登录"的场景。**

**⭐ 这是一个很好的面试素材**：说明"为什么登录接口要显式声明不带 token"。
</details>

## 练习 4：理解 `res.data`

下面代码里 `res`、`res.data`、`res.data.token` 分别是什么？

```javascript
login(username, password, code, uuid, tenantId).then(res => {
  setToken(res.data.token)
})
```

<details>
<summary>答案</summary>

假设后端返回：

```json
{ "code": 200, "msg": "操作成功", "data": { "token": "abc123" } }
```

- `res` = `{ code:200, msg:'操作成功', data:{ token:'abc123' } }`
  （响应拦截器的 `return res.data` 返回了后端响应体）
- `res.data` = `{ token: 'abc123' }`
- `res.data.token` = `'abc123'`

**⚠️ 注意命名歧义**：这里的 `res.data` 是**后端响应体的 data 字段**，
而不是 axios 的 `res.data`（那个是响应体本身）。容易混。
</details>

# 本章自测

1. 用户点登录后，**第一个**被调用的函数是哪个文件里的？
2. `dispatch('Login')` 和 `commit('SET_TOKEN')` 有什么区别？
3. 为什么 `username` 要 `.trim()` 而 `password` 不用？
4. `uuid` 是干什么用的？不传会怎样？
5. `headers: { isToken: false }` 的作用是什么？
6. 请求拦截器最后为什么必须 `return config`？
7. `setToken()` 和 `commit('SET_TOKEN')` 各存到哪？为什么存两份？
8. 响应拦截器的 `return res.data` 里的 `res.data` 是什么？
9. 为什么分页接口用 `response.rows` 而不是 `response.data.rows`？
10. `next({ ...to, replace: true })` 为什么必须调，不调会怎样？
11. 为什么 `GetInfo` 里要给 `ROLE_DEFAULT` 兜底？
12. `this.$router.push(...).catch(() => {})` 为什么要有空 catch？

<details>
<summary>答案</summary>

1. `src/views/login.vue` 的 `handleLogin()`
2. `dispatch` 触发 **action**（可异步，通常含业务编排）；`commit` 触发 **mutation**（同步，只改 state）
3. 用户名前后的误输入空格要去掉；**密码里的空格可能是用户故意设的**
4. `uuid` 是验证码的唯一标识，后端靠它从 Redis 查出正确答案来比对。不传 → 后端无法校验验证码
5. 告诉请求拦截器"这次不要加 token"（登录时还没有 token，加了反而非法）
6. 不 return 的话请求丢失，永远不会发出去
7. `setToken` → **Cookie**（持久，刷新还在）；`commit` → **state**（内存，响应式）。Cookie 供 `getToken()` 读，state 供组件读
8. 是**后端的整个响应体** `{ code, msg, data }`（不是后端的 data 字段）
9. 分页接口后端用的是 `TableDataInfo`（`{ rows, total }`），不是 `R<T>`（`{ data }`）。两种包装格式
10. 因为 `addRoutes` 刚执行，当前跳转是在路由还不存在时匹配的。不重走会落 404
11. 防止 `roles.length === 0` 一直成立，导致路由守卫**无限循环**拉 `GetInfo`
12. `$router.push` 在"目标与当前路由相同"时会 reject（`NavigationDuplicated`），空 catch 忽略这个噪音错误
</details>
