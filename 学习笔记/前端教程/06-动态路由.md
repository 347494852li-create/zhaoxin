# 6.1 问题的本质：字符串 ≠ 组件

## 前端需要什么

Vue Router 的路由表长这样：

```javascript
{
  path: '/contract/contractDraft',
  component: () => import('@/views/contract/contractDraft/index')    // ← 一个函数
}
```

**`component` 必须是一个"组件对象"或"返回 Promise 的函数"。**

## 后端给的是什么

```json
{
  "path": "contractDraft",
  "component": "contract/contractDraft/index"
}
```

**`component` 是一个普通字符串。**

## ⚠️ 直接赋值会怎样

```javascript
// ❌ 如果直接把字符串当 component
{
  path: '/contract/contractDraft',
  component: "contract/contractDraft/index"
}
```

**Vue Router 会报错**：

```
[Vue warn]: Invalid Component definition: contract/contractDraft/index
```

因为它期望的是组件（对象或函数），给个字符串它不知道怎么渲染。

## 所以必须有"翻译官"

```
"contract/contractDraft/index"（字符串）
        ↓  翻译
() => import('@/views/contract/contractDraft/index')（组件）
```

**这个翻译官就是 `loadView()`。**

**⭐ 为什么后端不能直接给组件？**

因为**后端是 Java，根本不知道 Vue 组件是什么**。
它只知道"数据库里存的这条菜单，对应的页面文件放在哪"。
所以只能给一个**路径字符串**，让前端自己去加载。

# 6.2 完整链路预览

```
【1】数据库 sys_menu 表
    有一行：menu_name='合同草拟', path='contractDraft', component='contract/contractDraft/index'
        ↓
【2】后端 GET /getRouters
    SysMenuServiceImpl.buildMenus()
    把表记录转成 RouterVo 对象 → JSON
        ↓
    返回：
    [
      {
        "name": "Contract",
        "path": "/contract",
        "component": "Layout",
        "meta": { "title": "合同管理", "icon": "contract" },
        "children": [
          {
            "name": "ContractDraft",
            "path": "contractDraft",
            "component": "contract/contractDraft/index",
            "meta": { "title": "合同草拟", "icon": "draft" }
          }
        ]
      }
    ]
        ↓
【3】前端 store/modules/permission.js
    GenerateRoutes()
        ↓ getRouters().then(res => ...)
        ↓ JSON.parse(JSON.stringify(res.data))   ← 深拷贝两份
        ↓
【4】filterAsyncRouter() 递归遍历
        ├─ component === 'Layout'      → 换成 Layout 组件
        ├─ component === 'ParentView'  → 换成 ParentView 组件
        ├─ component === 'InnerLink'   → 换成 InnerLink 组件
        └─ 其他字符串                  → loadView('contract/contractDraft/index')
                                          → () => import('@/views/contract/contractDraft/index')
        ↓
【5】router.addRoutes(rewriteRoutes)
    路由表生效
        ↓
【6】访问 /contract/contractDraft
    → 匹配成功 → 渲染 views/contract/contractDraft/index.vue
```

**⭐ 关键点：翻译发生在第 4 步，`loadView` 是核心。**

# 6.3 后端：`sys_menu` 表 → `RouterVo` JSON

## 数据库表结构（关键字段）

```sql
CREATE TABLE sys_menu (
  menu_id     bigint,       -- 主键
  menu_name   varchar(50),  -- 菜单名（侧边栏显示的文字）
  parent_id   bigint,       -- 父菜单 id（0 = 顶级）
  order_num   int,          -- 排序
  path        varchar(200), -- ★ 路由路径
  component   varchar(255), -- ★★ 组件路径（给前端的字符串）
  query_param varchar(255), -- 路由参数
  is_frame    int,          -- 是否外链（0=是，1=否）
  is_cache    int,          -- 是否缓存（0=缓存，1=不缓存）
  menu_type   char(1),      -- ★ 类型：M=目录 C=菜单 F=按钮
  visible     char(1),      -- 是否显示（0=显示，1=隐藏）
  status      char(1),      -- 状态（0=正常，1=停用）
  perms       varchar(100), -- ★ 权限码（如 contract:contractDraft:list）
  icon        varchar(100), -- 图标名
  ...
);
```

## ⭐ 三种 `menu_type` 的区别

| 类型 | 含义 | 有 `component` 吗 | 例子 |
|---|---|---|---|
| **`M`** | **目录** | 通常是 `Layout` 或 `ParentView` | "合同管理"（下面有子菜单） |
| **`C`** | **菜单** | ✅ **真实页面路径** | "合同草拟" → `contract/contractDraft/index` |
| **`F`** | **按钮** | ❌ 没有 | "新增"按钮 → 只有 `perms` |

**⭐ 所以 `sys_menu` 表同时存了「菜单」和「按钮权限」** —— 这是 RuoYi 的设计。

## 后端 `buildMenus()` 做了什么

**位置**：`ruoyi-base/ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysMenuServiceImpl.java`

```java
public List<RouterVo> buildMenus(List<SysMenu> menus) {
    List<RouterVo> routers = new LinkedList<RouterVo>();

    for (SysMenu menu : menus) {
        RouterVo router = new RouterVo();

        // ① 把表字段映射到 RouterVo 字段
        router.setHidden("1".equals(menu.getVisible()));        // visible='1' → hidden=true
        router.setName(getRouteName(menu));                      // 路由名
        router.setPath(getRouterPath(menu));                     // 路由路径
        router.setComponent(getComponent(menu));                 // ★★★ 组件字符串
        router.setQuery(menu.getQueryParam());
        router.setMeta(new MetaVo(
            menu.getMenuName(),                                   // title
            menu.getIcon(),                                        // icon
            StringUtils.equals("1", menu.getIsCache()),            // noCache
            menu.getPath()                                          // activeMenu
        ));

        // ② 递归处理子菜单
        List<SysMenu> cMenus = (List<SysMenu>) menu.getChildren();
        if (!cMenus.isEmpty() && UserConstants.TYPE_DIR.equals(menu.getMenuType())) {
            // ---- 情况 A：目录（menu_type = 'M'）且有子菜单 ----
            router.setAlwaysShow(true);
            router.setRedirect("noRedirect");
            router.setChildren(buildMenus(cMenus));              // ★ 递归
        } else if (isMenuFrame(menu)) {
            // ---- 情况 B：顶级菜单但配置了外链框 ----
            router.setMeta(null);
            List<RouterVo> childrenList = new ArrayList<RouterVo>();
            RouterVo children = new RouterVo();
            children.setPath(menu.getPath());
            children.setComponent(menu.getComponent());
            children.setName(StringUtils.capitalize(menu.getPath()));
            children.setMeta(new MetaVo(menu.getMenuName(), menu.getIcon(),
                    StringUtils.equals("1", menu.getIsCache()), menu.getPath()));
            childrenList.add(children);
            router.setChildren(childrenList);
        } else if (menu.getParentId().intValue() == 0 && isInnerLink(menu)) {
            // ---- 情况 C：内链（iframe） ----
            router.setMeta(new MetaVo(menu.getMenuName(), menu.getIcon()));
            router.setPath("/inner");
            List<RouterVo> childrenList = new ArrayList<RouterVo>();
            RouterVo children = new RouterVo();
            String routerPath = innerLinkReplaceEach(menu.getPath());
            children.setPath(routerPath);
            children.setComponent(UserConstants.INNER_LINK);      // ★ "InnerLink"
            children.setName(StringUtils.capitalize(routerPath));
            childrenList.add(children);
            router.setChildren(childrenList);
        }

        routers.add(router);
    }
    return routers;
}
```

## ⭐ `getComponent()` —— 决定给前端什么字符串

```java
public String getComponent(SysMenu menu) {
    String component = UserConstants.NO_FRAME;      // "Layout"
    if (StringUtils.isNotEmpty(menu.getComponent())) {
        component = menu.getComponent();             // ★ 直接用表里的值
    } else if (menu.getParentId().intValue() != 0 && isInnerLink(menu)) {
        component = UserConstants.INNER_LINK;        // "InnerLink"
    } else if (menu.getParentId().intValue() != 0 && isParentView(menu)) {
        component = UserConstants.PARENT_VIEW;       // "ParentView"
    }
    return component;
}
```

**⭐ 逻辑很重要**：

| 情况 | 返回的 `component` |
|---|---|
| 表里 `component` 字段**有值** | **直接用那个值**（如 `contract/contractDraft/index`） |
| 表里是空 + 是内链 | `"InnerLink"` |
| 表里是空 + 是父级视图 | `"ParentView"` |
| 表里是空 + 其他 | `"Layout"` |

**所以"业务页面"的 `component` 完全由数据库决定。**

## 后端返回的真实 JSON（示例）

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
```

# 6.4 前端：`/getRouters` → `filterAsyncRouter`

## `GenerateRoutes` 全貌

**位置**：`src/store/modules/permission.js`

```javascript
import auth from '@/plugins/auth'
import router, { constantRoutes, dynamicRoutes } from '@/router'
import { getRouters } from '@/api/menu'
import Layout from '@/layout/index'
import ParentView from '@/components/ParentView'
import InnerLink from '@/layout/components/InnerLink'

const permission = {
  state: {
    routes: [],
    addRoutes: [],
    defaultRoutes: [],
    topbarRouters: [],
    sidebarRouters: []
  },

  actions: {
    GenerateRoutes({ commit }) {
      return new Promise(resolve => {
        getRouters().then(res => {                       // ← 请求 ② /getRouters
          const sdata = JSON.parse(JSON.stringify(res.data))    // 深拷贝①
          const rdata = JSON.parse(JSON.stringify(res.data))    // 深拷贝②

          const sidebarRoutes = filterAsyncRouter(sdata)             // 给侧边栏（保留层级）
          const rewriteRoutes = filterAsyncRouter(rdata, false, true) // 给路由（压平 ParentView）

          const asyncRoutes = filterDynamicRoutes(dynamicRoutes)     // 写死的权限路由
          rewriteRoutes.push({ path: '*', redirect: '/404', hidden: true })   // 兜底

          router.addRoutes(asyncRoutes)
          commit('SET_ROUTES', rewriteRoutes)
          commit('SET_SIDEBAR_ROUTERS', constantRoutes.concat(sidebarRoutes))
          commit('SET_DEFAULT_ROUTES', sidebarRoutes)
          commit('SET_TOPBAR_ROUTES', sidebarRoutes)

          resolve(rewriteRoutes)
        })
      })
    }
  }
}
```

## ⭐ 四个 commit 分别是什么

| commit | 存进 state | 给谁用 |
|---|---|---|
| `SET_ROUTES` | `routes` | **Vue Router 的完整路由表**（含 constantRoutes） |
| `SET_SIDEBAR_ROUTERS` | `sidebarRouters` | **侧边栏菜单**（`Sidebar/index.vue` 的 `v-for`） |
| `SET_DEFAULT_ROUTES` | `defaultRoutes` | 面包屑 |
| `SET_TOPBAR_ROUTES` | `topbarRouters` | 顶部导航（如果有） |

**⭐ 为什么要存 4 份？** 因为不同组件需要**不同的数据形状**：

| 需求 | 需要什么形状 |
|---|---|
| Vue Router | 组件对象（已翻译） |
| 侧边栏 | 完整层级（目录 → 子菜单） |
| 面包屑 | 能回溯的路径链 |

**代价是数据冗余**（同一份菜单存 4 遍），但换来组件解耦。

## `filterAsyncRouter()` 完整代码

```javascript
function filterAsyncRouter(asyncRouterMap, lastRouter = false, type = false) {
  return asyncRouterMap.filter(route => {

    // ① 如果是路由表模式（type=true）且还有子节点 → 先压平
    if (type && route.children) {
      route.children = filterChildren(route.children)
    }

    // ② ★★★ 核心：翻译 component ★★★
    if (route.component) {
      if (route.component === 'Layout') {
        route.component = Layout                    // 换成真实组件
      } else if (route.component === 'ParentView') {
        route.component = ParentView
      } else if (route.component === 'InnerLink') {
        route.component = InnerLink
      } else {
        route.component = loadView(route.component)   // ★ 业务页面：字符串 → 组件
      }
    }

    // ③ 递归处理子节点
    if (route.children != null && route.children && route.children.length) {
      route.children = filterAsyncRouter(route.children, route, type)
    } else {
      // ④ 没有子节点 → 删掉空字段（否则会干扰 Vue Router）
      delete route['children']
      delete route['redirect']
    }

    return true          // ⚠️ 永远返回 true = 不过滤，只是借用 filter 的遍历
  })
}
```

## ⚠️ `filter` 但永远返回 `true`？

```javascript
return asyncRouterMap.filter(route => {
  // ...
  return true           // ← 永远 true
})
```

**所以它其实没有过滤**，只是借用 `filter` 的"遍历 + 返回新数组"能力。

**为什么不直接用 `forEach`？** 因为 `forEach` **不返回新数组**，
而这里需要返回一个处理好的新数组。

**更清晰的写法应该是 `.map()`**，但 RuoYi 原版就是这么写的（历史遗留）。

## `filterChildren()` —— 压平 ParentView

```javascript
function filterChildren(childrenMap, lastRouter = false) {
  var children = []

  childrenMap.forEach((el, index) => {
    if (el.children && el.children.length) {
      // ⭐ 如果这一层是 ParentView（纯目录）且不是最后一层
      if (el.component === 'ParentView' && !lastRouter) {
        el.children.forEach(c => {
          c.path = el.path + '/' + c.path        // ★ 把父路径拼到子路径上
          if (c.children && c.children.length) {
            children = children.concat(filterChildren(c.children, c))
            return
          }
          children.push(c)
        })
        return
      }
    }
    if (lastRouter) {
      el.path = lastRouter.path + '/' + el.path
    }
    children = children.concat(el)
  })

  return children
}
```

### ⭐ 为什么要"压平"ParentView

**场景**：三级菜单

```
合同管理（M，Layout）
  └─ 合同配置（M，ParentView）        ← 纯目录，没有自己的页面
       └─ 编号规则（C，conf/billRule/index）
```

**如果按原样给 Vue Router**：

```javascript
{
  path: '/contract',
  component: Layout,
  children: [{
    path: 'config',
    component: ParentView,          // ← 一个"空壳"组件
    children: [{
      path: 'billRule',
      component: () => import('@/views/conf/billRule/index')
    }]
  }]
}
```

**结果**：URL 是 `/contract/config/billRule`（三层）。

**压平后**：

```javascript
{
  path: '/contract',
  component: Layout,
  children: [{
    path: 'config/billRule',        // ← 路径拼在一起
    component: () => import('@/views/conf/billRule/index')    // ← 直接是业务页面
  }]
}
```

**URL 还是 `/contract/config/billRule`，但少了一层空壳组件。**

**好处**：渲染更快（少一层组件嵌套），调试更简单。

**⭐ 为什么侧边栏版本不压平？** 因为侧边栏**需要显示三层结构**（目录 → 子目录 → 菜单）。

**这就是为什么要深拷贝两份的原因**（见 6.8）。

# 6.5 ⭐ 核心：`loadView` 翻译官

```javascript
export const loadView = (view) => {
  if (process.env.NODE_ENV === 'development') {
    // 开发环境：用 require
    return (resolve) => require([`@/views/${view}`], resolve)
  } else {
    // 生产环境：用 import（按需切成独立 chunk）
    return () => import(`@/views/${view}`)
  }
}
```

## 输入输出

```javascript
loadView('contract/contractDraft/index')
// 返回：
(resolve) => require(['@/views/contract/contractDraft/index'], resolve)
```

或者生产环境：

```javascript
() => import('@/views/contract/contractDraft/index')
```

**这就是 Vue Router 需要的"组件"。**

## ⭐ 为什么开发用 `require`、生产用 `import`

| 环境 | 写法 | 原因 |
|---|---|---|
| 开发 | `require([...], resolve)` | webpack 的 **AMD 风格异步加载**，配合 HMR（热更新）更稳 |
| 生产 | `() => import(...)` | 真正切成**独立 chunk 文件**，按需下载 |

**⚠️ 两者效果类似**，但开发环境用 `require` 是 RuoYi 的历史选择
（早期 webpack 对动态 `import()` 的 HMR 支持不好）。

**⭐ 你写新代码时，两种都可以，但推荐统一用 `() => import(...)`。**

## ⭐⭐ 三个必须知道的点

### ① 数据库里**不能写 `.vue` 后缀**

```javascript
loadView('contract/contractDraft/index')       // ✅
loadView('contract/contractDraft/index.vue')   // ❌ 会变成 @/views/.../index.vue
```

**为什么？** 因为 `loadView` 已经拼了 `@/views/${view}`，
webpack 的 `import`/`require` 会**自动补扩展名**（`.js` → `.vue` → `.json`）。

**写了 `.vue` 后，webpack 会去找 `index.vue.vue`，找不到就报错。**

### ② 数据库里**不能带 `src/views/` 前缀**

```javascript
'contract/contractDraft/index'                  // ✅
'@/views/contract/contractDraft/index'          // ❌ 会变成 @/views/@/views/...
'src/views/contract/contractDraft/index'        // ❌ 会变成 @/views/src/views/...
```

**只能写"相对于 `src/views/` 的路径"。**

### ③ 路径**区分大小写**

```javascript
'contract/contractDraft/index'     // 文件必须是 src/views/contract/contractDraft/index.vue
'contract/contractdraft/index'     // ❌ Linux 上找不到（Windows 上可能能跑，部署后挂）
```

**⚠️ 这是"本地能跑、服务器 404"的经典原因** —— Windows 文件系统不区分大小写，Linux 区分。

## `@` 是什么

```javascript
`@/views/${view}`
```

**`@` 是 webpack 的别名，指向 `src` 目录**（`vue.config.js` 里配的）：

```javascript
configureWebpack: {
  resolve: {
    alias: {
      '@': resolve('src')
    }
  }
}
```

**所以 `@/views/xxx` = `src/views/xxx`。**

## 一张表：数据库值 → 实际文件

| `sys_menu.component` 的值 | 实际加载的文件 |
|---|---|
| `contract/contractDraft/index` | `src/views/contract/contractDraft/index.vue` |
| `system/user/index` | `src/views/system/user/index.vue` |
| `demo/index` | `src/views/demo/index.vue` |
| `index` | `src/views/index.vue` |
| `Layout` | `src/layout/index.vue`（特殊，走前面的分支） |

# 6.6 三种特殊 component

## ① `Layout` → `src/layout/index.vue`

**用在哪**：一级菜单（目录）

```javascript
if (route.component === 'Layout') {
  route.component = Layout
}
```

**效果**：访问这个一级菜单时，渲染**后台外壳**（侧边栏+顶栏+标签页），
子页面显示在 `<app-main>` 里。

```
访问 /contract（component: Layout）
  → 渲染 layout/index.vue（外壳）
    → 子菜单 contractDraft 渲染在 <app-main>
```

**⚠️ 特殊情况**：如果一级菜单**直接对应一个页面**（不是目录），
后端会把它包装成"Layout + 一个子路由"（见 `buildMenus` 的情况 A）。

## ② `ParentView` → `src/components/ParentView/index.vue`

**用在哪**：三级以上菜单的**中间目录**

**这个组件的源码极简**：

```vue
<template>
  <router-view />
</template>

<script>
export default {
  name: 'ParentView'
}
</script>
```

**就是一个"只把自己子路由渲染出来"的空壳。**

**为什么需要它？** 因为 Vue Router 的嵌套路由要求每一层都有 `component`。
但中间那层目录**不需要任何 UI**，所以给一个空壳。

**⭐ 但前端 `filterAsyncRouter` 会把它压平**（见 6.4 的 `filterChildren`），
所以最终路由表里可能没有 `ParentView`（只在侧边栏数据里保留）。

## ③ `InnerLink` → `src/layout/components/InnerLink/index.vue`

**用在哪**：菜单点开是**外部网页**（用 iframe 内嵌）

```vue
<template>
  <div :style="'height:' + height" v-loading="loading">
    <iframe
      :src="src"
      frameborder="no"
      style="width: 100%; height: 100%"
      scrolling="auto"
    />
  </div>
</template>

<script>
export default {
  name: 'InnerLink',
  data() {
    return {
      height: document.documentElement.clientHeight - 94.5 + 'px',
      loading: true,
      src: this.$route.meta.link
    }
  }
}
</script>
```

**场景**：把某个外部系统（如 XXL-JOB 控制台、Druid 监控页）嵌到菜单里。

**⭐ 项目里的例子**：

```sql
-- sys_menu 里的"系统监控 → Druid监控"
-- path = 'http://localhost:8080/druid'
-- component = 空（走后端 getComponent 的 innerLink 分支 → 'InnerLink'）
```

# 6.7 `addRoutes` 和"为什么 next 两次"

## `router.addRoutes()` 是什么

```javascript
router.addRoutes(accessRoutes)
```

**作用**：**动态**往路由表里添加路由。

**为什么需要动态添加？** 因为业务页面的路由**不是写死的**，
是登录后从后端拿的。

## ⭐ 为什么 `addRoutes` 之后要 `next({ ...to, replace: true })`

**位置**：`src/permission.js`

```javascript
router.addRoutes(accessRoutes)            // ① 刚把路由加进去
next({ ...to, replace: true })            // ② 重新走一遍当前跳转
```

### 问题的根源

路由守卫 `beforeEach` 执行时，**当前这次跳转已经匹配过了**：

```
用户访问 /index
  ↓
router 开始匹配 → 路由表里还没有 /index（因为是动态路由）
  ↓
匹配失败 → 准备跳 404
  ↓
**这时 beforeEach 才执行**
  ↓
我们执行 addRoutes()，路由表现在有 /index 了
  ↓
但**本次跳转已经按"没匹配上"处理了**
```

### 解决：重新走一遍

```javascript
next({ ...to, replace: true })
//   ↑ 把目标路由对象原样传回去 → 触发新一轮跳转
```

**这次路由表里已经有 `/index` 了**，匹配成功。

### 为什么要 `{ ...to }` 而不是直接 `next(to)`

**`{ ...to }` 是展开运算符**（第 1 章 1.5），把 `to` 的所有字段复制到新对象。

**为什么要复制？**

因为 `to` 是 Vue Router 传进来的**只读对象**。
如果直接改它（比如加 `replace: true`），可能出问题。

**复制一份再改，安全。**

### 为什么要 `replace: true`

**`replace` 的含义**：跳转时**替换历史记录**，而不是新增一条。

**不加会怎样？**

```
用户访问 /login → 登录成功 → push('/')
  → 历史记录：[/login, /]
  → 守卫触发 next({ ...to }) → 又压一条 / 进历史
  → 历史记录：[/login, /, /]
     ↑ 用户点浏览器"后退"，会回到 / 然后又触发守卫 → 无限后退循环
```

**加了 `replace: true`**：

```
历史记录：[/login, /]     ← 只保留一条
```

### ⭐ 这是 RuoYi 的标志性写法

**面试常问**：**"动态路由添加后为什么要 `next` 两次？"**

**标准答法**：

> 因为 `addRoutes` 是异步生效的。当 `beforeEach` 执行时，当前这次跳转**已经基于旧路由表匹配过了**。
> 新加的路由还没有被应用到本次匹配中，所以必须先 `addRoutes`，再用
> `next({ ...to, replace: true })` **重新触发一次跳转**，让路由按新表重新匹配。
> 用 `replace: true` 是为了避免在历史记录里留下中间状态。

## ⚠️ 一个常见陷阱

```javascript
router.addRoutes(accessRoutes)
next({ ...to, replace: true })
```

**如果 `to.path` 是 `/login` 会死循环吗？**

```javascript
if (to.path === '/login') {
  next({ path: '/' })
  // 不会走到 addRoutes 那里
}
```

**代码里有单独处理**（见 `permission.js`），所以不会。

# 6.8 深拷贝两次的原因

```javascript
const sdata = JSON.parse(JSON.stringify(res.data))    // 深拷贝①
const rdata = JSON.parse(JSON.stringify(res.data))    // 深拷贝②

const sidebarRoutes = filterAsyncRouter(sdata)                 // 处理①
const rewriteRoutes = filterAsyncRouter(rdata, false, true)     // 处理②（含压平）
```

## 为什么要拷贝

**因为两次处理会互相污染。**

### 如果不拷贝

```javascript
const data = res.data

const sidebarRoutes = filterAsyncRouter(data)              // 处理①（修改了 data 的 component）
const rewriteRoutes = filterAsyncRouter(data, false, true)  // 处理②（再处理同一份 data）
```

**问题**：

1. 处理①已经把 `component` 从字符串改成了组件对象
2. 处理②再处理时，`component` 已经是对象，走不进 `if (route.component === 'Layout')` 分支
3. **结果**：处理②拿到的是已经被处理过的数据，逻辑全错

**⚠️ 更严重**：`filterChildren` 会**修改 `path`**：

```javascript
c.path = el.path + '/' + c.path        // ← 直接改原对象
```

如果两次处理用同一个对象，**第二次的 path 会变成双层拼接**：

```
第一次：config + '/' + billRule = 'config/billRule'
第二次：config/billRule + '/' + billRule = 'config/billRule/billRule'   ❌ 错
```

### 所以必须深拷贝

```javascript
const sdata = JSON.parse(JSON.stringify(res.data))    // 独立副本①
const rdata = JSON.parse(JSON.stringify(res.data))    // 独立副本②
```

**两份完全独立，互不影响。**

## `JSON.parse(JSON.stringify(x))` 是什么黑魔法

**这是 JS 里最省事的深拷贝土办法**：

```javascript
const original = { a: 1, nested: { b: 2 } }
const copy = JSON.parse(JSON.stringify(original))

copy.nested.b = 999
console.log(original.nested.b)      // 2 ✅ 不受影响（真深拷贝）
```

**原理**：

1. `JSON.stringify` 把对象转成 JSON 字符串（此时所有嵌套都被"拍平"成文本）
2. `JSON.parse` 把字符串重新解析成对象（此时是全新的对象树）

### ⚠️ 这个方法的三个缺陷

| 缺陷 | 说明 |
|---|---|
| 丢掉 `undefined` | `{ a: undefined }` → `{}` |
| 丢掉函数 | `{ fn: () => {} }` → `{}` |
| 丢掉 `Date` 类型 | `Date` 会变成字符串 |

**但这里拷贝的是后端返回的路由 JSON 数据**（纯 JSON，没有函数和 Date），
**所以完全安全。**

**⭐ 现代替代**：`structuredClone(obj)`（Node 17+ / 新浏览器支持）。

## 对比：浅拷贝的坑

```javascript
const original = { a: 1, nested: { b: 2 } }
const shallow = { ...original }        // 浅拷贝

shallow.nested.b = 999
console.log(original.nested.b)         // 999 ❌ 被污染了
```

**所以这里必须用深拷贝，不能用 `{ ...res.data }`。**

# 6.9 完整数据流串讲

**把本章串成一条线。**

```
【数据库】
  sys_menu 表
  ┌────────────┬─────────────────────────────────────────────┐
  │ menu_name  │ 合同草拟                                     │
  │ path       │ contractDraft                               │
  │ component  │ contract/contractDraft/index                 │
  │ menu_type  │ C（菜单）                                     │
  │ perms      │ contract:contractDraft:list                  │
  │ parent_id  │ <合同管理 的 menu_id>                          │
  └────────────┴─────────────────────────────────────────────┘
        ↓
【后端 Java】
  SysMenuServiceImpl.buildMenus()
    → 查表（selectMenuTreeByUserId，已按角色过滤）
    → 转成 RouterVo
    → getComponent(menu) 返回 "contract/contractDraft/index"（字符串）
        ↓
【HTTP】
  GET /getRouters
  返回：
  [{
    "path": "/contract",
    "component": "Layout",                          ← 字符串
    "children": [{
      "path": "contractDraft",
      "component": "contract/contractDraft/index",   ← 字符串
      "meta": { "title": "合同草拟" }
    }]
  }]
        ↓
【前端 store/modules/permission.js】
  GenerateRoutes()
    ↓ getRouters() 拿到 res.data
    ↓ 深拷贝两份（sdata / rdata）
        ↓
【filterAsyncRouter 递归处理】
  处理 /contract：
    component === 'Layout' → 换成 import Layout from '@/layout/index'
  处理 /contract/contractDraft：
    component === 'contract/contractDraft/index'
      → 不是特殊名
      → loadView('contract/contractDraft/index')

        ↓
【得到最终路由表】
  [{
    path: '/contract',
    component: Layout,                                ← 组件对象

      path: 'contractDraft',

      meta: { title: '合同草拟' }

【router.addRoutes()】
  路由表注册到 Vue Router
        ↓
【用户点菜单 → 访问 /contract/contractDraft】

      → 渲染侧边栏（用 sidebarRouters 数据显示菜单）
      → 在 <app-main> 的 <router-view /> 里
        → 渲染 () => import(...) 的结果

        ↓
【页面渲染完成】
  created() 触发 → getList() → 请求列表数据
```

# 6.10 排查：菜单不出来的 8 种原因

| # | 现象 | 原因 | 怎么查 |
|---|---|---|---|
| 1 | 菜单完全没出现 | `sys_menu` 没插记录 | 查 `SELECT * FROM sys_menu WHERE menu_name='xxx'` |
| 2 | 菜单没出现 | 角色没分配 | 查 `sys_role_menu` 里有没有 |
| 3 | 菜单没出现 | `visible='1'`（隐藏） | 查 `visible` 字段 |
| 4 | 菜单出现但点进去**白屏** | `component` 路径错 | F12 Console 看有没有 `Cannot find module` |
| 5 | 菜单出现但 **404** | 文件不存在 | 检查 `src/views/xxx/index.vue` |
| 6 | 菜单出现但 **403/无权限** | `perms` 和后端不一致 | 对比 `sys_menu.perms` 和 `@SaCheckPermission` |
| 7 | 本地正常、**服务器 404** | **路径大小写不一致** | Linux 区分大小写 |
| 8 | 改了 `component` 不生效 | 浏览器缓存菜单 | **Ctrl+F5 强刷** |

## ⭐ 万能排查流程

```
① F12 → Network → 找到 /getRouters 请求
    ↓ Response 里有你要的菜单吗？
    ├─ 没有 → 后端问题（sys_menu 表 / 角色分配 / visible）
    └─ 有 → 继续

② 看那条菜单的 component 值
    ↓ 是字符串吗？路径对吗？
    ├─ 不对 → 改数据库
    └─ 对 → 继续

③ 检查文件是否存在
    src/views/<component 的值>.vue
    ├─ 不存在 → 建文件
    └─ 存在 → 继续

④ F12 → Console 有红色报错吗？
    └─ `Cannot find module '@/views/xxx'` → 路径/大小写问题
```

**做这个实验，你会彻底理解"字符串→组件"：**

2. 在 `loadView` 函数里加一行日志：

```javascript
export const loadView = (view) => {
  console.log('[loadView] 翻译:', view)       // ← 加这行
  if (process.env.NODE_ENV === 'development') {
    return (resolve) => require([`@/views/${view}`], resolve)

  }

```

3. 重启前端（`Ctrl+C` → `npm run dev`）

5. F12 → Console → 看输出了多少条、分别是什么

**你会看到**：每个菜单的 `component` 字符串都被打印了一次。

## 练习 3：故意改错

**试试把 `component` 改错，看报什么错：**

1. 数据库里把某条菜单的 `component` 从 `demo/index` 改成 `demo/index.vue`
2. 刷新页面（清空 store）
3. F12 → Console 看报错

**思考**：为什么加了 `.vue` 就找不到？

<details>
<summary>答案</summary>

**报错**（大概）：

```
Error: Cannot find module '@/views/demo/index.vue'
```

**原因**：`loadView` 拼成 `@/views/demo/index.vue`，
webpack 的 `require`/`import` 会**自动补扩展名**，
所以它去找 `@/views/demo/index.vue.vue` → 找不到。

**结论**：`component` 字段**绝对不能带 `.vue` 后缀**。
</details>

## 练习 4：理解深拷贝

**下面代码有什么 bug？**

```javascript
const data = res.data
const sidebarRoutes = filterAsyncRouter(data)
const rewriteRoutes = filterAsyncRouter(data, false, true)
```

<details>
<summary>答案</summary>

**两个 bug**：

1. **`component` 被改两次**：第一次已经把字符串换成组件对象，
   第二次再处理时走不进 `if (route.component === 'Layout')` 分支

2. **`path` 被拼接两次**：`filterChildren` 里 `c.path = el.path + '/' + c.path`，
   第二次会变成 `config/billRule/billRule`

**正确写法**：

```javascript
const sidebarRoutes = filterAsyncRouter(JSON.parse(JSON.stringify(res.data)))
const rewriteRoutes = filterAsyncRouter(JSON.parse(JSON.stringify(res.data)), false, true)
```
</details>

# 本章自测

1. 为什么后端不能直接返回 Vue 组件？
2. `sys_menu.component` 里存的是什么？为什么不能带 `.vue`？
3. `loadView` 的输入和输出分别是什么？
4. 开发环境和生产环境 `loadView` 用的写法有什么区别？为什么？
5. `component: 'Layout'` / `'ParentView'` / `'InnerLink'` 分别对应用什么场景？
6. `ParentView` 组件内部有什么？
7. 为什么要深拷贝两份数据？
8. `filterChildren` 里的"压平"是做什么的？
9. `addRoutes` 之后为什么必须 `next({ ...to, replace: true })`？
10. `replace: true` 不加会怎样？
11. 为什么 `filterAsyncRouter` 用 `filter` 却永远返回 `true`？
12. 菜单出现了但点进去白屏，先查什么？

<details>
<summary>答案</summary>

1. 因为后端是 Java，**不知道 Vue 组件是什么**。它只知道"这个菜单对应哪个文件路径"
2. 存的是**相对于 `src/views/` 的文件路径**（如 `contract/contractDraft/index`）。不能带 `.vue`，因为 `loadView` 会拼成 `@/views/${component}`，webpack 自动补扩展名，写了会变成 `.vue.vue`
3. 输入：`'contract/contractDraft/index'`（字符串）；输出：`() => import('@/views/contract/contractDraft/index')`（组件函数）
4. 开发用 `require([...], resolve)`（AMD 风格，HMR 更稳）；生产用 `() => import(...)`（切成独立 chunk，按需下载）
5. `Layout` → 一级目录（后台外壳）；`ParentView` → 三级以上菜单的空壳中间层；`InnerLink` → iframe 内嵌外部网页
6. 只有一个 `<router-view />`（纯空壳，透传子路由）
7. 因为两次处理会**互相污染**：① `component` 第一次被换成对象，第二次处理不到；② `path` 会被拼接两次
8. 把 `ParentView` 这种"纯目录"层**去掉**，把子路由的 `path` 拼到父路径上，减少一层组件嵌套
9. 因为 `addRoutes` 是异步生效的，当前跳转已经基于旧路由表匹配过了。必须重新触发一次跳转才能匹配到新路由
10. 历史记录里会多一条中间状态，用户点"后退"会回到那个状态又触发守卫 → 可能循环
11. 因为它**没有真正要过滤**，只是想借用 `filter` 的"遍历 + 返回新数组"能力（`forEach` 不返回数组）
12. **F12 → Console 看有没有 `Cannot find module '@/views/xxx'`**（组件路径错或文件不存在）
