# 9.1 F12 的五个面板

打开方式：`F12` 或 `Ctrl+Shift+I`

| 面板 | 中文 | 管什么 | 什么时候用 |
|---|---|---|---|
| **Elements** | 元素 | 看/改 DOM 和 CSS | 样式不对、元素找不到 |
| **Console** | 控制台 | 看报错、日志、执行 JS | **第一站，先看有没有红字** |
| **Sources** | 源代码 | 打断点调试 | 逻辑不对，要单步跟踪 |
| **Network** | 网络 | 看请求和响应 | **接口问题必看** |
| **Application** | 应用 | 看 Cookie/Storage | token 问题 |

**⭐ 排查 bug 的黄金顺序**：

```
① Console：有没有红色报错？
    ↓ 有 → 报错信息直接告诉你哪一行
    ↓ 没有
② Network：请求发了吗？返回什么？
    ↓ 404 / 500 / 参数不对
③ Elements：DOM 渲染对吗？
    ↓ 元素不在 / 样式不对
④ Sources：打断点看变量
```

# 9.2 Network 面板详解（最常用）

## 打开后的界面

```
┌─────────────────────────────────────────────────────────────┐
│ [全部] [Fetch/XHR] [JS] [CSS] [Img] ...  [过滤框]  [☑ Preserve log] │
├─────────────────────────────────────────────────────────────┤
│ Name          │ Status │ Method │ Type │ Size │ Time        │
├─────────────────────────────────────────────────────────────┤
│ login         │ 200    │ POST   │ xhr  │ 1.2K │ 320ms       │
│ getInfo       │ 200    │ GET    │ xhr  │ 3.4K │ 150ms       │
│ getRouters    │ 200    │ GET    │ xhr  │ 8.9K │ 200ms       │
│ demo/list     │ 404    │ GET    │ xhr  │ 0    │ 5ms         │
└─────────────────────────────────────────────────────────────┘
```

## ⭐ 三个必勾的选项

| 选项 | 作用 | 为什么必须 |
|---|---|---|
| **Persist log**（保留日志） | 页面跳转后不清空记录 | 登录会跳转，不勾就看不到登录前的请求 |
| **Disable cache**（禁用缓存） | 不读浏览器缓存 | 避免"改了代码但加载的是旧文件" |
| **Fetch/XHR 过滤** | 只看接口请求 | 过滤掉一堆图片、css 噪音 |

## ⭐ 点开一个请求，五个标签页

| 标签 | 看什么 |
|---|---|
| **Headers** | 请求 URL、方法、**请求头**（token 在这）、**请求参数**、响应头 |
| **Payload** | 请求体（POST 的 JSON 数据） |
| **Preview** | 响应的格式化预览（JSON 可展开） |
| **Response** | 响应的原始文本 |
| **Timing** | 各阶段耗时（DNS/连接/等待/下载） |

### Headers 里最关键的三块

**① Request URL**

```
https://localhost/dev-api/demo/list?pageNum=1&pageSize=10&name=xxx
                ↑ 前缀对不对        ↑ 参数对不对
```

**② Request Headers**

```
token: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
       ↑ 有没有？格式对不对？（Bearer + 空格）
```

**⭐ 如果没有 token 头** → 说明 `getToken()` 读不到 Cookie
→ 检查 Application → Cookies → 有没有 `Admin-Token`

**③ Response**

```json
{
  "code": 200,
  "msg": "查询成功",
  "rows": [...],
  "total": 53
}
```

**⭐ 看 `code`**：

| code | 含义 | 后续怎么办 |
|---|---|---|
| 200 | 成功 | 检查前端渲染 |
| 401 | 未登录/过期 | 检查 token |
| 403 | 无权限 | 检查权限码 |
| 500 | 服务器错误 | 看后端日志 |

## ⭐ 实战：判断"接口有没有问题"

**例子**：列表页显示"暂无数据"，但数据库明明有数据。

**排查**：

```
① Network → 找 demo/list 请求
    ↓
② 状态码 200？
    ├─ 404 → URL 错了（后端没这个接口 / 路由前缀不对）
    ├─ 401 → token 问题
    ├─ 403 → 权限问题
    └─ 200 → 继续
    ↓
③ 看 Response
    {
      "code": 200,
      "rows": [],          ← ★ 后端返回的就是空数组
      "total": 0
    }
    ↓
   结论：不是前端问题，是后端查询没数据
   → 查后端 SQL、查数据库、查 del_flag
```

**如果 Response 里 `rows` 有数据但页面不显示**：

```
→ 前端赋值错了
→ 看代码：this.demoList = response.rows  （写对了吗？）
→ 看模板：:data="demoList"                （绑定对了吗？）
```

## ⭐ 一个高级技巧：复制请求为 cURL

**右键请求 → Copy → Copy as cURL**

复制出来的东西可以直接在终端跑：

```bash
curl 'http://localhost/dev-api/demo/list?pageNum=1' \
  -H 'token: Bearer eyJ...' \
  -H 'Content-Type: application/json'
```

**⭐ 用途**：把请求发给后端同事，让他直接复现问题。

# 9.3 Console 面板技巧

## 三种输出

```javascript
console.log('普通信息')            // 白色
console.warn('警告')               // 黄色
console.error('错误')              // 红色
```

## ⭐ 更强大的输出

### `console.table()` —— 表格展示数组

```javascript
const list = [
  { id: 1, name: 'A', status: '0' },
  { id: 2, name: 'B', status: '1' }
]
console.table(list)
```

**输出**（真正的表格，可点表头排序）：

```
┌─────────┬────┬──────┬────────┐
│ (index) │ id │ name │ status │
├─────────┼────┼──────┼────────┤
│ 0       │ 1  │ 'A'  │ '0'    │
│ 1       │ 2  │ 'B'  │ '1'    │
└─────────┴────┴──────┴────────┘
```

### `console.group()` —— 分组

```javascript
console.group('用户信息')
console.log('name:', user.name)
console.log('roles:', user.roles)
console.groupEnd()
```

**输出**（可折叠）：

```
▼ 用户信息
    name: 张三
    roles: ['admin']
```

### `console.time()` —— 测耗时

```javascript
console.time('查询列表')
listDemo(params).then(() => {
  console.timeEnd('查询列表')
  // 输出：查询列表: 320.5ms
})
```

### `console.trace()` —— 打印调用栈

```javascript
console.trace('谁调了我？')
// 输出完整的函数调用链
```

**⭐ 用途**：找出"这个方法是被谁调的"（比如事件总线触发时）。

## ⭐ 在 Console 里直接操作页面

**Console 里可以访问全局变量和 DOM**：

```javascript
// ① 看 Vue 实例（如果构建时暴露了）
// 项目里通常没暴露，但可以试
document.querySelector('#app').__vue__

// ② 手动调接口
fetch('/dev-api/getInfo', {
  headers: { 'token': 'Bearer ' + document.cookie.match(/Admin-Token=([^;]+)/)[1] }
}).then(r => r.json()).then(console.log)

// ③ 改页面元素
document.querySelector('.el-table').style.background = 'red'

// ④ 看 localStorage / sessionStorage
localStorage
sessionStorage
```

## ⚠️ 常见报错怎么读

### `Cannot read property 'xxx' of undefined`

```javascript
TypeError: Cannot read property 'name' of undefined
    at VueComponent.getList (index.vue:120)
                  ↑ 组件         ↑ 方法      ↑ 文件:行号
```

**含义**：`getList` 方法里，某个应该是对象的变量是 `undefined`，
你访问它的 `.name` 就报错了。

**常见原因**：

```javascript
// ① 接口返回的数据结构不对
this.demoList = response.data.rows     // 但 response 里没有 data

// ② 异步数据还没到就用了
created() {
  console.log(this.form.name)          // form 可能还是空对象
}

// ③ 拼写错误
this.userInfo.nickName                  // 实际是 nickname（大小写）
```

**⭐ 点报错行号能直接跳到出错位置。**

### `Cannot read property 'resetFields' of undefined`

**典型场景**：弹窗的 `reset()` 里调 `this.$refs.form.resetFields()`。

**原因**：`this.$refs.form` 是 `undefined`（表单还没渲染）。

**解决**：包在 `$nextTick` 里：

```javascript
this.$nextTick(() => {
  this.$refs.form?.resetFields()
})
```

### `Unknown custom element: <xxx>`

```
[Vue warn]: Unknown custom element: <my-test> - did you register the component correctly?
```

**原因**：组件没注册。

**排查**：

```
① 是全局组件吗？（main.js 里 Vue.component 注册过）
② 是本页面 components: {} 里注册了？
③ 名字拼对了吗？（kebab-case vs PascalCase）
```

### `[Vue warn]: Property or method "xxx" is not defined`

**原因**：模板里用了 `xxx`，但 `data()` / `computed` / `methods` 里都没有。

**排查**：搜 `data()` 和 `computed` 里有没有这个字段。

# 9.4 Sources 断点调试（最强）

## 为什么用断点

**`console.log` 只能看"某个时刻"的值，断点能看"整个执行过程"。**

## 找到源码

**问题**：生产/开发环境打包后的代码是压缩过的，怎么找源文件？

**解决：配 source map**。

**项目的配置**（`vue.config.js`）：

```javascript
productionSourceMap: false        // 生产环境关闭（省体积、防源码泄漏）
// 开发环境默认开启，所以能调试
```

**打开 Sources 面板 → 左侧 `webpack://` → `src` → 找到你的文件**

```
webpack://
  └── .
      └── src
          ├── views
          │   └── demo
          │       └── index.vue
          ├── utils
          │   └── request.js
          └── ...
```

## ⭐ 打断点的三种方式

### 方式 1：在 Sources 里点行号

1. Sources → 找到 `src/views/demo/index.vue`
2. **点行号左边的空白处** → 出现蓝色标记
3. 触发那个方法 → 代码会停在那里

### 方式 2：在代码里写 `debugger`

```javascript
getList() {
  debugger                    // ★ 执行到这里会停
  this.loading = true
  listDemo(this.queryParams).then(response => {
    debugger                  // ★ 这里也会停
    this.demoList = response.rows
  })
}
```

**⚠️ 记得删掉 `debugger`**，否则生产环境也会停。

### 方式 3：条件断点

**右键行号 → Add conditional breakpoint**，输入条件：

```javascript
this.demoList.length === 0        // 只有列表为空时才停
```

**⭐ 用途**：循环里只想在特定条件下停（比如某个 id）。

## ⭐ 断点停下后能做什么

**停下来后，右侧面板**：

| 区域 | 作用 |
|---|---|
| **Scope**（作用域） | 看当前所有变量的值（`this`、局部变量、全局） |
| **Watch**（监视） | 手动添加想盯的表达式 |
| **Call Stack**（调用栈） | 看"谁调了我"（从哪层函数进来的） |
| **Breakpoints** | 所有断点列表 |

**顶部工具栏按钮**：

| 按钮 | 快捷键 | 作用 |
|---|---|---|
| ▶️ 继续 | `F8` | 继续执行到下一个断点 |
| ⤵️ 单步跳过 | `F10` | 执行下一行（不进函数） |
| ⬇️ 单步进入 | `F11` | 进入当前行的函数 |
| ⬆️ 单步跳出 | `Shift+F11` | 跳出当前函数 |
| ⏸️ 停用断点 | `Ctrl+F8` | 临时关掉所有断点 |

**⭐ 在 Console 里能访问当前作用域的变量**：

```
停下来后，Console 里敲：
> this.demoList
> this.queryParams
> response
```

**这比 `console.log` 强得多**（能实时看、能改）。

## ⭐ 实战：调试"列表数据不显示"

```
① 在 getList 的赋值行打断点
   this.demoList = response.rows      ← 这行点行号

② 刷新页面，代码会停

③ 在 Console 里看：
   > response
   { code: 200, rows: [...], total: 53 }    ← 数据有

   > response.rows
   [{...}, {...}]                            ← 有数据

④ 按 F10 执行这一行

⑤ 再看：
   > this.demoList
   [{...}, {...}]                            ← 赋值成功

⑥ 如果 this.demoList 有值但页面不显示
   → 问题在模板（:data 绑定错了）

⑦ 如果 response.rows 就是空
   → 问题在后端（查询没数据）
```

## ⚠️ 断点不生效的常见原因

| 现象 | 原因 | 解决 |
|---|---|---|
| 找不到 `src` 目录 | source map 没生成 | 确认 `productionSourceMap` / 开发环境默认有 |
| 断点行位置偏移 | 代码被 babel 转换 | 正常现象，在转换后的位置停 |
| 断点不触发 | 代码没执行到 | 检查方法有没有被调用 |
| 断点不触发 | 断点设在了没执行的 if 分支 | 看 Call Stack 确认走哪条路 |

# 9.5 Vue Devtools

## 安装

**Chrome / Edge 商店搜索 "Vue.js devtools"** 安装。

**⭐ 注意**：Vue 2 项目需要装 **Vue 2 兼容版**（新版 Devtools 只支持 Vue 3）。

**装好后**：F12 会多一个 **Vue** 标签页。

**⚠️ 如果 Vue 标签不出现**：

1. 确认是开发环境（生产版 Vue 禁用了 devtools）
2. 刷新页面
3. 检查扩展是否启用

## 三个最有用的功能

### ① Components —— 看组件树

```
<Root>
  └─ <App>
      └─ <Layout>
          ├─ <Sidebar>
          ├─ <Navbar>
          ├─ <TagsView>
          └─ <AppMain>
              └─ <DemoIndex>            ← 你当前在看的页面
                  ├─ <EditDialog>
                  └─ <Pagination>
```

**点任意组件** → 右侧看它的 **data / props / computed**。

**⭐ 可以直接改值**（双击值）→ 界面实时更新，**不用改代码**。

**用途**：测试"如果 `loading` 变成 false 会怎样"。

### ② Vuex —— 看状态仓库

```
state
  ├─ user
  │   ├─ token: "eyJ..."
  │   ├─ roles: ["admin"]
  │   └─ permissions: ["*:*:*"]        ← ★ 权限码在这
  ├─ permission
  │   ├─ sidebarRouters: [...]         ← ★ 菜单数据
  │   └─ routes: [...]
  └─ app ...
```

**⭐ 排查权限问题时，第一站就是这里** —— 看 `permissions` 到底有没有那个权限码。

**也能直接改**（比如手动加一个权限码测试）。

### ③ Events —— 看事件

**能看到所有 `$emit` 的事件**（如果代码里用了）。

**⚠️ 对 `$EventBus` 的监听有限**，主要看组件的 emit。

## ⭐ 一个实用场景：排查"按钮不显示"

```
① 打开 Vue Devtools → Vuex
② 找 state → user → permissions
③ 看里面有没有 'demo:add'
   ├─ 没有 → 后端没给这个权限（查 sys_menu / 角色分配）
   └─ 有 → 继续
④ 看页面的 v-hasPermi 写的字符串
   v-hasPermi="['demo:add']"          ← 和上面一致吗？
⑤ 如果一致但按钮还不显示
   → 检查指令是否注册（directive/index.js）
   → 检查是不是被"完全一致的字符串"卡住了（多一个空格都不行）
```

# 9.6 六类常见 bug 的定位流程

## 类型 1：页面白屏

```
① Console 有红色报错吗？
    ├─ 有 → 按报错位置修
    └─ 没有 → 继续
② Network 有失败的请求吗？（红色）
    ├─ 有 → 看是哪个接口
    └─ 没有 → 继续
③ Elements 里 <div id="app"> 里面有内容吗？
    ├─ 只有"系统加载中" → Vue 没启动
    │   → 检查 main.js 有没有报错
    │   → 检查 index.html 的 script 是否正确加载
    └─ 有内容但看不到 → CSS 问题（display:none? 高度0?）
```

## 类型 2：菜单不显示

```
① Network → /getRouters → Response 里有这个菜单吗？
    ├─ 没有 → 后端问题
    │   ① 查 sys_menu 表
    │   ② 查 visible = '0'？
    │   ③ 查 sys_role_menu 有分配吗
    │   ④ 查 status = '0'？
    └─ 有 → 继续
② 检查 component 路径对不对
    → src/views/<component>.vue 存在吗？
③ Ctrl+F5 强刷（菜单是登录时拉的）
```

## 类型 3：接口 401

```
① Network → 请求的 Request Headers 里有 token 吗？
    ├─ 没有 → 拦截器没加
    │   → 查 request.js 的 isToken
    │   → 查 getToken() 能不能读到 Cookie
    └─ 有 → 继续
② token 格式对吗？
    应该是 "Bearer eyJ..."（Bearer + 空格）
    ├─ 格式错 → 查 request.js 的拼接
    └─ 格式对 → 继续
③ Application → Cookies → 有 Admin-Token 吗？
    ├─ 没有 → 登录没成功 / Cookie 被清
    └─ 有 → 继续
④ 后端日志看具体原因
    → token 过期？token 无效？用户被踢？
```

## 类型 4：接口 403（无权限）

```
① 后端注解的权限码是什么？
    搜 @SaCheckPermission("xxx")
② 数据库 sys_menu.perms 的值是什么？
    SELECT perms FROM sys_menu WHERE ...
③ 两者一致吗？
    ├─ 不一致 → 改成一个
    └─ 一致 → 继续
④ 当前用户真的分配了这个权限吗？
    → Vue Devtools → Vuex → permissions 里有没有
    ├─ 没有 → 查 sys_role_menu
    └─ 有 → 重新登录（权限可能在登录时缓存）
```

## 类型 5：数据不对（显示"暂无数据"）

```
① Network → 接口返回什么？
    → 看 rows / total
    ├─ rows 是空的 → 后端问题
    │   ① 数据库有数据吗
    │   ② 查询条件是否过滤掉了
    │   ③ del_flag 是否 = '0'
    └─ rows 有数据 → 继续
② 前端赋值对吗？
    this.demoList = response.rows      ← 对了吗？
③ 模板绑定对吗？
    :data="demoList"                    ← 对了吗？
④ 打断点确认（9.4 的实战）
```

## 类型 6：改了代码不生效

```
① Ctrl+F5 强刷（跳过缓存）
② Network 勾上 Disable cache
③ 确认 dev server 重新编译了吗？
    → 看终端有没有 "Compiled successfully"
④ 重启 dev server
    → Ctrl+C 然后 npm run dev
⑤ 改的是 .env 吗？
    → 环境变量必须重启（编译时注入）
```

# 9.7 后端日志配合

## 看后端控制台

**IDEA 里跑的后端**：看 Run 窗口的输出。

**关键日志类型**：

| 日志 | 含义 |
|---|---|
| `ERROR` | 错误（红色） |
| `WARN` | 警告（黄色） |
| `SQL` | 执行的 SQL（如果开了 p6spy） |
| `[请求]` / `[响应]` | 如果配了日志切面 |

# 9.8 快速排查速查表

## 症状 → 第一站

| 症状 | 第一站 | 看什么 |
|---|---|---|
| 页面白屏 | **Console** | 红色报错 |
| 按钮点了没反应 | **Console** | 有没有报错 |
| 数据不显示 | **Network** | 接口 Response 里有没有数据 |
| 接口 404 | **Network** | 请求 URL 对不对 |
| 接口 401 | **Network** | Request Headers 有 token 吗 |
| 接口 403 | **Network** + 后端 | 权限码对不对 |
| 接口 500 | **后端控制台** | 异常堆栈 |
| 菜单不显示 | **Network** | `/getRouters` 的 Response |
| 按钮不显示 | **Vuex** | `permissions` 里有没有 |
| 样式不对 | **Elements** | 哪个 CSS 规则生效了 |
| 逻辑不对 | **Sources** | 打断点看变量 |

## 五条黄金法则

### ① 先看红字

**Console 里的红色报错 90% 直接告诉你原因。**

### ② 分清前后端

**用 `/doc.html` 测同一个接口**，就知道是谁的问题。

### ③ Network 看三样

**URL、Headers（token）、Response（code + 数据）。**

### ④ 断点比 console.log 强

**打断点能在 Console 里实时看变量、改变量。**

### ⑤ 强刷解决一半问题

**`Ctrl+F5`** —— 缓存问题是最常见的"玄学 bug"。

# 本章自测

1. 排查 bug 时第一个看哪个面板？
2. Network 面板必须勾哪两个选项？为什么？
3. 怎么判断"是前端问题还是后端问题"？
4. 请求头里应该有什么？格式是什么？
5. `code: 403` 说明什么？怎么排查？
6. 断点的三个打断点方式？
7. 断点停下后在哪看变量的值？
8. Vue Devtools 的 Vuex 面板用什么？
9. 怎么在浏览器里看到实际执行的 SQL？
10. 改了代码不生效，试哪三招？

<details>
<summary>答案</summary>

1. **Console**（先看有没有红色报错）
2. **Preserve log**（页面跳转后保留记录，登录必用）；**Disable cache**（不读缓存，避免加载旧文件）
3. 在 `http://localhost:8080/doc.html` 里测同一个接口：能通 → 前端问题；不通 → 后端问题
4. `token: Bearer eyJhbGci...`（头名是 `token`，值以 `Bearer ` + 空格开头）
5. **无权限**。排查：① 后端 `@SaCheckPermission` 的字符串 ② 数据库 `sys_menu.perms` ③ 当前用户是否分配（Vuex → permissions）
6. ① Sources 里点行号 ② 代码里写 `debugger` ③ 右键行号加条件断点
7. 右侧 **Scope** 面板；或者直接在 **Console** 里敲变量名
8. 看 **state**，尤其 `user.permissions`（权限码）和 `permission.sidebarRouters`（菜单）
9. 后端 `application-dev.yml` 配 `p6spy: true`，控制台会打印 SQL
10. ① `Ctrl+F5` 强刷 ② Network 勾 Disable cache ③ 重启 `npm run dev`
