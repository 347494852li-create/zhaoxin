# 10.1 分层架构对照

## 一张总表

| 层 | 前端 | 后端 | 职责 |
|---|---|---|---|
| **入口** | `main.js` + `index.html` | `RuoYiApplication.main()` | 启动 |
| **路由/分发** | `router/index.js` + `permission.js` | `@RequestMapping` + `HandlerInterceptor` | 决定谁处理 |
| **控制器** | `views/**/*.vue` | `*Controller.java` | 接请求/展示 |
| **服务** | `store/modules/*.js`（业务编排） | `*ServiceImpl.java` | 业务逻辑 |
| **数据访问** | `api/**/*.js` | `*Mapper.java` | 拿数据 |
| **实体** | `data()` 里的对象 | `*Entity` / `*Bo` / `*Vo` | 数据结构 |
| **工具** | `utils/*.js` | `utils/*.java` | 通用函数 |
| **拦截器** | `request.js` 的 interceptor | `Filter` / `HandlerInterceptor` | 统一加工 |
| **全局异常** | `request.js` 的响应拦截器 | `@RestControllerAdvice` | 统一错误 |
| **权限** | `v-hasPermi` + `plugins/auth.js` | `@SaCheckPermission` | 权限校验 |

## ⭐ 关键差异：前端的"三层"不是后端的"三层"

```
后端（经典三层）：
  Controller → Service → Mapper → DB

前端（实际是四层）：
  views（页面）→ api（接口声明）→ request.js（统一拦截）→ 浏览器
                      ↑
                  store（业务编排，可选）
```

**⭐ 前端的 `api/` 层 ≈ 后端的 `Mapper` 层**（都是"数据访问"），
但前端**没有真正的业务层** —— 业务逻辑通常在：
1. `store` 的 action 里（跨页面的逻辑）
2. `views` 的 methods 里（页面内逻辑）
3. **后端**（真正的业务规则）

**这是最关键的一个认知**：

> **前端的"业务逻辑"通常只是"界面逻辑"（拼参数、改显示）。**
> **真正的业务规则在后端。**

**例子**：合同能不能删除？

| 在哪判断 | 判断什么 |
|---|---|
| 前端 | 按钮要不要显示（`v-hasPermi`） |
| 后端 | **真的能不能删**（`@SaCheckPermission` + 业务校验） |

# 10.2 登录接口：前端 4 个文件 vs 后端 4 个文件

## 完整对照

| 步骤 | 前端 | 后端 |
|---|---|---|
| 1 | `views/login.vue` 的用户输入 | — |
| 2 | `store/modules/user.js` 的 `Login` action | — |
| 3 | `api/login.js` 的 `login()` | — |
| 4 | `utils/request.js` 拦截器 | `Filter` 链 |
| 5 | HTTP POST `/login` | **`SysLoginController.login()`** |
| 6 | — | `SysLoginService.login()` |
| 7 | — | `LoginBody`（接参数） |
| 8 | — | `R<Map>`（返回） |

## 前端：`api/login.js`

```javascript
// zxcm-learn/zxcm-ui/src/api/login.js
export function login(username, password, code, uuid, tenantId) {
  const data = {
    username,
    password,
    code,
    uuid,
    tenantId
  }
  return request({
    url: '/login',
    headers: {
      isToken: false
    },
    method: 'post',
    data: data
  })
}
```

## 后端：`SysLoginController.java`

```java
// zhaoxin-contract/ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysLoginController.java

@PostMapping("/login")
public R<Map<String, Object>> login(@Validated @RequestBody LoginBody loginBody) {
    Map<String, Object> ajax = new HashMap<>();
    String tenantId = loginBody.getTenantId();
    if (StringUtils.isEmpty(tenantId)) {
        tenantId = TenantProperties.getInstance().getDefaultTenantId();
    }
    // 生成令牌
    String token = loginService.login(
        loginBody.getUsername(),
        loginBody.getPassword(),
        loginBody.getCode(),
        loginBody.getUuid(),
        tenantId
    );
    ajax.put(Constants.TOKEN, token);
    return R.ok(ajax);
}
```

## ⭐ 逐个对应

### ① URL 和 Method

| 前端 | 后端 |
|---|---|
| `url: '/login'` | `@PostMapping("/login")` |
| `method: 'post'` | `@PostMapping` |

**⭐ 对应关系**：

```java
@PostMapping("/login")        ←→    { url: '/login', method: 'post' }
@GetMapping("/list")          ←→    { url: '/list', method: 'get' }
@PutMapping                   ←→    { method: 'put' }
@DeleteMapping("/{ids}")      ←→    { url: '/xxx/' + ids, method: 'delete' }
```

### ② 参数：`data` vs `@RequestBody`

| 前端 | 后端 |
|---|---|
| `data: { username, password, code, uuid, tenantId }` | `@RequestBody LoginBody loginBody` |

**⭐ `@RequestBody` 表示"从请求体里读 JSON 并转成对象"** ——
所以前端**必须用 `data`**（放请求体），**不能用 `params`**（拼 URL）。

**后端 `LoginBody` 的字段**（`ruoyi-base/ruoyi-common/.../LoginBody.java`）：

```java
public class LoginBody {
    private String username;
    private String password;
    private String code;
    private String uuid;
    private String tenantId;
}
```

**⭐ 前端 `data` 对象的 key 必须和这些字段名**完全一致**（大小写敏感）。**

```javascript
// ✅ 正确
data: { username: 'x', password: 'y', code: 'z', uuid: 'u', tenantId: 't' }

// ❌ 错误（大写 U）
data: { UserName: 'x', ... }
// 后端收到 null
```

### ③ 返回：`R<Map>` vs `res.data`

| 后端 | 前端收到的 |
|---|---|
| `R.ok(ajax)` | `res.data` |

**`R` 类的结构**（`ruoyi-base/ruoyi-common/.../R.java`）：

```java
public class R<T> implements Serializable {
    public static final int SUCCESS = 200;
    public static final int FAIL = 500;

    private int code;
    private String msg;
    private T data;

    public static <T> R<T> ok(T data) {
        return restResult(data, SUCCESS, null);
    }
    // ...
}
```

**所以 `R.ok(ajax)` 返回的 JSON 是**：

```json
{
  "code": 200,
  "msg": null,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

**⭐ 前端拿 token 的路径**：

```javascript
login(...).then(res => {
  // res = { code: 200, msg: null, data: { token: '...' } }
  setToken(res.data.token)
  //       ↑ data 是 R 的 data 字段
  //              ↑ token 是 HashMap 的 key
})
```

### ④ `isToken: false` 在后端有对应吗

**没有。**

**`isToken: false` 是「前端独有的约定」** ——
它只被 `request.js` 的拦截器读取，**不会发给后端**。

**所以后端完全不知道这个标记。**

**⭐ 这是一个重要的认知**：请求头里有些是"给前端自己看的元信息"，
不一定要发给后端（虽然实际上会发过去，但后端忽略）。

### ⑤ `@Validated` 校验

```java
public R<Map<String, Object>> login(@Validated @RequestBody LoginBody loginBody)
//                            ↑ 触发校验
```

**`@Validated` 会让 Spring 校验 `LoginBody` 上的注解**（如果有 `@NotBlank` 等）。

**⚠️ 但这里 `LoginBody` 的字段没有校验注解**，
所以实际上只是"标记一下"（真正的校验在 `SysLoginService` 里）。

### ⑥ 实际登录逻辑（`SysLoginService`）

**位置**：`zhaoxin-contract/ruoyi-base/ruoyi-system/src/main/java/com/ruoyi/system/service/SysLoginService.java`

```java
public String login(String username, String password, String code, String uuid, String tenantId) {
    HttpServletRequest request = ServletUtils.getRequest();
    boolean captchaOnOff = configService.selectCaptchaOnOff();

    // ① 验证码校验
    if (captchaOnOff) {
        validateCaptcha(tenantId, username, code, uuid, request);
    }

    // ② 真正的登录
    return login(username, password, tenantId);
}

public String login(String username, String password, String tenantId) {
    HttpServletRequest request = ServletUtils.getRequest();

    // ① 检查登录错误次数（防暴力破解）
    Integer errorNumber = RedisUtils.getCacheObject(
        Constants.LOGIN_ERROR + tenantId + ":" + username
    );
    if (ObjectUtil.isNotNull(errorNumber) && errorNumber.equals(Constants.LOGIN_ERROR_NUMBER)) {
        // 锁定
        throw new UserException("user.password.retry.limit.exceed", ...);
    }

    // ② 查用户
    SysUser user = loadUserByUsername(username, tenantId);

    // ③ 校验密码（BCrypt）
    if (!BCrypt.checkpw(password, user.getPassword())) {
        // 记录错误次数，达到上限就锁定
        errorNumber = ObjectUtil.isNull(errorNumber) ? 1 : errorNumber + 1;
        if (errorNumber.equals(Constants.LOGIN_ERROR_NUMBER)) {
            RedisUtils.setCacheObject(
                Constants.LOGIN_ERROR + tenantId + ":" + username,
                errorNumber,
                Duration.ofMinutes(Constants.LOGIN_ERROR_LIMIT_TIME)
            );
            throw new UserException("user.password.retry.limit.exceed", ...);
        } else {
            RedisUtils.setCacheObject(
                Constants.LOGIN_ERROR + tenantId + ":" + username,
                errorNumber
            );
            throw new UserException("user.password.retry.limit.count", errorNumber);
        }
    }

    // ④ 其他校验（用户状态、租户状态、密码过期等）
    // ...

    // ⑤ 生成 token（Sa-Token）
    // ...
    return token;
}
```

**⭐ 这段代码里，前端的 `password` 是明文传过来的。**

**前端有没有加密？**

**看 `login.vue`**：

```javascript
Cookies.set('password', encrypt(this.loginForm.password), { expires: 30 })
//                    ↑ 只在"记住密码"时加密存 Cookie
```

**但传给后端的是明文**：

```javascript
this.$store.dispatch('Login', this.loginForm)
// loginForm.password 是明文
```

**⚠️ 所以密码在传输中是明文的（靠 HTTPS 保护）。**

**后端用 `BCrypt.checkpw(password, user.getPassword())` 校验** ——
数据库里存的是 BCrypt 哈希。

**⭐ 这是正确做法**：前端不加密（HTTPS 保证传输安全），后端用 BCrypt 存哈希。

# 10.3 ⭐ 统一返回格式：`R` vs `TableDataInfo`

**这是最容易混的一点，必须讲清。**

## 两个类

### `R<T>` —— 单条数据 / 操作结果

**位置**：`ruoyi-base/ruoyi-common/src/main/java/com/ruoyi/common/core/domain/R.java`

```java
public class R<T> implements Serializable {
    private int code;
    private String msg;
    private T data;

    public static <T> R<T> ok(T data) { ... }         // 成功 + 数据
    public static <T> R<T> ok() { ... }                // 成功 + 无数据
    public static <T> R<T> ok(String msg) { ... }      // 成功 + 消息
    public static <T> R<T> fail(String msg) { ... }    // 失败
    // ...
}
```

**JSON 长这样**：

```json
{ "code": 200, "msg": "操作成功", "data": { ... } }
```

### `TableDataInfo<T>` —— 分页列表

**位置**：`ruoyi-base/ruoyi-common/src/main/java/com/ruoyi/common/core/page/TableDataInfo.java`

```java
public class TableDataInfo<T> implements Serializable {
    private long total;        // ★ 总条数
    private List<T> rows;      // ★ 当前页数据
    private int code;
    private String msg;

    public static <T> TableDataInfo<T> build(IPage<T> page) { ... }
}
```

**JSON 长这样**：

```json
{ "code": 200, "msg": "查询成功", "total": 53, "rows": [ ... ] }
```

## ⭐⭐ 关键区别

| | `R<T>` | `TableDataInfo<T>` |
|---|---|---|
| 数据字段名 | **`data`** | **`rows`** |
| 有总数吗 | ❌ | ✅ **`total`** |
| 用在哪 | 单条查询、增删改 | **分页列表** |
| 前端取值 | `response.data` | **`response.rows`** |

## 前端怎么用

### 单条 / 操作结果 → `response.data`

**例子**：查详情 `api/contract/contractDraft.js`

```javascript
export function getContractDraft(id) {
  return request({
    url: "/contract/contractDraft/" + id,
    method: "get"
  })
}
```

**页面里**：

```javascript
getContractDraft(id).then(response => {
  this.form = response.data        // ★ R<T> 的 data
})
```

**后端**：

```java
@GetMapping("/{id}")
public R<ContractDraftVo> getInfo(@PathVariable String id) {
    return R.ok(iContractDraftService.queryById(id));
}
//        ↑ R.ok(data)  →  JSON 的 data 字段
```

### 分页列表 → `response.rows`

**例子**：`api/contract/contractDraft.js`

```javascript
export function listContractDraft(query) {
  return request({
    url: "/contract/contractDraft/list",
    method: "get",
    params: query
  })
}
```

**页面里**：

```javascript
listContractDraft(this.queryParams).then(response => {
  this.contractDraftList = response.rows      // ★ TableDataInfo 的 rows
  this.total = response.total                 // ★ TableDataInfo 的 total
})
```

**后端**：

```java
@GetMapping("/list")
public TableDataInfo<ContractDraftVo> list(ContractDraftBo bo, PageQuery pageQuery) {
    return iContractDraftService.queryPageList(bo, pageQuery);
}
//         ↑ 返回 TableDataInfo，含 rows + total
```

**Service 里怎么构造**（参考 RuoYi 惯例）：

```java
@Override
public TableDataInfo<ContractDraftVo> queryPageList(ContractDraftBo bo, PageQuery pageQuery) {
    LambdaQueryWrapper<ContractDraft> lqw = buildQueryWrapper(bo);
    Page<ContractDraftVo> result = baseMapper.selectVoPage(pageQuery.build(), lqw);
    return TableDataInfo.build(result);
    //      ↑ 自动把 Page 转成 { total, rows }
}
```

## ⚠️ 混用会怎样

**错误 1**：分页接口用 `response.data`

```javascript
listContractDraft(...).then(response => {
  this.contractDraftList = response.data      // ❌ undefined
  // TableDataInfo 里没有 data 字段，只有 rows
})
```

**结果**：`this.contractDraftList = undefined` → 表格显示"暂无数据"。

**错误 2**：单条查询用 `response.rows`

```javascript
getContractDraft(id).then(response => {
  this.form = response.rows                   // ❌ undefined
  // R<T> 里没有 rows 字段，只有 data
})
```

## ⭐ 记忆口诀

```
R<T>            →  单个对象装 "data"
TableDataInfo   →  一堆对象装 "rows"，还附带 "total"
```

**或者**：

```
有分页（有 total）  →  rows
无分页（单条/操作）  →  data
```

# 10.4 参数绑定对照

## 四种场景

| 前端写法 | 后端注解 | 说明 |
|---|---|---|
| `params: query`（GET） | `ContractDraftBo bo`（无注解） | **参数从 URL 问号后取**，按名字绑定 |
| `data: data`（POST/PUT） | `@RequestBody DemoBo bo` | **参数从请求体取**，JSON 转对象 |
| `url: '/xxx/' + id` | `@PathVariable("id") Long id` | **参数在 URL 路径里** |
| `data: {a, b}` + 表单格式 | `@RequestParam("a") String a` | 表单提交 |

## ⭐ 逐个举例

### ① GET + `params` → 无注解参数绑定

**前端**：

```javascript
export function listContractDraft(query) {
  return request({
    url: "/contract/contractDraft/list",
    method: "get",
    params: query        // { pageNum: 1, pageSize: 10, contractName: 'xxx' }
  })
}
```

**实际请求**：

```
GET /contract/contractDraft/list?pageNum=1&pageSize=10&contractName=xxx
```

**后端**（`zhaoxin-contract/zxcm-contract/.../ContractDraftController.java`）：

```java
@GetMapping("/list")
public TableDataInfo<ContractDraftVo> list(ContractDraftBo bo, PageQuery pageQuery) {
    return iContractDraftService.queryPageList(bo, pageQuery);
}
```

**⭐ 关键：`ContractDraftBo bo` 前面没有注解！**

Spring 会**按参数名自动绑定** URL 参数：

```
?contractName=xxx   →   bo.setContractName("xxx")
?pageNum=1          →   pageQuery.setPageNum(1)
```

**⚠️ 前提：参数名必须一致。**

**`ContractDraftBo` 的字段**：

```java
@Data
@EqualsAndHashCode(callSuper = true)
public class ContractDraftBo extends BaseEntity {
    private String contractName;
    private String contractType;
    // ...
}
```

**`PageQuery` 的字段**：

```java
public class PageQuery implements Serializable {
    private Integer pageNum;
    private Integer pageSize;
    private String orderByColumn;
    private String isAsc;
    // ...
}
```

### ② POST/PUT + `data` → `@RequestBody`

**前端**：

```javascript
export function addDemo(data) {
  return request({
    url: '/demo',
    method: 'post',
    data: data          // { name: 'x', code: 'y' }
  })
}
```

**实际请求**：

```
POST /demo
Content-Type: application/json

{"name":"x","code":"y"}
```

**后端**：

```java
@PostMapping
public R<Void> add(@Validated(AddGroup.class) @RequestBody DemoBo bo) {
    return toAjax(iDemoService.insertByBo(bo));
}
```

**⭐ `@RequestBody` = 从请求体读 JSON。**

### ③ URL 路径 → `@PathVariable`

**前端**：

```javascript
export function delDemo(id) {
  return request({
    url: '/demo/' + id,        // /demo/123
    method: 'delete'
  })
}
```

**后端**：

```java
@DeleteMapping("/{ids}")
public R<Void> remove(@PathVariable Long[] ids) {
    //                        ↑ 从 URL 路径里取 {ids}
}
```

**⭐ `@PathVariable` = 从 URL 路径变量取。**

**⚠️ 路径变量的名字必须匹配**：

```java
@GetMapping("/{id}")  →  前端 url: '/xxx/' + id         ✅
@GetMapping("/{userId}") → 前端 url: '/xxx/' + id       ✅
                           但方法参数要 @PathVariable("userId") Long id
```

## ⭐ 三种注解的对照图

```
HTTP 请求
┌─────────────────────────────────────────────────────┐
│ POST /demo/123?status=0                             │
│      ↑         ↑                                    │
│      │         └── 查询参数（?后）                    │
│      │             → 前端 params                      │
│      │             → 后端 无注解 / @RequestParam      │
│      │                                              │
│      └── 路径变量                                    │
│          → 前端 拼在 url 里                           │
│          → 后端 @PathVariable                        │
│                                                     │
│ Header: token: Bearer xxx                           │
│          → 前端 headers                              │
│          → 后端 @RequestHeader("token")              │
│                                                     │
│ Body: {"name":"x"}                                  │
│          → 前端 data                                 │
│          → 后端 @RequestBody                         │
└─────────────────────────────────────────────────────┘
```

## ⭐ 参数名不一致怎么办

**前端传 `contract_name`，后端字段是 `contractName`。**

**三种解决**：

**① 前端改**（推荐）

```javascript
params: { contractName: xxx }
```

**② 后端加 `@RequestParam`**

```java
@GetMapping("/list")
public R<?> list(@RequestParam("contract_name") String contractName) { ... }
```

**③ 后端用 `@JsonProperty`**

```java
@JsonProperty("contract_name")
private String contractName;
```

**⭐ 项目里的惯例**：前端和后端**字段名完全一致**（都用 camelCase）。

# 10.5 校验对照

## 前端校验

**位置**：`views/**/*.vue`

```javascript
data() {
  return {
    form: {},
    rules: {
      name: [
        { required: true, message: '名称不能为空', trigger: 'blur' }
      ],
      code: [
        { required: true, message: '编码不能为空', trigger: 'blur' },
        { min: 2, max: 20, message: '长度在 2 到 20 个字符', trigger: 'blur' }
      ]
    }
  }
}
```

```html
<el-form ref="form" :model="form" :rules="rules">
  <el-form-item label="名称" prop="name">
    <el-input v-model="form.name" />
  </el-form-item>
</el-form>
```

```javascript
submitForm() {
  this.$refs.form.validate(valid => {
    if (!valid) return         // ★ 校验不通过就返回
    // 提交...
  })
}
```

## 后端校验

**位置**：`*Bo.java`

```java
@Data
@EqualsAndHashCode(callSuper = true)
public class DemoBo extends BaseEntity {

    @NotNull(message = "id不能为空", groups = { EditGroup.class })
    private Long id;

    @NotBlank(message = "名称不能为空", groups = { AddGroup.class, EditGroup.class })
    private String name;

    @NotBlank(message = "编码不能为空", groups = { AddGroup.class, EditGroup.class })
    @Size(min = 2, max = 20, message = "长度在 2 到 20 个字符")
    private String code;

    @NotBlank(message = "状态不能为空", groups = { AddGroup.class, EditGroup.class })
    private String status;
}
```

```java
@PostMapping
public R<Void> add(@Validated(AddGroup.class) @RequestBody DemoBo bo) {
    //             ↑ 触发校验，AddGroup 组
    return toAjax(iDemoService.insertByBo(bo));
}

@PutMapping
public R<Void> edit(@Validated(EditGroup.class) @RequestBody DemoBo bo) {
    //             ↑ EditGroup 组（会校验 id 非空）
    return toAjax(iDemoService.updateByBo(bo));
}
```

## ⭐ 为什么要做两遍校验

| 层 | 目的 | 能省略吗 |
|---|---|---|
| **前端** | **用户体验**（立即提示，不用等网络） | ✅ 能（但体验差） |
| **后端** | **数据安全**（防止绕过前端） | ❌ **绝对不能** |

**⚠️ 只做前端校验 = 没有校验**（用户可以绕过）。

**只做后端校验 = 体验差**（要等请求回来才知道错了）。

**所以两层都要做。**

## ⭐ 分组校验（`AddGroup` / `EditGroup`）

**问题**：新增时 `id` 应该为空（数据库自动生成），
修改时 `id` 必须有值。

**一个 BO 怎么同时满足？**

```java
@NotNull(message = "id不能为空", groups = { EditGroup.class })   // ★ 只在修改时校验
private Long id;

@NotBlank(message = "名称不能为空", groups = { AddGroup.class, EditGroup.class })   // ★ 新增和修改都校验
private String name;
```

**Controller 指定用哪组**：

```java
@PostMapping
public R<Void> add(@Validated(AddGroup.class) @RequestBody DemoBo bo)   // 只校验 AddGroup

@PutMapping
public R<Void> edit(@Validated(EditGroup.class) @RequestBody DemoBo bo)  // 只校验 EditGroup
```

**⭐ 这就是"一个 BO 服务两个接口"的技巧。**

## 校验注解对照表

| 前端 Element 规则 | 后端注解 |
|---|---|
| `{ required: true }` | `@NotNull` / `@NotBlank` / `@NotEmpty` |
| `{ min: 2, max: 20 }` | `@Size(min = 2, max = 20)` |
| `{ type: 'email' }` | `@Email` |
| `{ pattern: /^\d+$/ }` | `@Pattern(regexp = "^\\d+$")` |
| `{ type: 'number' }` | `@Digits` / `@Min` / `@Max` |

**⭐ 注意三个 `Not` 的区别**：

| 注解 | 拒绝什么 | 用在哪 |
|---|---|---|
| `@NotNull` | `null` | 对象、数字 |
| `@NotBlank` | `null` + 空串 + 纯空格 | **字符串**（最常用） |
| `@NotEmpty` | `null` + 空集合/空串 | 集合、数组 |

# 10.6 权限对照

## 一张表

| 前端 | 后端 | 位置 |
|---|---|---|
| `v-hasPermi="['demo:add']"` | `@SaCheckPermission("demo:add")` | 按钮 / 接口方法 |
| `v-hasRole="['admin']"` | `@SaCheckRole("admin")` | 按钮 / 接口方法 |
| `plugins/auth.js` 的 `hasPermi()` | `StpUtil.hasPermission()` | 代码里手动判断 |

## 前端：按钮级

```html
<el-button
  v-hasPermi="['demo:add']"
  @click="handleAdd"
>新增</el-button>
```

**效果**：没权限 → **按钮从 DOM 消失**。

## 后端：接口级

```java
@SaCheckPermission("demo:add")
@PostMapping
public R<Void> add(@RequestBody DemoBo bo) { ... }
```

**效果**：没权限 → **抛 `NotPermissionException` → 返回 403**。

## ⭐ 两处必须一致

```
数据库 sys_menu.perms     = 'demo:add'
前端 v-hasPermi           = ['demo:add']
后端 @SaCheckPermission   = "demo:add"
```

**⚠️ 三处任何一处不同，权限就废。**

## ⭐ `@SaCheckRole` 的用法

```java
@SaCheckRole("admin")                    // 只允许 admin 角色
@GetMapping("/admin-only")
public R<?> adminOnly() { ... }

@SaCheckRole(value = {"admin", "manager"}, mode = SaMode.OR)    // admin 或 manager
@GetMapping("/manager")
public R<?> managerAccess() { ... }
```

**前端对应**：

```html
<el-button v-hasRole="['admin']">仅管理员</el-button>
```

## ⚠️ 只有后端才是防线

**复习第 7 章的结论**：

```
前端权限 = 藏按钮（防手滑）
后端权限 = 真检查（防黑客）
```

**验证方法**：

```javascript
// F12 → Console，绕过前端直接调
fetch('/dev-api/demo/1', {
  method: 'DELETE',
  headers: { 'token': 'Bearer ' + token }
})
// 后端有 @SaCheckPermission → 403 ✅
// 后端没有               → 删除成功 ❌（漏洞）
```

# 10.7 状态管理对照：Vuex vs Spring 单例 Bean

## 一张表

| Vuex | Spring | 说明 |
|---|---|---|
| `state` | 单例 Bean 的字段 | 数据 |
| `mutations` | setter（同步） | 改数据 |
| `actions` | Service 方法（可异步） | 业务逻辑 |
| `getters` | DTO / 只读视图 | 取数据 |
| `dispatch('xxx')` | `service.xxx()` | 调方法 |
| `commit('SET_X')` | `entity.setX()` | 改字段 |

## 例子对照

### Vuex（`store/modules/user.js`）

```javascript
const user = {
  state: {
    token: getToken(),
    roles: [],
    permissions: []
  },

  mutations: {
    SET_TOKEN: (state, token) => {
      state.token = token
    },
    SET_ROLES: (state, roles) => {
      state.roles = roles
    }
  },

  actions: {
    Login({ commit }, userInfo) {
      return new Promise((resolve, reject) => {
        login(...).then(res => {
          setToken(res.data.token)
          commit('SET_TOKEN', res.data.token)
          resolve()
        }).catch(reject)
      })
    }
  }
}
```

### Spring 类比

```java
@Component   // ≈ Vuex 的 module
public class UserStore {

    // state
    private String token = readTokenFromCookie();
    private List<String> roles = new ArrayList<>();
    private List<String> permissions = new ArrayList<>();

    // getters（只读访问）
    public String getToken() { return token; }
    public List<String> getRoles() { return roles; }

    // mutations（同步改）
    private void setToken(String token) { this.token = token; }

    // actions（异步业务）
    @Autowired
    private LoginClient loginClient;

    public void login(LoginBody body) {
        R<Map<String, Object>> res = loginClient.login(body);
        String newToken = (String) res.getData().get("token");
        writeTokenToCookie(newToken);
        setToken(newToken);              // ← 相当于 commit
    }
}
```

**⭐ 结构几乎一模一样**，只是 JS 用约定（`state`/`mutations`/`actions` 三个对象），
Java 用类的方法。

## ⭐ 关键差异：前端的 state 是"响应式"的

```javascript
state.roles = ['admin']
// 所有用到 roles 的地方【自动重新渲染】
```

**Java 里没这个概念**（后端没有"界面"，不需要响应式）。

**这是前端独有的机制**（第 3 章讲过）。

## 为什么前端需要 Vuex

**问题**：多个不相关的组件要共享数据（如 `token`、`roles`）。

**不用 Vuex 会怎样**：

```
组件 A 拿到 roles
  ↓ 想给组件 B 用
只能：
  ﹣ 逐层 props 传递（深层嵌套很痛苦）
  ﹣ 用 $EventBus（难追踪）
  ﹣ 存 localStorage（不响应式）
```

**用 Vuex**：所有组件 `this.$store.getters.xxx` 直接取，**且响应式**。

**类比 Java**：所有 Service `@Autowired` 注入同一个单例 Bean。

# 10.8 异常处理对照

## 前端：响应拦截器

```javascript
// src/utils/request.js
service.interceptors.response.use(res => {
    const code = res.data.code || 200

    if (code === 401) {
      // 登录过期 → 弹窗 → 登出 → 跳首页
      return Promise.reject('无效的会话...')
    } else if (code === 500) {
      Message({ message: msg, type: 'error' })
      return Promise.reject(new Error(msg))
    } else if (code !== 200) {
      Notification.error({ title: msg })
      return Promise.reject('error')
    } else {
      return res.data
    }
  },
  error => {
    // HTTP 层失败（断网、超时、跨域）
    let { message } = error
    if (message == "Network Error") {
      message = "后端接口连接异常"
    } else if (message.includes("timeout")) {
      message = "系统接口请求超时"
    }
    Message({ message, type: 'error', duration: 5 * 1000 })
    return Promise.reject(error)
  }
)
```

## 后端：`@RestControllerAdvice`

**位置**：`ruoyi-base/ruoyi-framework/.../handler/GlobalExceptionHandler.java`（大意）

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 业务异常
    @ExceptionHandler(ServiceException.class)
    public R<Void> handleServiceException(ServiceException e, HttpServletRequest request) {
        return R.fail(e.getMessage());
    }

    // 权限异常（@SaCheckPermission 拦住时抛这个）
    @ExceptionHandler(NotPermissionException.class)
    public R<Void> handleNotPermissionException(NotPermissionException e) {
        return R.fail(HttpStatus.FORBIDDEN, "没有访问权限，请联系管理员授权");
    }

    // 参数校验异常（@Validated 失败）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleMethodArgumentNotValidException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldError().getDefaultMessage();
        return R.fail(message);
    }

    // 兜底：所有未捕获的异常
    @ExceptionHandler(Exception.class)
    public R<Void> handleException(Exception e) {
        log.error("请求地址'{}',发生系统异常.", request.getRequestURI(), e);
        return R.fail("系统异常，请联系管理员");
    }
}
```

## ⭐ 对照关系

| 前端 | 后端 |
|---|---|
| 响应拦截器按 `code` 分支 | `@ExceptionHandler` 按异常类型分支 |
| `code === 500` → 弹 Message | `ServiceException` → `R.fail(msg)` |
| `code === 401` → 跳登录 | `NotLoginException` → `R.fail(401)` |
| `code === 403`（由 `code !== 200` 分支处理） | `NotPermissionException` → `R.fail(403)` |

**⭐ 一个完整链路**：

```
后端 throws ServiceException("合同类型已被使用")
    ↓
GlobalExceptionHandler 捕获
    ↓
返回 { code: 500, msg: "合同类型已被使用" }
    ↓
前端响应拦截器：code === 500
    ↓
Message({ message: "合同类型已被使用", type: 'error' })
    ↓
用户看到顶部红色提示
```

# 10.9 生命周期对照

| 前端 | 后端 | 时机 |
|---|---|---|
| `beforeCreate` | （无对应） | 实例创建前 |
| **`created`** | **`@PostConstruct`** | **初始化完成**（发请求在这） |
| `beforeMount` | （无） | 模板编译完 |
| **`mounted`** | （无对应） | **DOM 渲染完**（能操作 DOM） |
| `beforeUpdate` / `updated` | （无） | 数据变化、DOM 更新 |
| **`beforeDestroy`** | **`@PreDestroy`** | **销毁前**（清理资源） |
| `destroyed` | （无） | 销毁完成 |

## ⭐ 最常用的两个

### `created` ≈ `@PostConstruct`

```javascript
created() {
  this.getList()        // 组件创建后立即拿数据
}
```

```java
@PostConstruct
public void init() {
    loadConfig();         // Bean 创建后立即执行
}
```

### `beforeDestroy` ≈ `@PreDestroy`

```javascript
beforeDestroy() {
  clearInterval(this.timer)        // 清理定时器
  this.$EventBus.$off('reloadPage')
  if (this.refreshChannel) this.refreshChannel.close()
}
```

```java
@PreDestroy
public void destroy() {
    executor.shutdown();           // 关闭线程池
    connection.close();
}
```

**⭐ 两者的共同点**：**销毁前必须清理外部资源**（否则内存泄漏）。

## ⚠️ 前端特有的坑：DOM 相关只能在 `mounted`

```javascript
created() {
  console.log(this.$refs.myInput)      // ❌ undefined（DOM 还没渲染）
},
mounted() {
  console.log(this.$refs.myInput)      // ✅ 拿到元素
}
```

**Java 里没这个问题**（后端没有 DOM）。

# 10.11 自测

1. 前端的 `api/*.js` 相当于后端的哪一层？
2. 前端有真正的"业务层"吗？业务规则通常在哪？
3. `R<T>` 和 `TableDataInfo<T>` 的数据字段名分别是什么？
4. 分页接口前端应该取 `response.` 什么？
5. 前端 `params` 对应后端的什么注解？
6. 前端 `data` 对应后端的什么注解？
7. URL 路径变量对应后端的什么注解？
8. 前端 `rules` 校验和后端 `@Validated` 能只做一个吗？为什么？
9. `@NotBlank` 和 `@NotNull` 有什么区别？
10. 分组校验解决什么问题？
11. `v-hasPermi` 和 `@SaCheckPermission` 哪个是安全防线？
12. Vuex 的 `state` / `mutations` / `actions` 分别对应 Java 的什么？
13. 后端的 `ServiceException` 最终会变成前端的什么？
14. `created` 和 `mounted` 分别对应后端的什么？
15. `beforeDestroy` 里必须做什么？

<details>
<summary>答案</summary>

1. **`Mapper` 层**（都是"数据访问"）
2. **没有真正的业务层**。业务规则主要在**后端**；前端的"业务逻辑"是界面逻辑（拼参数、改显示）
3. `R<T>` → **`data`**；`TableDataInfo<T>` → **`rows`**（+ `total`）
4. **`response.rows`** 和 **`response.total`**
5. **无注解**（按参数名自动绑定）或 `@RequestParam`
6. **`@RequestBody`**
7. **`@PathVariable`**
8. **不能只做一个**。只做前端 = 没校验（可绕过）；只做后端 = 体验差（要等请求回来）
9. `@NotNull` 只拒绝 `null`；**`@NotBlank` 还拒绝空串和纯空格**（用于字符串）
10. 让**一个 BO 同时服务新增和修改**（新增时 id 不必填，修改时 id 必填）
11. **`@SaCheckPermission`**（后端才是防线）
12. `state` ≈ 单例 Bean 的字段；`mutations` ≈ setter（同步）；`actions` ≈ Service 方法（可异步）
13. 后端 `GlobalExceptionHandler` 捕获 → 返回 `{ code:500, msg }` → 前端响应拦截器 → **`Message` 红色提示**
14. `created` ≈ **`@PostConstruct`**；`mounted` → **无对应**（后端没 DOM）
15. **清理外部资源**：定时器、事件监听、`BroadcastChannel` 等（防内存泄漏）
</details>
