# 11.1 30 个坑

## A 组：语法坑（JS 特有）

### 坑 1：`x => { x + 1 }` 返回 `undefined`

```javascript
const f1 = x => x + 1        // ✅ 返回 x+1
const f2 = x => { x + 1 }    // ❌ 返回 undefined（有 {} 没 return）
```

**规则：有 `{}` 就必须有 `return`。**

### 坑 2：`const` 不锁"内容"

```javascript
const arr = [1, 2]
arr.push(3)          // ✅ 允许
arr = [1]            // ❌ 报错
```

**`const` 只锁"不能重新赋值"**（≈ Java 的 `final`）。

### 坑 3：`||` 会把 `0` / `''` 当"没有"

```javascript
const num = 0
num || 10            // 10  ❌ 如果 0 是有效值，这是 bug
num ?? 10            // 0   ✅
```

**要保留 `0`/`''`/`false` 时用 `??`。**

### 坑 4：浅拷贝的坑

```javascript
const a = { x: 1, nested: { y: 2 } }
const b = { ...a }
b.nested.y = 999
console.log(a.nested.y)     // 999 ❌ 被污染
```

**`...` 只复制第一层。** 深拷贝用 `JSON.parse(JSON.stringify(x))`。

### 坑 5：`==` vs `===`

```javascript
1 == '1'        // true  ⚠️
1 === '1'       // false ✅
```

**永远用 `===`。**

### 坑 6：`?.` 只防 `null`/`undefined`

```javascript
const obj = { a: 0 }
console.log(obj?.a)          // 0（正常）
console.log(obj?.b?.c)       // undefined（不报错）
```

**但 `obj.a.b` 如果 `a` 是 `0`，还是会报错**（`?.` 只看是不是 null/undefined）。

## B 组：请求坑（request.js）

### 坑 7：`=== false` 不能写成 `!isToken` ⚠️⚠️

```javascript
// src/utils/request.js:29
const isToken = (config.headers || {}).isToken === false
```

**为什么？**

| 情况 | `.isToken` | `=== false` | `!isToken` |
|---|---|---|---|
| 没写 | `undefined` | `false` ✅ | **`true`** ❌ |
| `true` | `true` | `false` ✅ | `false` ✅ |
| `false` | `false` | `true` ✅ | `true` ✅ |

**用 `!isToken` → 所有没写 `isToken` 的请求都不带 token → 全站 401。**

### 坑 8：请求头名是 `token` 不是 `Authorization`

```javascript
config.headers['token'] = 'Bearer ' + getToken()
//                    ↑ 由后端 sa-token.token-name 决定
```

**后端**：

```yaml
sa-token:
  token-name: token
```

**两边必须一致。**

### 坑 9：`Bearer` 后必须有空格

```javascript
'Bearer ' + getToken()      // ✅
'Bearer' + getToken()       // ❌ "BearereyJ..."
```

### 坑 10：`config.params = {}` 必须清空

```javascript
if (config.method === 'get' && config.params) {
  let url = config.url + '?' + tansParams(config.params)
  url = url.slice(0, -1)
  config.params = {}          // ★ 不清空会变成 ?a=1&a=1
  config.url = url
}
```

### 坑 11：拦截器忘了 `return config`

```javascript
service.interceptors.request.use(config => {
  // ... 加工
  return config        // ★ 不 return 请求就丢了
})
```

### 坑 12：前端校验 ≠ 后端校验

**只做前端 = 没有校验**（用户绕过前端直接调接口）。

**后端必须再校验一遍。**

### 坑 13：`isToken: false` 是前端独有约定

**后端完全不知道这个标记**（它只被 `request.js` 读取）。

### 坑 14：忘记 `response.rows` vs `response.data`

```javascript
// 分页接口 → rows
listXxx().then(response => {
  this.list = response.rows
  this.total = response.total
})

// 单条接口 → data
getXxx(id).then(response => {
  this.form = response.data
})
```

**混用 → `undefined` → 表格"暂无数据"。**

### 坑 15：GET 用 `params`，POST/PUT 用 `data`

```javascript
// ✅ GET
request({ url: '/x', method: 'get', params: query })

// ✅ POST
request({ url: '/x', method: 'post', data: body })

// ❌ POST 用 params → 参数拼到 URL，@RequestBody 收不到
```

## C 组：Vue 坑

### 坑 16：`v-for` 用 index 当 key

```html
<!-- ❌ 删除中间元素会错乱 -->
<div v-for="(item, index) in list" :key="index">

<!-- ✅ -->
<div v-for="item in list" :key="item.id">
```

### 坑 17：Vue 2 新增属性不响应

```javascript
this.user.age = 20                // ❌ Vue 2 检测不到
this.$set(this.user, 'age', 20)   // ✅
this.user = { ...this.user, age: 20 }    // ✅
```

### 坑 18：数组按索引赋值不响应

```javascript
this.list[0] = newItem      // ❌
this.list.splice(0, 1, newItem)    // ✅
this.list = [...]                  // ✅
```

### 坑 19：`this` 丢失

```javascript
setTimeout(function() {
  this.list = data          // ❌ this 不是组件
}, 100)

setTimeout(() => {
  this.list = data          // ✅ 箭头函数
}, 100)
```

### 坑 20：`created` 里拿不到 `$refs`

```javascript
created() {
  this.$refs.form            // ❌ undefined（DOM 还没渲染）
},
mounted() {
  this.$refs.form            // ✅
}
```

### 坑 21：`beforeDestroy` 忘了清理

```javascript
created() {
  this.timer = setInterval(...)      // 定时器
  this.$EventBus.$on('x', fn)         // 事件监听
},
beforeDestroy() {
  clearInterval(this.timer)           // ★ 必须清理
  this.$EventBus.$off('x')
}
```

**不清理 → 内存泄漏 + 无用请求。**

### 坑 22：`$nextTick` 用错时机

```javascript
this.showDialog = true
this.$refs.dialog.init()        // ❌ dialog 还没渲染

this.showDialog = true
this.$nextTick(() => {
  this.$refs.dialog.init()      // ✅
})
```

### 坑 23：`data()` 必须是函数

```javascript
data: { count: 0 }              // ❌ 多个实例共享数据
data() { return { count: 0 } }  // ✅ 每次返回新对象
```

### 坑 24：全局注册的组件无法 tree-shaking

```javascript
Vue.component("X", X)     // ⚠️ 即使不用也会进 bundle
```

**只在"几乎所有页面都用"时才全局注册。**

```
数据库：contract/contractDraft/index
文件：  src/views/contract/contractDraft/index.vue
```

**⚠️ Windows 不区分大小写，Linux 区分。**

**这是"本地正常、服务器 404"的经典原因。**

### 坑 28：`v-hasPermi` 必须传数组

```html
v-hasPermi="['a:b:c']"      <!-- ✅ -->

```

### 坑 29：`dynamicRoutes` 不写 `permissions` 会被丢弃

```javascript
{
  path: '/x',
  // 既没 permissions 也没 roles
}
// → filterDynamicRoutes 会丢弃它
```

### 坑 30：权限码三处必须一致

```
数据库 sys_menu.perms   = 'demo:add'
前端 v-hasPermi         = ['demo:add']
后端 @SaCheckPermission = "demo:add"
```

**任何一处不同 → 权限失效。**

# 11.2 错误信息速查表

## 控制台报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `Cannot read property 'x' of undefined` | 访问了 undefined 的属性 | 加 `?.` 或检查数据 |
| `Cannot read property 'resetFields' of undefined` | 表单还没渲染 | 包 `$nextTick` |
| `Unknown custom element: <xxx>` | 组件没注册 | 检查 `components: {}` 或全局注册 |
| `Property or method "xxx" is not defined` | 模板用了不存在的字段 | 加到 `data()` 或 `computed` |
| `Invalid Component definition` | `component` 给了字符串 | 用 `loadView` 翻译 |
| `Cannot find module '@/views/xxx'` | 路径错/文件不存在 | 检查路径和大小写 |
| `NavigationDuplicated` | 跳到当前路由 | `.catch(() => {})` 忽略 |
| `请设置操作权限标签值` | `v-hasPermi` 传了字符串 | 改成数组 |
| `ERR_OSSL_EVP_UNSUPPORTED` | Node 版本太高 | 用 Node 16/18 |
| `Module build failed` | 语法错误 | 看具体行号 |

## 请求状态码

| 状态码 | 含义 | 排查 |
|---|---|---|
| **200** | 成功 | 看 `code` 字段（可能是业务失败） |
| **400** | 参数错误 | 看后端 `@Validated` 校验信息 |
| **401** | 未登录/过期 | 检查 token（头名、格式、Cookie） |
| **403** | 无权限 | 检查 `@SaCheckPermission` 和权限码 |
| **404** | 接口不存在 | URL 错 / 后端没这个接口 |
| **405** | 方法不允许 | GET/POST 用反了 |
| **500** | 服务器错误 | 看后端日志堆栈 |
| **502/504** | 网关错误 | 后端没起 / 超时 |

## 页面现象

| 现象 | 第一站 | 可能原因 |
|---|---|---|
| 白屏 | Console | JS 报错 / Vue 没启动 |
| 菜单不显示 | Network `/getRouters` | `sys_menu` / 角色分配 / 缓存 |
| 按钮不显示 | Vuex `permissions` | 权限码不一致 |
| 表格"暂无数据" | Network Response | 后端没数据 / 前端赋值错 |
| 表单提交没反应 | Console | 校验没过 / 事件没绑定 |
| 样式错乱 | Elements | CSS 冲突 / scoped 失效 |
| 改代码不生效 | 终端 | 编译失败 / 缓存 |

# 11.3 25 道面试题

## 一、基础概念（1-8）

### Q1：Vue 是 MVVM 吗？怎么理解？

**答**：

> Vue 是 **MVVM**（Model-View-ViewModel）模式的实现，但更准确说是**响应式数据绑定**。
>
> - **Model**：`data()` 里的数据
> - **View**：`<template>` 渲染出来的 DOM
> - **ViewModel**：Vue 实例本身，负责把 Model 和 View 双向连接
>
> **核心是"数据驱动"**：改 Model（数据），View 自动更新；用户在 View 上输入（`v-model`），Model 自动更新。
>
> **类比**：像 Excel 的单元格和图表——改单元格，图表自动重画。
>
> **和传统 jQuery 的区别**：jQuery 是"命令式"（手动操作 DOM），Vue 是"声明式"（描述数据和界面的关系，框架负责更新）。

### Q2：`v-if` 和 `v-show` 的区别？怎么选？

**答**：

> **区别是"是否真的销毁 DOM"**：
>
> | | `v-if` | `v-show` |
> |---|---|---|
> | 实现 | 销毁/重建 DOM | 改 CSS `display: none` |
> | 初始开销 | 条件为假时不渲染 | **总是渲染** |
> | 切换开销 | 大（重建） | **小**（只改样式） |
> | 能拿到 DOM 吗 | 假时拿不到 | **能**（只是隐藏） |
>
> **选择**：
> - 条件**很少变** → `v-if`（省初始渲染成本）
> - 条件**频繁切换** → `v-show`（省切换成本）
>
> **项目里的实际用法**：
> - 搜索区折叠：`v-show="showSearch"`（经常切换）
> - 弹窗：`v-if="showDialog"`（很少打开，不需要一直渲染）
>
> **⚠️ 安全相关**：如果用来"隐藏敏感信息"，`v-show` 不安全（F12 能看到 DOM），必须用 `v-if` 或干脆不渲染。

### Q3：为什么 `v-for` 要加 `:key`？为什么不能用 index？

**答**：

> **`key` 是 Vue 用来"识别每个元素身份"的标记**，用于 diff 算法优化。
>
> **不用 index 的原因**：删除中间元素时，index 会变，Vue 会误判"内容变了"而不是"元素被删了"，导致**复用错误的 DOM**。
>
> **例子**：
> ```javascript
> // 原列表
> [{ id: 1, name: 'A' }, { id: 2, name: 'B' }]
> // 删除 A 后
> [{ id: 2, name: 'B' }]
> ```
> - 用 index 当 key：Vue 以为"第 0 个元素的内容从 A 变成 B"了，会**复用第 0 个 DOM**（如果里面是输入框，内容会错乱）
> - 用 `item.id` 当 key：Vue 知道"id=1 的没了"，正确移除
>
> **所以要用"唯一且稳定"的 id。**

### Q4：`computed` 和 `methods` 的区别？

**答**：

> **三个区别**：
>
> | | `computed` | `methods` |
> |---|---|---|
> | **缓存** | ✅ 依赖不变就不重新计算 | ❌ 每次都执行 |
> | **用法** | `{{ fullName }}`（像属性） | `{{ getFullName() }}`（要调用） |
> | **适合** | 派生数据（只读） | 事件处理 / 有副作用 |
>
> **缓存的原理**：`computed` 会记录依赖（比如 `this.list`），只有依赖变了才重算。
>
> **⚠️ `computed` 里不能有副作用**（不能发请求、不能改数据），必须是纯函数。

### Q5：`created` 和 `mounted` 的区别？

**答**：

> | | `created` | `mounted` |
> |---|---|---|
> | DOM 存在吗 | ❌ 不存在 | ✅ 存在 |
> | 能拿 `$refs` 吗 | ❌ | ✅ |
> | 能操作 DOM 吗 | ❌ | ✅ |
> | 项目里用来 | **发请求** | 操作 DOM / 初始化图表 |
>
> **为什么发请求在 `created`？** 因为早一点发，能早点拿到数据。
>
> **为什么操作 DOM 必须在 `mounted`？** 因为 `created` 时 DOM 还没渲染出来。
>
> **类比后端**：`created` ≈ `@PostConstruct`。

### Q6：`props` 和 `data` 的区别？

**答**：

> | | `data` | `props` |
> |---|---|---|
> | 谁初始化 | **组件自己** | **父组件传入** |
> | 能改吗 | ✅ 自己随便改 | ❌ **不能改**（会警告） |
> | 数据流 | 内部状态 | **单向**：父 → 子 |
>
> **为什么 props 不能改？**
>
> 如果子组件能改父组件的数据，多个子组件同时改就乱了。
> **这叫"单向数据流"**，是 Vue 的核心理念。
>
> **子组件想改怎么办？** `$emit` 通知父组件，让父组件改。

### Q7：`$emit` 和 `$on` 是什么？

**答**：

> **组件通信机制**：
> - `$emit('事件名', 数据)`：**触发**事件（子 → 父）
> - `$on('事件名', 回调)`：**监听**事件
>
> **典型用法（子传父）**：
> ```html
> <!-- 子组件 -->
> <button @click="$emit('ok', data)">确定</button>
>
> <!-- 父组件 -->
> <Child @ok="handleOk" />
> ```
>
> **项目里的 `$EventBus`**：`main.js:85` 创建了一个空的 Vue 实例当"事件总线"，
> 用于**任意组件之间**通信（不只是父子）。
>
> ```javascript
> // A 组件发
> this.$EventBus.$emit('reloadPage')
> // B 组件收
> this.$EventBus.$on('reloadPage', this.getList)
> // ⚠️ beforeDestroy 里要 $off，否则内存泄漏
> ```

### Q8：Vue 2 的响应式原理是什么？

**答**：

> **Vue 2 用 `Object.defineProperty` 把 `data()` 里的每个属性改造成 getter/setter**。
>
> 流程：
> 1. `data()` 返回对象时，Vue 递归遍历所有属性
> 2. 每个属性用 `Object.defineProperty` 定义 getter/setter
> 3. getter 里**收集依赖**（记录"有哪些 Watcher 用了我"）
> 4. setter 里**通知更新**（依赖变了，通知 Watcher 重新渲染）
>
> **⚠️ 三个局限**：
> 1. **新增属性不响应**：`this.obj.newKey = 1` → 检测不到（要用 `$set`）
> 2. **数组按索引赋值不响应**：`this.arr[0] = x` → 检测不到（要用 `splice`）
> 3. **`length` 变化不响应**
>
> **Vue 3 用 `Proxy` 解决了这些问题**（能监听新增/删除属性）。

## 二、项目相关（9-18）

### Q9：这个项目的路由是怎么来的？为什么"加一条数据库记录就有新页面"？

**答**：

> **因为用的是「动态路由」**。完整链路：
>
> 1. 数据库 `sys_menu` 表存菜单（含 `path`、`component`）
> 2. 登录后前端调 `GET /getRouters`
> 3. 后端 `SysMenuServiceImpl.buildMenus()` 把表记录转成 `RouterVo` JSON 返回，
>    **`component` 是字符串**（如 `"contract/contractDraft/index"`）
> 4. 前端 `store/modules/permission.js` 的 `filterAsyncRouter()` 遍历，
>    用 `loadView()` 把字符串翻译成组件：
>    ```javascript
>    component: () => import('@/views/contract/contractDraft/index')
>    ```
> 5. `router.addRoutes()` 动态注册
> 6. 侧边栏用 `sidebarRouters` 渲染菜单
>
> **所以数据库里加一条菜单 + 给角色分配 → 刷新页面就有新菜单和新页面。**
>
> **⚠️ 关键细节**：`component` 不能带 `.vue`（webpack 自动补），大小写必须和文件一致（Linux 区分）。

### Q10：`next({ ...to, replace: true })` 为什么要这么写？

**答**：

> **因为 `addRoutes` 是异步生效的，当前这次跳转已经按旧路由表匹配过了。**
>
> 流程：
> ```
> 用户访问 /index
>   ↓ router 开始匹配（路由表里还没有 /index，因为是动态路由）
>   ↓ 匹配失败 → 准备跳 404
>   ↓ 【这时 beforeEach 才执行】
>   ↓ 我们执行 addRoutes()，路由表现在有 /index 了
>   ↓ 但本次跳转已经按"没匹配上"处理了
> ```
>
> **解决**：`next({ ...to, replace: true })` **重新触发一次跳转**，
> 让路由按新表重新匹配。
>
> **`{ ...to }`**：复制 `to` 的所有字段（因为 `to` 是只读对象，不能直接改）
> **`replace: true`**：替换历史记录，避免留下中间状态（否则用户点后退会回到那个状态又触发守卫）
>
> **这是 RuoYi 的标志性写法，几乎是必问题。**

### Q11：前端权限有哪几层？分别怎么实现？

**答**：

> **三层**：
>
> | 层 | 控制什么 | 实现 |
> |---|---|---|
> | **路由级** | 能不能打开页面 | 后端 `/getRouters` 按角色过滤 + 前端 `filterDynamicRoutes` |
> | **菜单级** | 侧边栏显示什么 | **后端已筛好**，前端只管渲染 `sidebarRouters` |
> | **按钮级** | 页面显示什么按钮 | `v-hasPermi` 指令 → `el.parentNode.removeChild(el)` |
>
> **数据来源**：`GET /getInfo` 返回 `roles` 和 `permissions`。
>
> **⭐ 关键认知**：**前端几乎不"判断"权限，只是"接收"**。
> 菜单是后端筛的，权限码是后端给的。

### Q12：前端权限能防住黑客吗？

**答**：

> **不能。前端权限只是"界面美化"，不是安全防线。**
>
> **能防住**：普通用户误点、看不到会报错的按钮（体验优化）
> **防不住**：会用 F12 的人
>
> **绕过方法**：
> ```javascript
> // F12 → Console
> fetch('/dev-api/demo/1', {
>   method: 'DELETE',
>   headers: { 'token': 'Bearer ' + token }
> })
> ```
>
> **真正的防线是后端 `@SaCheckPermission`**：
> ```java
> @SaCheckPermission("demo:remove")
> @DeleteMapping("/{ids}")
> public R<Void> remove(@PathVariable Long[] ids) { ... }
> ```
>
> **所以正确设计是**：前端做（体验）+ 后端做（安全），**两层都要**。

### Q13：`*:*:*` 是什么？从哪来？

**答**：

> **`*:*:*` 是「超级管理员权限通配符」**，表示"拥有所有权限"。
>
> **来源是后端硬编码的**（`SysPermissionService.getMenuPermission`）：
> ```java
> public Set<String> getMenuPermission(SysUser user) {
>     Set<String> perms = new HashSet<String>();
>     if (user.isAdmin()) {
>         perms.add("*:*:*");        // ★ 硬编码
>     } else {
>         perms.addAll(menuService.selectMenuPermsByUserId(...));
>     }
>     return perms;
> }
> ```
>
> **前端的判断**（`plugins/auth.js`）：
> ```javascript
> return permissions.some(v => {
>   return all_permission === v || v === permission    // 有通配符 or 精确匹配
> })
> ```
>
> **⭐ 注意区分**：
> - `*:*:*` 是**权限码**通配符（按钮级）
> - `admin` 是**角色**通配符（路由级）
>
> 两者都由后端硬编码，但机制独立。

### Q14：`request.js` 的请求拦截器做了什么？

**答**：

> **三件事**：
>
> 1. **加 token**
>    ```javascript
>    if (getToken() && !isToken) {
>      config.headers['token'] = 'Bearer ' + getToken()
>    }
>    ```
>
> 2. **把 GET 参数拼到 URL**
>    ```javascript
>    if (config.method === 'get' && config.params) {
>      let url = config.url + '?' + tansParams(config.params)
>      url = url.slice(0, -1)
>      config.params = {}          // 必须清空
>      config.url = url
>    }
>    ```
>    **为什么要手动拼？** 为了支持嵌套对象（如 `params[beginTime]`）。
>
> 3. **防重复提交**
>    ```javascript
>    // POST/PUT 且 1 秒内 url+data 完全相同 → 拦截
>    return Promise.reject(new Error('数据正在处理，请勿重复提交'))
>    ```
>
> **⭐ 三个坑**：
> - 头名是 `token` 不是 `Authorization`
> - `isToken === false` 不能写成 `!isToken`（否则全站 401）
> - `config.params = {}` 必须清空（否则 `?a=1&a=1`）

### Q15：响应拦截器为什么 `return res.data`？

**答**：

> **为了剥掉 axios 的包裹层，让页面少写一层 `.data`。**
>
> **axios 的 `res` 结构**：
> ```javascript
> {
>   data: { ... },        // ← 后端的整个响应体
>   status: 200,
>   headers: {...}
> }
> ```
>
> **后端的响应体结构**（`R<T>`）：
> ```json
> { "code": 200, "msg": "...", "data": { ... } }
> ```
>
> **如果拦截器 `return res`**，页面要写 `response.data.data.xxx`（两层）。
> **`return res.data`**，页面写 `response.data.xxx`（一层）。
>
> **⭐ 分页接口例外**：`TableDataInfo` 返回 `{ code, msg, rows, total }`，
> 所以页面要写 `response.rows`（不是 `response.data.rows`）。

### Q16：前端的 token 存在哪？为什么？

**答**：

> **存在 Cookie，key 是 `Admin-Token`**（`src/utils/auth.js`）：
> ```javascript
> export function getToken() {
>   return Cookies.get('Admin-Token')
> }
> ```
>
> **同时也存一份在 Vuex 的 `state.token`**。
>
> **为什么存两份？**
>
> | 位置 | 用途 | 刷新后 |
> |---|---|---|
> | **Cookie** | `request.js` 的 `getToken()` 读它加请求头 | ✅ 还在 |
> | **state** | 组件里 `this.$store.getters.token` 响应式使用 | ❌ 没了 |
>
> **⭐ 这就是"刷新页面不会掉登录"的原因**：
> state 清空了，但 Cookie 还在 → 路由守卫能读到 token → 重新拉用户信息。

### Q17：前端防重复提交和后端 `@RepeatSubmit` 有什么区别？

**答**：

> **两套机制，用途不同**：
>
> | | 前端（`request.js`） | 后端 `@RepeatSubmit` |
> |---|---|---|
> | 存哪 | `sessionStorage` | **Redis** |
> | 阈值 | 1 秒 | **默认 5 秒** |
> | 防什么 | 用户手抖连点 | **真实重复请求**（含脚本/curl） |
> | 能绕过吗 | ✅ 能（F12 直接发） | ❌ 不能 |
>
> **前端实现**：记录"上一条请求"的 `url + JSON(data) + time`，
> 1 秒内完全相同就拦截。
>
> **⚠️ 前端的局限**：只记"上一条"，1 秒后失效 → 实际防的是"手抖连点"，
> **不是"请求还在处理中"**。
>
> **后端才是安全防线**（Redis 分布式锁）。

### Q18：这个项目有什么代码质量问题？

**答**：（面试时可以主动说，显得有代码审查能力）

> **我注意到几个点**：
>
> 1. **`filterAsyncRouter` 用 `filter` 却永远返回 `true`**
>    → 其实没过滤，只是借用遍历能力。应该用 `.map()`。
>
> 2. **`GetInfo` 里给 `ROLE_DEFAULT` 兜底**
>    → 是"防死循环的 hack"。正确做法是后端保证至少返回一个默认角色。
>
> 3. **`new Promise` 包装多余的 Promise**
>    → `user.js` 的 `Login` action 外面包了一层 `new Promise`，
>    但 `login()` 本身已返回 Promise，可以直接 `return login(...).then(...)`。
>
> 4. **`login.js` 有个无用的 import**
>    → `import de from "element-ui/src/locale/lang/de"`（德语语言包，完全没用到）。
>
> 5. **防重复提交只记"上一条"**
>    → 应该用 `Set` 记录所有"在飞"的请求，响应返回时释放。
>
> 6. **`sa-token.timeout: 186400`**
>    → ≈ 51.8 小时，不像正常的整数值（86400=24h），可能是多打了一个 1。

## 三、进阶（19-25）

### Q19：为什么数据库 `component` 不能带 `.vue`？

**答**：

> 因为 `loadView()` 会拼成 `@/views/${component}`：
> ```javascript
> export const loadView = (view) => {
>   return () => import(`@/views/${view}`)
> }
> ```
>
> 传入 `'demo/index.vue'` → 变成 `@/views/demo/index.vue`，
> 而 webpack 的 `import` 会**自动补扩展名**，所以它去找 `@/views/demo/index.vue.vue` → 找不到。
>
> **正确写法**：`'demo/index'`（不带后缀）。

### Q20：为什么 `loadView` 开发环境用 `require`、生产用 `import`？

**答**：

> **开发环境**：`(resolve) => require([`@/views/${view}`], resolve)`
> - 这是 webpack 的 **AMD 风格异步加载**
> - 配合 HMR（热更新）更稳定
>
> **生产环境**：`() => import(`@/views/${view}`)`
> - 真正**切成独立的 chunk 文件**，按需下载
> - 首屏 bundle 更小
>
> **⭐ 这是 RuoYi 的历史选择**（早期 webpack 对动态 `import()` 的 HMR 支持不好）。
> **新代码推荐统一用 `() => import(...)`。**

### Q21：`main.js` 里 `import "./permission"` 为什么没有 `from`？

**答**：

> 这是**"副作用导入"（side-effect import）**：只是为了**执行一遍**那个文件，不取任何东西。
>
> `permission.js` 里做了：
> ```javascript
> router.beforeEach((to, from, next) => { ... })
> ```
> **注册了路由守卫**。
>
> **所以这一行就是"路由守卫"被接进整条链的地方。**
>
> **类比**：像 Java 里 `@PostConstruct` 里的初始化逻辑，或者静态初始化块。

### Q22：全局注册的组件有什么代价？

**答**：

> **无法 tree-shaking。**
>
> `Vue.component("X", X)` 是一句**有副作用的运行时代码**，
> 打包工具（webpack/rollup）**无法静态判断"这个组件到底用没用"**，所以不敢删。
>
> **结果**：即使某个组件从未被使用，也会被打进首屏 bundle。
>
> **项目里的实际情况**：
> - `Pagination`、`DictTag`（几乎每页都用）→ **全局注册合理**
> - `FileUploadContract`、`ZnModal`（少数页面用）→ **其实该局部注册**
>
> **这是"管理后台"场景下的合理权衡**（用户一天开一次，多几百 KB 换开发便利）。
> 如果是 C 端首屏敏感的场景，应该全部局部注册 + 按需加载。

### Q23：为什么 `dynamicRoutes` 里不写 `permissions` 会被丢弃？

**答**：

> 看 `filterDynamicRoutes` 的逻辑：
> ```javascript
> export function filterDynamicRoutes(routes) {
>   const res = []
>   routes.forEach(route => {
>     if (route.permissions) {
>       if (auth.hasPermiOr(route.permissions)) res.push(route)
>     } else if (route.roles) {
>       if (auth.hasRoleOr(route.roles)) res.push(route)
>     }
>     // ← 都没有？什么都不做（丢弃）
>   })
>   return res
> }
> ```
>
> **因为 `dynamicRoutes` 的定义就是"需要权限的页面"。**
> 不写权限声明说明**配置有误**，宁可不注册（避免误开放）。
>
> **这是"fail-safe"（失败时保守）的设计。**

### Q24：如果让你优化这个前端，你会做什么？

**答**：（结构化回答）

> **分优先级**：
>
> **P0（正确性）**：
> 1. 修 `filterAsyncRouter` 用 `filter` 却永远返 true 的问题
> 2. `GetInfo` 的 `ROLE_DEFAULT` hack 改成后端保证默认角色
> 3. 前端防重复提交改用 `Set` 记录"在飞"请求
>
> **P1（性能）**：
> 4. 把只在少数页面用的全局组件改成局部注册（减小首屏 bundle）
> 5. 检查是否有可以拆包的路由
> 6. 加 `gzip_static`（项目已生成 `.gz` 文件，但 Nginx 没配就用不上）
>
> **P2（可维护性）**：
> 7. 删掉无用 import（如 `login.js` 的德语语言包）
> 8. 统一 `==` 改 `===`
> 9. 补 ESLint 规则（`no-console`、`eqeqeq`）
>
> **P3（安全）**：
> 10. 确认所有后端接口都有 `@SaCheckPermission`
> 11. 密码"记住密码"别存 Cookie（改用 refresh token）

### Q25：你从这个项目学到了什么？

**答**：（真诚 + 具体）

> **三个层面**：
>
> **① 技术层面**
> - **动态路由**：理解了"后端给字符串、前端翻译成组件"这个设计，以及为什么不能带 `.vue`
> - **权限的三层结构**：路由级、菜单级、按钮级，各自的数据来源和实现
> - **响应式原理**：`Object.defineProperty` 的 getter/setter，以及 Vue 2 的三个局限
>
> **② 工程层面**
> - **分层的价值**：`api`（接口声明）→ `request`（统一拦截）→ `views`（页面），每层只做一件事

> **③ 判断力层面**

> - **知道"设计的取舍"**：全局组件注册牺牲了 tree-shaking 换取开发便利，在管理后台场景是合理的；但 C 端就不能这么干
> - **能看出代码的"坏味道"**：`filter` 返 true、`ROLE_DEFAULT` hack、`new Promise` 冗余包装

# 11.5 自测

1. 坑 7 的 `=== false` 为什么不能写成 `!isToken`？后果是什么？
2. `v-for` 为什么不能用 index 当 key？
3. `v-if` 和 `v-show` 怎么选？
4. `next({ ...to, replace: true })` 里两个部分各起什么作用？
5. 前端权限和后端权限，哪个是防线？
6. `*:*:*` 是前端配的还是后端给的？
7. `R<T>` 和 `TableDataInfo` 前端分别取什么字段？
8. 全局注册组件的代价是什么？
9. `loadView` 为什么开发用 `require`、生产用 `import`？
10. 如果面试官问"这是你做的吗"，怎么答？

<details>
<summary>答案</summary>

1. `undefined` 取反是 `true`，会让**所有没写 `isToken` 的请求都不带 token** → **全站 401**
2. 删除中间元素时 index 会变，Vue 误判"内容变了"而非"元素删了"，**复用错误的 DOM**（输入框内容错乱）
3. 条件**很少变**用 `v-if`（省初始渲染）；**频繁切换**用 `v-show`（省切换成本）
4. `{ ...to }` 复制只读的 `to` 对象（不能直接改它）；`replace: true` 替换历史记录（防止后退循环）
5. **后端 `@SaCheckPermission`**（前端只是界面美化）
6. **后端硬编码**（`SysPermissionService` 里 `perms.add("*:*:*")`）
7. `R<T>` → **`data`**；`TableDataInfo` → **`rows`** + `total`
8. **无法 tree-shaking**（即使不用也进 bundle）
9. 开发用 `require` 是 AMD 风格、HMR 更稳；生产用 `import()` 才能切成独立 chunk
10. **诚实说明**是基于开源的二次开发/学习项目，然后讲"我真正理解和做了什么"
</details>
