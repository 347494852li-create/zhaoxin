# 前端全链路读法：一个接口从前到后经历了什么

> 这份文档的目的：**给你一条主线**。
> 你顺着它读一遍，就能把散落的前端文件串成"一个有逻辑的流程"，而不是一堆看不懂的代码。
>
> 所有代码文件里都加了 `★` 开头的教学注释（搜 `★` 就能看到），本文只负责告诉你**"先看哪个、为什么看它"**。

---

## 0. 一句话总览

```
【阶段 A：登录（从零开始）】
浏览器访问 /
  ↓ 没有 token
[L0] permission.js 把用户踢到 /login
[L1] views/login.vue 输入账号密码 → handleLogin()
[L2] store/modules/user.js 的 Login action
[L3] api/login.js 的 login() → utils/request.js 拦截器（isToken:false 所以不带 token）
  ↓ POST /dev-api/login
[L4] 后端返回 token → setToken() 写进 Cookie('Admin-Token')
  ↓ 跳回 redirect（默认 /index）

【阶段 B：拿权限 + 建路由】
[2] permission.js 路由守卫发现有 token
      ↓ dispatch('GetInfo')  → api/login.js getInfo() → GET /getInfo
      ↓ 拿到 roles（角色）+ permissions（权限码）存进 store
      ↓ dispatch('GenerateRoutes') → GET /getRouters
[3] store/modules/permission.js 把菜单字符串翻译成组件 → 动态加路由
[4] router 匹配到目标页面

【阶段 C：渲染页面 + 拿数据】
[5] App.vue → layout 套上侧边栏/顶栏（侧边栏读 store.getters.sidebarRouters）
[6] views/.../index.vue 被创建，created() 触发
[7] api/...js 声明接口
[8] utils/request.js 拦截器加 token、拼参数
  ↓ HTTP GET /dev-api/contract/contractDraft/list?pageNum=1&...
[9] vue.config.js 的 devServer 代理剥掉 /dev-api → 转发到 8080
  ↓
[10] 后端 Controller
```

**注意这条链上有【三次】请求，别搞混**：

| # | 请求 | 什么时候 | 目的 | 走哪个文件 |
|---|---|---|---|---|
| ① | `/login` | 用户点"登录" | 拿 token | `login.vue` → `user.js` → `api/login.js` → `request.js` |
| ② | `/getInfo` + `/getRouters` | 路由守卫里（有 token 但还没拉过用户信息） | 拿权限、拉菜单、建路由表 | `permission.js` → `store/modules/permission.js` |
| ③ | `/contract/contractDraft/list` | 页面组件 `created()` | 拿列表数据 | `index.vue` → `api/*.js` → `request.js` |

**①是"我怎么进来"，②是"页面从哪来"，③是"数据从哪来"。** 三个都懂了，前端就没黑箱了。

## 0.1 权限体系：三层，但前端都不是防线

这是必须提前建立的认知，否则读权限代码会误以为是"安全控制"。

| 层 | 控制什么 | 前端代码 | 数据来源 |
|---|---|---|---|
| **① 路由级** | 能不能**打开**某个页面 | `permission.js` + `store/modules/permission.js` 的 `filterDynamicRoutes` | `sys_menu` 表 |
| **② 菜单级** | 侧边栏**显示**哪些菜单 | `layout/components/Sidebar/*` 渲染 `sidebarRouters` | 后端 `/getRouters` **已经筛好了** |
| **③ 按钮级** | 页面上**显示**哪个按钮 | `v-hasPermi` 指令 → `plugins/auth.js` | `/getInfo` 返回的 `permissions` |

**⭐ 三个反直觉但必须知道的真相**：

1. **前端几乎不"判断"权限，它只是"接收"权限。**
   菜单是后端按角色查出来的；权限码列表也是后端给的。前端唯一的判断是拿权限码去比对按钮上写的码。

2. **`*:*:*` 是超级管理员通配符。**
   `admin` 账号在 `/getInfo` 时拿到的 `permissions` 就是 `['*:*:*']`，所以所有按钮都显示。
   同理角色层面有 `'admin'` 这个通配符（见 `plugins/auth.js:16`）。

3. **⚠️ 前端三层都只是"界面美化"，不是安全防线。**
   用户改 DOM、或直接用 curl 调接口，就能绕过所有前端判断。
   **真正的防线是后端 `@SaCheckPermission` 注解。**
   前端做这些的价值是"别让用户看到点了会报错的按钮"。

## 第 0 步：`public/index.html` —— 一切的起点

**这个文件里有什么**：只有一个 `<div id="app">`，里面放了一段"系统加载中"的转圈动画。

**你要理解的关键点**：

- 整个网站**只有这一个 HTML 文件**（这就是 SPA 单页应用）
- 它里面**没有** `<script src="main.js">`，那是打包时 webpack 自动插进去的
- `<div id="app">` 就是**挂载点**，后面 `main.js` 要接管它

**🔍 读代码时搜**：`★【全链路起点`

---

## 第 1 步：`src/main.js` —— 创建根实例

**这个文件干 3 件事**：

1. **import 一堆东西**：组件、路由、状态、样式
2. **往 Vue 上挂全局能力**：
   - `Vue.component('名字', 组件)` → 全局组件（你之前问的"为什么不 import 就能用"）
   - `Vue.prototype.xxx = xxx` → 全局方法（`this.parseTime()` 这类）
   - `Vue.use(插件)` → 安装插件（Element UI、自定义指令、`$modal` 等）
3. **`new Vue({ el:'#app' })`** → 创建根实例，接管 `index.html` 的挂载点

**⭐ 本章最该记住的一条**：

> **整个应用只 `new Vue()` 这一次。** 之后切换页面**不会**再执行 `main.js`，
> 页面切换是 router 在内部替换 `<router-view />` 的内容。

**🔍 读代码时搜**：`★【全链路关键`、`★★★【核心】全局组件注册`

---

## 第 2 步：`src/permission.js` —— 路由守卫（最关键的一环）

**什么时候执行**：`main.js` 第 24 行 `import "./permission"` 的那一刻，它往 router 上挂了钩子。

**每次跳转都会走 `router.beforeEach`**，逻辑是：

```
有 token 吗？
├─ 没有 → 在白名单里？ → 是：放行；否：踢到 /login
└─ 有   → 用户信息拉过吗？
          ├─ 没拉过 → dispatch('GetInfo')  ──→ 请求① /getInfo
          │            ↓ 成功后
          │          dispatch('GenerateRoutes') ──→ 请求① /getRouters
          │            ↓ 成功后
          │          router.addRoutes(路由)  ← 动态注册
          │            ↓
          │          next({...to, replace:true})  ← ⚠️ 重新走一遍跳转
          └─ 拉过了 → 直接 next() 放行
```

**⭐ 三个必须看懂的点**：

| 点 | 为什么重要 |
|---|---|
| **`next()` / `next('/login')` / `next({...to})`** | 决定了"放行 / 改道 / 重走"。少写一个分支，页面就会**卡住白屏** |
| **为什么要 `next({...to, replace:true})`** | 因为 `addRoutes` 是刚执行的，当前这次跳转是在路由还不存在时匹配的，不重走会落 404 |
| **为什么要判断 `roles.length === 0`** | 保证刷新页面（内存清了）时会重新拉一次用户信息和菜单 |

**🔍 读代码时搜**：`★★★【核心】router.beforeEach`、`★【经典 hack】`

## 第 3 步：`src/store/modules/permission.js` —— 字符串变组件（最烧脑的一步）

**这是整条链里最容易懵的地方**，因为：

```javascript
// 后端返回的（字符串）
component: "contract/contractDraft/index"

// Vue Router 要的（组件对象）
component: () => import('@/views/contract/contractDraft/index')
```

**两者不是一个东西！** 所以必须有 `loadView()` 来翻译。

**转换分三种情况**（`filterAsyncRouter` 里）：

| 后端返回的 component | 换成什么 | 用在哪 |
|---|---|---|
| `"Layout"` | 后台外壳组件 | 一级目录 |
| `"ParentView"` | 空壳（只有 `<router-view/>`） | 纯目录（三级以上菜单的中间层） |
| `"InnerLink"` | iframe 组件 | 外部网页 |
| **其他字符串** | **`loadView(字符串)`** | **业务页面** |

**⭐ 这解释了你的一个疑问**：

> 为什么**数据库 `sys_menu.component` 里不能写 `.vue` 后缀**？
> 因为 `loadView` 会拼成 `@/views/xxx`，webpack 自动补 `.vue`。写了反而找不到。

**🔍 读代码时搜**：`★【全链路关键】这行是【深拷贝】`、`★★★【全链路 · 谜底揭晓】loadView`

## 第 4 步：`src/router/index.js` —— 路由表

**这个文件有两部分，别混**：

| 名字 | 内容 | 什么时候注册 |
|---|---|---|
| `constantRoutes` | 登录页、404、首页、WPS 编辑页 | **启动就注册** |
| `dynamicRoutes` | 需要权限的页面（分配用户、字典数据等） | **登录后**按权限过滤再加 |

**你之前问过的这段**就在这里（第 99-111 行）：

```javascript
{
  path: '',                    // 空路径容器，靠 redirect 跳到 /index
  component: Layout,           // 套后台框架（侧边栏+顶栏）
  redirect: "/index",
  children: [
    { path: 'index',           // 相对路径 → 拼成 /index
      component: () => import('@/views/index'),   // 懒加载
      name: 'Index',           // keep-alive 缓存要用
      meta: { title:'首页', icon:'dashboard', affix:true } }  // affix=标签页固定不可关
  ]
}
```

## 第 5 步：`src/App.vue` → `src/layout/` —— 套上外壳

**两层结构**：

```
App.vue                     ← 最外层，只含 <router-view />
  └─ layout/index.vue       ← 后台外壳：左侧菜单 + 顶栏 + 标签页
       └─ <app-main>        ← 内容区
            └─ <router-view />   ← ★ 真正的业务页面在这里
```

**⭐ 这就是"嵌套路由"**：`Layout` 是共用的装修，业务页面是桌面上的具体内容。

> 如果不用嵌套路由，就得在**每一个页面**里都写一遍侧边栏和顶栏 —— 20 个页面重复 20 遍。

## 第 6 步：`views/contract/contractDraft/index.vue` —— 页面组件

**`.vue` 文件固定三段**：`<template>` 结构、`<script>` 逻辑、`<style scoped> 样式`。

**你要先认识 5 个语法**：

| 语法 | 含义 | 类比 |
|---|---|---|
| `{{ 变量 }}` | 显示变量的值 | JSP 的 `${}` |
| `:属性="变量"` | 把变量绑到 HTML 属性（`v-bind` 简写） | — |
| `@事件="方法"` | 监听事件（`v-on` 简写） | `onclick=""` |
| `v-if` / `v-show` | 条件显示 | `if` |
| `v-for` | 循环渲染 | `c:forEach` |
| `this.xxx` | 访问组件自己的 data / methods | `this.` |

**⭐ 最核心的心智模型**：

> **Vue 是"数据驱动"——你不操作界面，只改数据，界面自动变。**
> 类比 Excel：你改单元格的值，图表自动重画；而不是手动去画图。

**这个页面的生命周期关键点**：

```javascript
created() {
  this.getList()          // ← 页面一创建就请求数据
}
```

**生命周期顺序**（记这 3 个就够）：

| 钩子 | 时机 | 类比 |
|---|---|---|
| `created()` | 数据好了，还没渲染到浏览器 | `@PostConstruct` |
| `mounted()` | 已渲染到浏览器（能操作 DOM） | 页面渲染完成事件 |
| `destroyed()` | 组件销毁 | `@PreDestroy` |

**🔍 读代码时搜**：`★★★【全链路 · 触发点】created()`、`★★★【全链路 · 核心方法】getList`

## 第 7 步：`api/contract/contractDraft.js` —— 接口清单

**这个文件只做一件事**：把后端每个接口包装成一个函数。

**为什么单独放一个文件**：

1. 页面代码更干净（页面只管"拿到数据怎么显示"）
2. 接口地址只写一次
3. **能和后端 Controller 一一对应**（对着看特别顺）

**⭐ 必须分清 `params` 和 `data`**：

| 写法 | 参数去哪 | 用在哪 |
|---|---|---|
| `params: query` | **拼在 URL 上**：`/list?pageNum=1` | **GET** |
| `data: data` | **放请求体**（JSON） | **POST / PUT** |

**⭐ RESTful 约定**（看这个文件能学到）：

```
GET    /contract/contractDraft/list   → 查列表
GET    /contract/contractDraft/123    → 查详情
POST   /contract/contractDraft        → 新增    ← 注意没有 /add
PUT    /contract/contractDraft        → 修改    ← 靠 method 区分
DELETE /contract/contractDraft/123    → 删除
```

**🔍 读代码时搜**：`★★★【全链路 · 主角接口】`

## 第 8 步：`utils/request.js` —— 请求总闸门

**所有请求都路过这里。** 两个拦截器：

### 请求拦截器（发出去之前）

| 做什么 | 关键细节 |
|---|---|
| **带 token** | `config.headers['token'] = 'Bearer ' + getToken()` |
| **拼 GET 参数** | 用 `tansParams` 支持嵌套对象 → `params[beginTime]=xxx` |
| **防重复提交** | POST/PUT 且 1 秒内 url+data 完全相同 → 拦掉 |

**⭐ 三个坑**：

| 坑 | 说明 |
|---|---|
| 头名是 `token` **不是** `Authorization` | 由后端 `sa-token.token-name` 决定 |
| `isToken === false` **不能**写成 `!isToken` | 否则所有请求都不带 token → 全站 401 |
| `config.params = {}` **必须清空** | 否则 axios 会再拼一次 → `?a=1&a=1` |

### 响应拦截器（拿回来之后）

| code | 处理 |
|---|---|
| 401 | 弹"登录过期"确认框（有锁防重复弹） → 登出 → 跳首页 |
| 500 | 弹红色 Message |
| 其他非 200 | 右上角 Notification |
| **200** | **`return res.data`** ← 剥掉包裹层 |

**⭐ 记住最后这条**：它解释了为什么页面里写 `response.rows` 而不是 `response.data.rows`。

**🔍 读代码时搜**：`★★★【axios】请求拦截器`、`★★★【全链路 · 关键】成功时只返回 res.data`

## 第 9 步：`vue.config.js` —— 代理转发

**开发环境的最后一步**：`/dev-api` 是假的，靠 devServer 代理转走。

```javascript
devServer: {
  proxy: {
    [process.env.VUE_APP_BASE_API]: {     // '/dev-api'
      target: 'http://localhost:8080',    // 转发到后端
      pathRewrite: { '^/dev-api': '' }    // ★ 剥掉前缀
    }
  }
}
```

**完整路径变化**：

```
浏览器看到： GET http://localhost/dev-api/contract/contractDraft/list
                                     ↓ 代理剥掉 /dev-api
后端收到：   GET http://localhost:8080/contract/contractDraft/list
```

> **⚠️ 生产环境换成 Nginx**：`location /prod-api/ { proxy_pass http://后端:8080/; }`
> `proxy_pass` 末尾那个 `/` 就是"剥前缀"，**不能省**。

## 第 10 步：到后端了

用你熟悉的方式对照：

| 前端 | 后端 |
|---|---|
| `url: '/contract/contractDraft/list'` | `@RequestMapping("/contract/contractDraft")` + `@GetMapping("/list")` |
| `method: 'get'` | `@GetMapping` |
| `params: {...}` | 方法参数（`ContractDraftBo bo`, `PageQuery pageQuery`） |
| 返回值 `response.rows` | `TableDataInfo.build(page)` → `{ rows, total }` |
| 返回值 `response.data` | `R.ok(data)` → `{ code, msg, data }` |

## 附：怎么删掉这些教学注释

所有教学注释都以 `★` 开头。三种方式：

**方式 1：git 还原（最干净）**
```powershell
cd E:\Develop\project\zxcm-learn
git checkout -- zxcm-ui/
```

**方式 2：用备份还原**
```powershell
# 每个改过的文件都有 .orig-backup 备份
Copy-Item "zxcm-ui\src\main.js.orig-backup" "zxcm-ui\src\main.js" -Force
```

**方式 3：只删注释行**
```powershell
# 删掉所有以 ★ 开头（可带缩进和 //）的行
```
