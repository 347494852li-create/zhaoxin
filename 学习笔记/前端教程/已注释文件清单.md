## 四、权限的「三个真相」（读代码前必须先知道）

### 真相 1：前端几乎不"判断"权限，它只是"接收"权限

菜单是**后端**按角色查出来的（`/getRouters` 只返回你有权看的）；
权限码列表也是**后端**给的（`/getInfo` 返回 `permissions: [...]`）。

前端唯一的"判断"是：拿到权限码后，**比对按钮上写的码**，决定要不要把那个 `<button>` 删掉。

### 真相 2：`*:*:*` 是超级管理员通配符

`admin` 账号在 `/getInfo` 时拿到的 `permissions` 就是 `['*:*:*']`，
所以所有按钮都显示。角色层面同理，有 `'admin'` 这个通配符（见 `plugins/auth.js:16`）。

### 真相 3：⚠️ 前端三层权限都只是"界面美化"，**不是安全防线**

用户改 DOM、或直接用 `curl` 调接口，就能绕过所有前端判断。

**真正的防线是后端 `@SaCheckPermission` 注解。**

前端做这些的价值是：**别让用户看到"点了会报错"的按钮**。

# ③ 去后端搜这个 URL
#    搜 "/contract/contractDraft" → 找到 ContractDraftController

## 七、怎么还原成没注释的版本

### 方式 1：git 还原（最干净）

```powershell
cd E:\Develop\project\zxcm-learn
git checkout -- zxcm-ui/
```

### 方式 2：用备份还原

所有原始文件都备份在项目外：

```
E:\DeepSeek\project\zhaoxin\_annotation_backups\
```

文件名规则：把路径里的 `\` 换成 `__`，再加 `.orig`

例如：
```
zxcm-ui__src__api__login.js.orig
zxcm-ui__src__store__modules__user.js.orig
zxcm-ui__public__index.html.orig
```

### 方式 3：只删注释行（保留你自己的改动）

```powershell
$f = "zxcm-ui\src\main.js"
(Get-Content $f -Encoding utf8) |
  Where-Object { $_ -notmatch '^\s*(//|<!--)?\s*★' } |
  Set-Content $f -Encoding utf8
```

> ⚠️ 方式 3 只适合删"整行 ★ 注释"。如果是多行 `//` 注释（只有第一行带 ★），
> 删完会留下续行。**建议用方式 1 或 2。**
